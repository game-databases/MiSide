### Row placement ruling

The spec's illustrative `conditions-met` row showed `windows[]` inline. This
emit places the safe-access windows on **`safe-of-life`** instead: the windows
are Basement_Safe gates and the spec itself states ACHI_safelife's award lives
in the safe-chain native bodies. No AC pins window placement to a row
(AC-B6 constrains only marking/status). Logged as a deliberate placement
correction.

## Grounding rules enforced

1. Loc rows cited only as `<file>.jsonl#line_index=<n>` — never bare-colon
   (B.3 trap: `Menu.jsonl:130` binds record 129). Lint asserts.
2. Numeric constants (17%/98%, password compare, condition ordering) remain
   `unverified-behavior` unless a native pass proves them.
3. Chapter numbers never enter data fields — `[community]` labels only.
4. Free text confined to `attribution`/`*_community` fields; lore prose is
   structurally impossible inside `evidence[]` (cite grammar).

## Deviations from the illustrative spec shapes (deliberate)

1. Output family `extracted/data/endings/` (orchestrator brief; arbiter
   residue (a)).
2. Choice-node emit follows AC-B2's pinned sweep (all 371 nodes), not B.7's
   smaller stub sketch; award-chain hosts stay out of the node set (they are
   not DC/OI/IM kinds) and live on `endings.award_chain`.
3. `windows[]` moved to `safe-of-life` (placement ruling above).
4. Edge-id grammar adds a branch ordinal (`b{n}`) because real data contains
   duplicate `if_int` keys within one instance.
5. `effect_class` enum gains `dead-reference` for serialized-null targets;
   everything else maps into the spec's six labels via the documented
   deterministic table.
6. `is-this-the-end.award_chain` pins the award mid-chain (call index 4 of
   13), not last — the ordered list is stored verbatim either way.
