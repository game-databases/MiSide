## 1. Scope

This dataset owns the **rows** for exactly two SPEC entity kinds:

- `mita_variant` — the soul surfaces (SPEC §Page inventory: flagship page
  type, palette-keyed);
- `player_character` — protagonist + Players 1–10 (D1 §2).

Everything else the Mita pages *display* — outfits, cartridges, profiles,
achievements, dialogue — is **joined, not owned**: those kinds get their own
datasets; this spec fixes only the join keys (§5). Scales in SPEC were
estimates ("~20–30", "~20"); this spec replaces them with measured registry
sizes (§3): **14 Mita gallery entries + 10 player entries = 24 owned rows**,
plus an evidence-less candidates ledger (§7).

Findings this table pins, each load-bearing for the schema:

1. **Internal names ≠ display names** — Sleepy is `MitaDreamer`, Tiny is
   `MitaLittle`, Ghostly is `MitaBlack`. Doctrine Principle one (never strip
   identifiers) makes `resource_path` mandatory and untouchable.
2. **Display names live in `Menu`, not `Names`** — `indexNameStringFile`
   resolves into `Menu.jsonl` lines 83–95/119–128; `Names.jsonl` carries
   dialogue speaker words + an NPC name pool instead (S7).
3. **Both section-comment lines are skipped by design** — desc indices start
   at 1 (past `// Mitas`) and jump 14→16 (past `// Players`); the indices are
   deliberate 0-based line picks, corroborating the split-based line model
   (E1 step 5 deviation #3).
4. **One display name serves two identities** — `MitaTrue` reuses Menu line
   83; the schema needs `name_is_shared` so pages don't merge the Crazy-form
   alias into base Mita.
5. **Palettes are first-class game data** — per-character `color1`/`color2`
   (S2) feed SPEC's colour-is-identity mandate (design direction summary)
   directly from the client, not hand-picked hexes.
6. **Gallery icons are mostly unset** — `icon` PPtr is pathID 0 for all 14
   Mita entries and 0/shared-276 for players: portraits must come from the ART
   layer, not this field ([unverified] until mapped, §8-R5).

## 4. Schema — `personages.jsonl`

### 4.1 Locale ruling: pointer columns, not locale columns

Three options existed: wide per-locale columns, per-locale record copies, or
**loc pointers resolved at build/render time**. Ruling: **pointers**
(`{category, line_index}` objects), plus one derived pivot convenience field.
Rationale, each tied to measured corpus facts:

- **Parity is total here.** All four registry categories have identical
  record counts in all 34 locales (26/165/47/13 — verified this pass across
  every dir under `extracted/localization/`), so per-row locale availability
  would be a constant column: pure duplication. Skew exists elsewhere
  (categories 64–76/dir, R-E1-3) and stays the job of
  `localization/_ledger/locale-delta.jsonl`, not of this dataset.
- **The game's own join is index-shaped.** `GetString(category, index)`
  (S4) is the proven authority (E1 step 7); storing anything but the pointer
  would replace the game's identifier with our transcription — exactly what
  doctrine Principle one forbids.
- **Patch diffs stay cheap.** A patch that edits RU bio text then changes one
  loc JSONL row; with copied text it would also dirty every character record
  and its buildId stamp, defeating SPEC's per-record staleness model.
- **Filler policy composes cleanly.** SPEC declares explicit-filler; a
  missing/mismatched locale cell renders filler driven by
  `relinks/locale_availability.jsonl` — a planned PIPE P1 sibling output
  ([pipeline-run_all.mdx](pipeline-run_all.mdx), outputs list), not yet on
  disk at spec time; this dataset consumes it once that stage lands. With
  pointers there is nothing to go stale; with copies there always is.

### 4.2 Record schema (one JSON object per line; 24 rows)

| Field | Type | Source | Notes |
|---|---|---|---|
| `character_id` | slug | derived from `resource_path` | stable kebab-case (`mita-kind`, `player-3`); never replaces originals, adds friendliness only |
| `kind` | enum | S1 array membership | `mita` \| `player` |
| `registry_ref` | string | S1 | `<container>#<array>[<index>]`, e.g. `level2#resourceMita[3]` — exact provenance of the row |
| `resource_path` | string | S1 | verbatim; `""` preserved as `""` |
| `save_key` | string | S1 `nameSave` | verbatim incl. empty; the cartridge/profile save identity (§5-J5) |
| `name_loc` | object | S1→S5 | `{"category": "Menu", "line_index": 86}` |
| `description_loc` | object | S1→S6 | `{"category": "Personages", "line_index": 4}` |
| `palette_color1` | number[4] | S1 | RGBA floats 0–1, serialized order |
| `palette_color2` | number[4] | S1 | present on all 24 entries (verified: 24 `color2` blocks in the dump) |
| `gallery_icon` | object\|null | S1 | `{container, path_id}` or `null` when pathID 0 — null is honest-missing, never backfilled |
| `preview_prefab_key` | string | S12 `'Personages/'` + S1 | `[unverified]` Resources.Load key, e.g. `Personages/MitaKind` — only the `'Personages/'` literal is proven; IL-stub bodies expose no load call site, so the mechanism is inferred |
| `name_is_shared` | bool | derived within S1 | true iff another row shares `name_loc` (row 13 `MitaTrue`) |
| `gallery_order` | int | S1 array index | canonical ordering inside the game UI |
| `name_en` | string | derived via S4/S5 | pivot convenience copy for search/API consumers; marked `"derived"` in the file header meta — the pointer remains the truth |
| `build_id` / `version_label` | string | EXTRACTION-LOG pins | `19029065` / `0.93L` on every record (provenance rule 3 user-facing class) |

source table §3, schema version, derived-field list.

## 5. Join plan

| # | Pair | Key | Mechanism | Status |
|---|---|---|---|---|
| J1 | character ↔ all localized text | `(category, line_index)` via `GlobalLanguage.GetString` (S4) | **hard** | proven end-to-end (E1 steps 3/7); AC-2 re-proves per emit |
| J2 | character ↔ scene/location | `resource_path` matched against S13 asset names + S14 instance containers; PPtr graphs give (container, pathID). Scene GameObjects mostly do NOT reuse `resource_path`: `level13.xml` carries `Location11_BlackMita` + `Location11_EyesMitaBlack`, never bare `MitaBlack`. Join = transform **T**: `Mita<X>` → `Location<n>_<X>Mita` (container-scoped `Location<n>_` prefix + modifier moved before the head noun `Mita`), whole-word decorations prepended as extra tokens (`Eyes…` → `Location11_EyesMitaBlack`) — registry row 11 joins `level13` through BOTH names; verbatim equality survives only for `MitaCore` (2 containers) | **hard** where an S13 `<Name>` equals `resource_path` verbatim (only `MitaCore` today); **inferred** where only T links them — T itself is the edge's recorded `method`, never silent (AC-7 asserts it) | modeled at census level; per-instance identity needs the emit pass |
| J3 | character ↔ outfit | `DataClothMita` (S8) binds meshes/materials; which Mitas *reflect* the equipped outfit is code behaviour (COMP J7) | **hard** for the outfit table itself; **logic/inferred** for reflection targets | reflection list `[unverified]` until decompiled-body analysis lands |
| J4 | character ↔ achievement | set-membership achievements reference collectible families (`ACHI_cartridgeplayers` literal, S12); per-achievement text via `DataAchievements.lineTranslate` → `Achievements.txt` (S10, E1 step 3) | **hard** for row joins; **logic** for family membership | modeled; family mapping emitted with the achievements dataset |
| J5 | character ↔ cartridge/profile | `save_key` ↔ `FlashTaker.SaveFlash(_save)` strings + `/Save/Flashes` collection literal (S11/S12) | **logic** (string-keyed save identity; no direct PPtr) | modeled; per-cartridge placement waits on the scenes dataset |
| J6 | character ↔ dialogue speaker | speaker words `Names.jsonl` 0–2 (`Mita`/`You`/`Thoughts`); dialogue lines keyed by `DialogueChanger.fileQuest` + `buttons[].stringFile`, `Dialogue_3DText.indexString` (decompiled fields) | **hard** for line refs; speaker-per-line attribution **open** (see §8-R1) | partial — pinned as the dialogue dataset's problem, keys fixed here |

Cross-references stay bidirectional: every edge file also emits the inverted
index (doctrine Principle one).

## 6. Stub-first plan (promptForDB hooks)

Data honesty rules the stub ladder — a row ships only at the evidence tier it
actually reached:

1. `registered` — in the S1 registry (all 24 rows): full record, no stubbing.
2. `loc_only` — has client text but no registry row (e.g. Personages line 12's
   "misty variation" paragraph if it fails to map to `MitaBlack` at emit):
   row with `status: "loc_only"`, empty identity fields, no invented values.
3. `unregistered candidate` — appears in scenes/literals but maps to no
   registry/text row (Giant/Lower-Half/Prankster-class variants if their
   GameObjects surface): **candidates ledger only**
   (`characters.candidates.jsonl`: `evidence: [{path, locator}]`, `status:
   "unregistered"`), never a page-grade row.
4. Wiki-only names (D1 §2 mention-only list) — **no row, no candidate** until
   client evidence exists; SPEC non-goals forbid fan-lore in data rows. If
   the site wants visible-locked stub pages for these, that is a frontend
   question routed through promptForDB — answered from the candidates
   ledger, never by inventing data.

Every stub/candidate row carries `missing_fields: [...]` so missingdata.md
can be generated mechanically.

## 8. Acceptance criteria (verifier-checkable)

Each criterion states the check a verifier can run against the emitted files
without re-running extraction, using only repo artifacts.

1. **Row census reconciles.** `personages.jsonl` has exactly 24 data rows =
   `int size` lines 48/301 of `extracted/harvest/mb-dump/level2/MenuPersonage.txt`;
   every row's `registry_ref` names its array + index, and the multiset of
   `(resource_path, save_key, desc_line, name_line)` tuples equals the one
   extracted from that dump byte-for-byte.
2. **Loc joins resolve ×34.** For every row, `name_loc` and
   `description_loc` resolve to non-empty text in all 34 locale dirs under
   `extracted/localization/`; zero U+FFFD in any resolved value unless the
   row cites `localization/_ledger/encoding-residue.jsonl` (which today
   contains no character-category rows).
3. **Identifiers preserved.** Every S2 field name survives as a schema column
   or an explicitly-dropped-with-reason entry in the README; `resource_path`
   and `save_key` are byte-identical to the dump (including the two empty
   save keys); `character_id` never replaces them.
4. **Palette round-trips.** All `palette_*` arrays parse as RGBA floats in
   [0,1]; spot-check row 0 ≈ (0.80, 0.45, 0.64) and row 13 ≈ (0.85, 0.17,
   0.27) against §3; hex conversion used by the site token layer reproduces
   from the stored floats.
5. **Save-key shape holds.** Non-empty `save_key` values match the observed
   families (`mta*`, `mla`, `plr*`), the ten `plr*` keys are exactly
   `plr1a…plr1099`, and each appears in `character--cartridge.jsonl` with
   `mechanism` recorded.
6. **Outfit join pin recorded.** The `character--outfit` side (or README)
   states the chosen Clothes-line hypothesis; a verifier recomputing both
   offsets from S8+S9 gets Default/School/Vampire/Christmas only under the
   documented one, and the rejected hypothesis is named with its failure.
7. **Scene membership greps clean under the recorded method.** Sampling
   any 10 rows of `character--scene-membership.jsonl`, each claimed
   `(container, Name)` pair greps clean in
   `extracted/harvest/asset-list/<container>.xml`: exact-match rows claim
   the GameObject name verbatim; `name-transform` rows claim the
   T-product (§5-J2) and never the raw `resource_path` — e.g. the
   `level13` edge for registry `MitaBlack` claims `Location11_BlackMita`
   / `Location11_EyesMitaBlack` (both grep clean there), while
   `MitaBlack` greps clean in no asset-list and must appear in zero
   claimed Names. Applying the row's recorded transform T to its
   `resource_path` reproduces the claimed Name byte-for-byte;
   unnamed-instance counts sum to the S14 filename census.
8. **Honesty ledgers wired.** R3's Version-category gap, both empty-icon
   facts, and every `status != "registered"` row appear in the dataset
   README/ledger files; `grep -ri "version" extracted/data/characters/README.md`
   finds the gap entry; no row invents a value for a field its sources don't
   prove.
9. **Locale availability derives, never asserts.** Page-facing availability
   for these entities computes from the four categories' presence per locale
   and matches `localization/_ledger/locale-delta.jsonl` — all 34 today; a
   verifier deleting a locale's `Personages.jsonl` in a scratch copy flips
   the computed availability for affected cells (filler policy demonstrably
   data-driven).
10. **Stub policy enforced negatively.** No D1 §2 wiki-only variant name
    (e.g. `Prankster`, `Long-legged`, `Mitaphone`) appears as a row in
    `personages.jsonl`; such names occur only in `characters.candidates.jsonl`
    and only with client-evidence locators or `evidence: []`.

## 9. Implementation notes

- Emission lands as a `run_all` stage (registry order after `decompile`),
  idempotent, reading only repo artifacts listed in §2 — keeping
  [DR-2026-08-18-pipeline] intact (PIPE §4 manifest gains the stage module +
  test file in the same commit).
- The stage refuses to emit when EXTRACTION-LOG `pipeline-defaults` disagree
  with the corpus buildId it reads from `census/detect.json` (stale-log
  defense, PIPE §3).
- Schema changes after datasets ship = new schema version in `_meta` + a
  regenerating rerun, never an in-place mutation.
