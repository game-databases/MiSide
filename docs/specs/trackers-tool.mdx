## 1. Purpose + player-experience framing

MiSide scatters its completion across twenty-six achievements, four endings,
twenty-three flash cartridges, seventeen minigames, fourteen Mita profiles,
eight books, six paper surfaces, and twenty-four personages — and gives the
player no single place that says *how far along am I, what's missable, and
what have I already walked past*. Competitors answer with JS-walled progress
tables that crawllers cannot read (COMP S1 `table-progress-tracking`, the
anti-precedent). This tool answers with **private-first checklists over the
accepted corpus**: every row exists in served HTML before any script runs,
progress persists synchronously in the browser, and sharing is an explicit
opt-in export — never ambient leakage.

The experience laws:

- **One toggle, zero ceremony.** Clicking a row checks it, saves it, and moves
  every gauge on the page — no submit control, no account wall, no debounce
  loss window (the reactive-input law applied to persistence).
- **Confidence is visible state.** A proven-hard award site, an
  unverified-behavior native grant, and a community-attributed window look
  different at a glance; unverified rows guide ("the interaction exists, here
  is the container") without ever rendering as advice.
- **Locked content stays visible.** Peaceful Mode, four unreachable tamagotchi
  activities, and two unresolved pickups render as locked rows with their
  reasons — checkerboard wells and lock chips, never omission-with-apology.
- **Progress is private until exported.** Item-checked state never enters an
  ambient URL, a sitemap, or any beacon. The share-code is an explicit
  generate/import action with a diff preview.

## 5. T0 — tracker-manifest emitter (data-side gating module)

### 5.1 Emission law

1. **Consumes-never-derives.** The emitter reads the §3 artifacts and performs
   ONLY projection: id extraction, group-key copying (`type_tag`, `family`,
   `access_medium`, `placement_mechanism`), status enum copying, link/marker
   ref assembly, label-free composition hints. It resolves NO new join and
   invents NO display name; where the client ships none, the row carries
   `label_mode:"id-form"` (O5) instead of a guess.
2. **Byte-freeze**: sha256 of every consumed file recorded before and after
   emission; mismatch aborts non-zero naming the file (AC-L1a/L5 tripwire
   pattern). Frozen set: the eight dataset JSONLs of §3 + `markers.jsonl` +
   `minigame--achievement.jsonl` + `tracker-exclusions.seed.json` (curated
   input at `extracted/data/build/`, joined to the byte-freeze set per A-TR4).
3. **Counts fail-fast**: emitted per-set item counts reconcile against JSONL
   censuses inside the run (26/4/23/17/14/8/6/24); any drift aborts before
   writing the public artifact (TR-A1). This is the gate that makes T0 the
   M0′-class blocker: the id universe the island validates against is proven
   before any viewer can consume it.
4. **Determinism**: same inputs ⇒ byte-identical outputs; stable ordering keyed
   on contract id; rerun over unchanged inputs diffs empty (TR-A14).
5. **Exclusion ledger**: rows deliberately not tracked (notes ×160, wiki-only
   minigames, cut-content family) enter ONLY `_meta.exclusion_ledger` counts —
   they exist in the ledger so absence is measured, never silent. Emitted
   ledger values are COPIED VERBATIM from the frozen seed
   `tracker-exclusions.seed.json`; and because `notes` IS derivable, the
   emitter ADDITIONALLY re-derives it from frozen `world_documents.jsonl`
   (`document_id` prefix `note-`), aborting non-zero naming the class on any
   seed ≠ derivation mismatch — belt-and-braces that keeps the seed honest
   without coupling the gate to prose files (missingdata.md churn) or
   violating the tier-4 no-row policy.

## 6. T1 — TrackerStore state layer (sync-ready schema law)

Pure TypeScript, zero React, zero network. One module owner; conformance-suite
tested (TR-A6).

### 6.1 Stored shape (versioned envelope)

```ts
// localStorage key: `miside.tracker.v1.<set_id>`   — ONE key per set
interface StoredSet {
  v: 1;                       // envelope version; bump migrates, never resets
  setId: string;              // defensive mirror; mismatch = corrupt, typed error
  items: Record<string, ItemRecord>;   // keys are CONTRACT IDS (O2)
}
interface ItemRecord {
  done: boolean;
  ts: number;                 // epoch ms of last local transition — THE merge key
  tomb?: number;              // OPTIONAL deletion tombstone ts (reserved; see L5)
  won?: boolean;              // reserved second axis (minigames); pattern = L5 tombstones
  wonTs?: number;             // per-axis merge key for `won` (independent of ts)
}
```

### 6.2 Laws

- **L1 Sync-write.** Every toggle calls the storage write synchronously inside
  the event handler — no submit control, no debounce, no batched flush. Proof
  obligation rides TR-A4 (write-per-toggle assertion).
- **L2 Contract-id keys only.** Any future key form requires a schema-bump
  migration in this module (O2).
- **L3 Drift tolerance.** Ids absent from the current T0 manifest render
  nowhere but are PRESERVED through read/write cycles and included in exports.
  Reconciliation never rewrites history; a patch that removes and re-adds a
  row must not lose the user's check. Unknown ids never crash render
  (defensive parse: malformed envelopes quarantine to a typed error state, no
  silent wipe).
- **L4 Deterministic merge (defined now, executed later).** Server sync, when
  it arrives, merges PER-AXIS last-write-wins: `done` orders on `ts`, `won` on
  `wonTs`, axes independent — non-minigame sets never write `won`/`wonTs`;
  set-level operations do not exist. Equal-`ts` ties break executor-independently:
  `done=true` beats `done=false`; records equal on BOTH `ts` and `done` are
  semantically interchangeable and the merge is declared idempotent there — a
  tie can therefore never silently un-check a row.
  This function ships NOW as pure code with unit proofs (TR-A6) even though no
  caller invokes it remotely — the schema is sync-ready because the semantics
  are already fixed, not because a server exists.
- **L5 Tombstones reserved, never fabricated.** v1 writes no tombstones
  (deletion-by-drift keeps records intact per L3). The field exists so a future
  SyncAdapter can propagate deletions without resurrect-on-pull; codec and
  conformance suite round-trip the field today.
- **L6 Adapter seam.** `TrackerStore { read(set): SetState; write(set, patch):
  void; subscribe(set, cb): () => void }` with `LocalAdapter` (v1) and a typed
  `SyncAdapter` interface (sign-in push/pull; server authoritative, local
  demotes to cache) DECLARED but unimplemented — no auth code, no endpoints,
  no conflict UI ships (non-goal §16). A `FakeSyncAdapter` in the test suite
  implements the seam; the conformance suite SPLITS into UNIVERSAL laws
  (envelope validation, drift preservation, deterministic merge, codec
  round-trip) parameterized over BOTH adapters, and ADAPTER-SPECIFIC laws named
  per adapter — the synchronous write-per-toggle spy (L1) binds LocalAdapter
  only, while `FakeSyncAdapter` proves seam typing plus every universal law
  (TR-A6). That split is what makes "seam only" a verified claim rather than a
  promise.
- **L7 Degraded mode is honest.** When storage is unavailable (private mode,
  quota, disabled), the store reports a typed unavailable state; UI renders
  read-only checklists with `StorageUnavailableNote` — progress visibly will
  not persist, stated in chrome words. Never fake persistence, never a console
  error as UX.

  Import VALIDATES against

## 12. Design language requirements
