## 1. Purpose and the consumes-never-derives gate

The data layer is closed ([spec.md](../../spec.md) `status`: full-pull done, locales-complete true;
PROOF §5 reconciles all six dataset scoreboards). Every question answerable from the corpus has been
answered in `extracted/` (AGENTS.md rule 8; [DR-2026-08-19-data-before-frontend]). Consequence:
**the frontend consumes typed contracts and never derives data** — no pointer arithmetic beyond the
pinned resolution rules (§3), no runtime joins beyond reading pre-emitted relink edges (§4), no
fallback invention beyond the declared availability chain (§5), no silent empties (§7). Anything the
frontend needs that the data does not hold is an open question (§9) or a dataminer work item in
[missingdata.md](../../extracted/data/missingdata.md) — never a consumer-side guess.

This spec is the UMBRELLA: the seven pinned per-dataset contracts under [`contracts/`](../../contracts/)
remain the field-level authority (deep rationale, offset pins, honesty ledgers); what they do not pin
— the cross-dataset entity registry, the join-key registry, availability semantics,
fingerprint/drift gates, and the stub-marker vocabulary — is pinned HERE.

### 4.2 Anchor grammar + cardinality

Every `from`/`to` parses as `<kind>:<id>` over the measured vocabulary:
`character:<character_id>` · `cartridge:<save_key>` (C13 anchors) · `flashes:<save_key>` ·
`minigame:<minigame_id>` · `achievement:<steam_api_name>` · `profile_document:<document_id>` ·
`document:<document_id>` · `outfit:<file_save>` · `cloth-site:<key>` · `speaker-theme:<Theme>` ·
`scene:<container>` · `scene-class:<Class>` · `scene-class-family@<container>` ·
`loc:<Category>[<line>]` · `encoding-residue:<incident:locale/category>`. Cardinality law: a forward
edge's mirror inverse edge exists in the same file (direction-bearing families; measured splits
above); reverse-index families are single-direction by construction; `partial` status always carries
`missing_fields` naming the concrete unblock. Consumers link ONLY through these edges — an entity
page never computes a relation the tree does not ship.

### 4.3 Reference-by-reference rule (B-4/B-5 precedent)

Placements are stored once, at the owner: cartridge pickups on `cartridges.pickup_ref`, profiles
consume DS-4 by reference (PROOF §5.3: live consume-by-reference reconciliation held — 11-pair
multiset byte-equal). Frontend equivalent: render joined data by resolving the edge to the owning row
AT BUILD TIME; never copy joined values into another dataset's payload, never restate a placement
from a non-owner file, and treat parked `data/*/relinks/` copies as staging (read
`extracted/relinks/` only). Pointer text resolves per §5; `*_en`/embedded-display conveniences
(§3.5 `display`, §3.1 `name_en`, §3.9 `objective_hints_text_en`) are search/API glue — never rendered
as prose on a non-pivot page (localization-architecture §1).

## 5. Locale availability semantics for consumers

Authority:
[`locale_availability.jsonl`](../../extracted/relinks/locale_availability.jsonl) — **2,686 cells**
measured this pass = 680 `dialogue_bucket` (646 present / 33 filler / 1 contentless) + 1,734
`category_presence` (1,462 / 264 / 8; 50 distinct categories across
achievements/cartridges/characters/scenes) + 272 `book_page`. Totals: present 2,108 / filler 297 /
contentless 9. Regenerated every rerun (localization-architecture §5.4); reruns byte-identical.

- **Locale key domain:** the ledger keys locales by CLIENT DIR NAME (34 distinct measured: `English`,
  `Russian`, …, `Português-Brasil` WITH accent, `Arabic (Egyptian)`, `Pre-revolutionaryRussian`).
  Consumers join through the pinned code-mapping (`spec.md` `code-mapping` + 34-row table →
  `site/src/i18n/locales.ts`); a ledger locale with no mapping row fails the build (scaffold §3.1).
- **Row shapes:** bucket/presence rows carry `classification ∈ {present, filler, contentless}` +
  `line_count`/`pivot_line_count`/`tail_delta`/`record_count`/`file_bytes`; `book_page` rows carry
  boolean `present` instead (both forms handled; C6).
- **Fallback chain (explicit-filler policy, localization-architecture §5.5):** ① resolve the pointer
  0-based in locale L's category (arithmetic-free — TV −1, Clothes −1, dialogue −1 offsets were
  applied at emit); ② category absent or cell `filler` → render the localized not-yet-translated
  filler; ③ `contentless` ≠ missing — a 0-byte shell (French `LocationDialogue Location16` MA-2;
  French `LocationHint Location18` SCN-9) renders filler like any unfilled cell; ④ a page is omitted
  ONLY when the entity has ZERO strings in that locale — driven solely by this ledger, never asserted
  uniform (per-locale category skew 64–76 dirs is real, R-E1-3).
- **RTL + aliases:** `ar`, `ar-EG` render `dir="rtl"` (per-locale fonts ship). Exactly two declared
  aliases exist and both are CHROME-ONLY (scaffold §3.3): `ru-x-prerev → ru`, `ar-EG → ar`. Game text
  is NEVER aliased — `ru-x-prerev` resolves its own pre-reform orthography files, `ar-EG` its own
  category set (64-file minimum tier). Any further alias is a defect.
- **Cross-locale link row + hreflang clusters + per-locale sitemaps** derive exclusively from ledger
  membership (+ self + `x-default` → bare path) — scaffold ACs S3/S14; this spec adds nothing to that
  contract, it pins the ledger as the sole input.

## 6. Versioning: fingerprint/hash rule per artifact

Ties to the pipeline ledger policy: outputs are deterministic FULL REWRITES, never appends (S4 write
mode; PIPE AC-5), byte-stable modulo
[`census/volatile-fields.json`](../../extracted/census/volatile-fields.json) (measurement timestamps,
wall times, host names — same *data*, not same clock). Build pins come from `EXTRACTION-LOG.md`
`pipeline-defaults` (buildId 19029065, versionLabel 0.93L) — the stale-log defense already aborts
runs on pin disagreement.

1. **Per-record stamps:** every data row carries `build_id` + `version_label` (staleness model
   per-record, spec automation block). Type inconsistency is REAL and pinned: string form in
   characters/cartridges/documents/scenes/endings; numeric in achievements (`19029065`) and dialogue
   (`build`). Compare canonically as strings (C9) — never raw JSON-type diffs.
2. **Fingerprints:** `contracts/registry/fingerprints.json` records
   `{artifact_path → sha256, row_count, build_id}` for EVERY consumed artifact (all §3 files + all 25
   relation files + `speakers.json`, `poi-kinds.json`, the 19 graph files, `availability.csv`,
   `_ledger/*`). Site build and `check_contracts.py` recompute and **fail loud on any mismatch** —
   silent content drift at the same buildId is a defect, same bar as PIPE AC-5.
3. **Schema evolution:** ANY field-set change (add/remove/type/enum-value) bumps the artifact's
   schema-id version (`…/1` → `…/2`), regenerates `entities.json`, and updates `fingerprints.json` in
   ONE commit ([DR-2026-08-18-pipeline] same-commit discipline). Additive nullable fills (e.g.
   chapter after XC-2) still bump — cheap, loud, keeps generated frontend readers honest (Q3 asks the
   reviewer to confirm the cadence).
4. **Patch day:** a new buildId invalidates every fingerprint; the rerun re-pins them in the
   emit-stage commit; site rebuild fails until re-pinned (drift can never ship quietly).
5. **Baseline:** the six dataset scoreboards (PROOF §5.3: B-1 10/10 · B-2A 7 PASS + 1 PENDING · B-2B
   8/8 · B-3 8 PASS/1 PARTIAL · B-4 10/10 · B-5 10/10 · B-6 S1–S10) are the acceptance floor the
   registries must reproduce; a registry that disagrees with a scoreboard fails verification.

## 7. Stub policy: how missingdata.md surfaces in typed contracts

Every gap in [missingdata.md](../../extracted/data/missingdata.md) (83 entries) already has a typed
marker IN THE DATA. The vocabulary, measured:

| Marker (as emitted) | Where measured | Consumer obligation |
|---|---|---|
| `missing_fields: ["<field> - <reason>", …]` | cartridges, candidates, partial relink rows | render the named explicit-missing state; never backfill |
| `status:"registered-unresolved-pickup"` | cartridges ×2 (CAR-1) | tier-2 row: no pickup coordinates claimed |
| `status:"pending-export"` | achievement `icon` ×26 (ACH-1) | named explicit-missing icon slot; interim `official_url` may feed OG only |
| `unlock.status:"unverified-behavior"` | 15/26 predicates (ACH-2), safe windows (END-2) | label as community/unverified gloss; never stated as game fact |
| `flags.get_bool_trusted:false` | all 26 rows (ACH-5) | HARD quarantine — renderer reads neither the flag nor anything derived from it |
| `present_but_unreachable:true` | minigames ×4 (CAR-8, COMP J11) | visible-locked rendering, never dropped, never speculated |
| `scoring_derivable:false` | minigames ×17 (CAR-3/R1) | no thresholds rendered; `rule_evidence` strings only |
| `kind:"mode-stub"` / `state:"locked-stub"` | ending `peaceful` (END-1) | visible-locked stub with cited evidence |
| `effect_class:"dead-reference"` | branch_edges ×3 (END-4) | ledgered residue; never silently omitted, never resolved |
| `text_mechanism:"unresolved"` | world_documents ×166 (DOC-1) | interactable+wiring surfaces only; zero invented prose |
| `entity.status:"pending-curation"` / `"provisional-pending-ds1"` | speakers.json 5 + 9 themes (DLG-1/DLG-2) | entity links withheld until slugs are ruled |
| `[inferred]` / `[community]` / `[unverified]` bracket labels | `container_location_binding`, `windows.chapter_attribution`, `preview_prefab_key`, … | the label renders with the value or the value does not render |
| `_meta.unverified_columns` / header notes | class-A/B headers | consumers inherit the caveat; checkers enforce |

Rules: (1) a stub marker MUST cite its missingdata.md ID where one exists — `check_contracts.py`
greps both directions (marker↔ledger) and fails on an uncited marker or an uncovered ledger row;
(2) silent empties are banned — absence is a typed value, never a blank cell (empty UI sections are
OMITTED per [DR-2026-08-22-copy-earns-its-place], which governs rendering, not data); (3)
`measured-absence` rows (MA-1…MA-8) mean nobody re-chases — the typed markers above ARE the data.

## 8. Non-goals

- **No new fields, joins, or derivations invented here.** This spec pins what the emitters emit;
  where a consumer needs something absent it becomes an open question (§9) or a ledgered dataminer
  item — never a schema fiction.
- **No page, route, tool, or rendering decisions** — owned by [site-scaffold.mdx](site-scaffold.mdx),
  [`tools-plan.md`](../../tools-plan.md), and later page pieces; §5/§7 give those pieces their
  inputs, nothing more.
- **No per-field rationale duplicated** — the seven pinned dataset contracts keep deep authority
  (offset pins, transform grammar T, dedupe rules); this file pins the cross-dataset surface and
  would rot if it restated them.
- **No pipeline stage implementation** — the XC-6 registration commit owns emitter/checker
  registration in `run_all`; `check_contracts.py` rides that registration, it does not preempt it.
- **No RELATIONS.md roll-up** (XC-7, derivable-later) and no marker projection rerun (XC-5) inside
  this piece — the registries are built to make both mechanical afterwards.
- **No art/icon export work** (ACH-1) and no native-body derivation (XC-1, owner-costed) — the
  schemas mark those holes, they don't close them.
- **No audio/video/3D/GI/psd surfaces ever** — the media carve-out ([DR-2026-08-18-media-scope])
  leaves nothing for contracts to pin there.
