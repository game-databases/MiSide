## 1. What this dataset is

The **scene registry and placement layer**: which playable spaces exist, what
each is called in-game and in every locale, how they chain into chapters, what
spawns/appears where inside them — the dataset that FEEDS the owned map
(SPEC §Section map row 2; FRAMEWORK §2.6). It owns:

- the **scene registry** (level container → location naming → chapter
  grouping → sub-scene lattice);
- **points of interest** with whatever positions the client actually
  serializes (§2.6 measures exactly which POI classes carry coordinates);
- **spawn tables** (day-gated prefab creation) and **monster/anomaly
  carrier** instances;
- the **marker schema** for the owned map, with two-way entity↔map link
  integrity as a shipped guarantee.

It does **not** own dialogue text (DS3), character rows (DS1), achievement /
ending logic (DS-2), or minigame rules — it fixes the *join keys* those
datasets use to reach a place (§4). SPEC's `maps.coordinate-sources` cells
marked `client` become concrete here; `secret_easter_egg: unknown-P0`
stays `[unverified]`.

Competitor frame (D1 §8, COMP J2/J13): guide prose disagrees with itself on
cartridge chapters (Ghostly Mita ch 9 vs ch 10) and monster lore carries no
placement at all. This dataset replaces both with per-buildId scene facts.

   not track level numbers: level13 loads "Scene 17 - Dreamer" straight past

3. **`stringFileNamePart` is the chapter-name pointer** into the `Menu`

### 2.4 Chapter names are loc pointers — `Menu` 99–118

LOC `English/Menu.jsonl`: line 99 is the author comment `'// Name load
location'`; lines 100–118 are 19 chapter display names (100 *"I'm Inside a
Game?"*, 103 *"The Basement"*, 105 *"The Loop"*, 107 *"Dummies and Forgotten
Puzzles"*, 113 *"Being Candid"*, 115 *"Cappie"*, 116 *"Ghost Mita"*, 118
*'"Leave the Core!"'*). Cross-checks:

- `stringFileNamePart = 105` (level9) → line 105 = *"The Loop"*; `104`
  (level8) → *"Beyond the World"*; `113` (level14) → *"Being Candid"* — the
  pointer resolves cleanly for every non-zero value.
- **The client's canonical chapter sequence is the Menu order, and it
  disagrees with the wiki numbering D1 §1 tabulates** (client puts Cappie at
  position 15, Ghost Mita at 16; the wiki numbers them 6 and 10). The dataset
  therefore keys chapters by `line_index`, never by wiki number — the same
  identifier-preservation discipline DS1 applied to internal character names.
  A curated `chapter_no` column may later align the two orders, marked
  `inferred` with method `wiki-crosswalk`.
- 19 named segments ≠ D1's 20 units: no Prologue name exists in this block
  (level3, the tutorial/in-game segment, carries part 0 and empty `fileSave`).
  Recorded as a measured gap, not papered over.

### 2.6 The measurement that names this spec: which POI classes serialize positions?

The corpus holds **two classes of position evidence**, and conflating them
would be the dataset's cardinal sin.

**(a) Inline-serialized coordinates (usable today, MB fields):**

| Carrier | Instances | Position fields | Caveat |
|---|---|---|---|
| `World` | 20 | `positionSpawn:Vector3`, `rotationSpawn:Vector2` | root-level controller ⇒ world-space `[assumed, §9-R2]` |
| `Transform_Position` (DEC `Transform_Position.cs`) | 71 (levels 2–23) | `positions:TransformPoint[]` each `{position:Vector3, rotation:Vector3}` + `myParent:PPtr<Transform>` | **parent-relative** where `myParent ≠ 0` |
| `ObjectItem` | 262 | `positionFace/rotationFace:Vector3`, `positionItemInHand:Vector3` + `Quaternion` | **object-local hand/face offsets, NOT world placement** — never map-project these |
| `Transform_Magnet` | 191 | magnet attract points (`Vector3`) | local to the magnet's object |
| `Transform_MovePointsStartFinish` | 7 (level4 ×6, level9 ×1) | start/finish point vectors | path endpoints |
| `Rigidbody_StartVelocity` | 27 | initial velocity vectors | physics, not placement |

**(b) Referenced-but-not-dumped coordinates (PPtr into `Transform` objects
the harvest did not capture):** `Trigger_Teleport.targetTeleport` (14
instances, **all in level9** — the portal chamber), `Player_Teleport` ×13,
`MitaAIMovePoint.mitaa-target` ×31, `ObjectInteractive` ×312,
`ObjectInteractiveItemTake` ×11, `Trigger_DistanceCircle` ×32,
`Trigger_Event` ×334. Proof of absence: `Trigger_Teleport_#10938` targets
`Transform` pathID **6192**; ASL `level9.xml` contains **zero** entries for
pathID 6192 (grep) — the harvest captured type-id-114 assets only (§2.1).
This is the concrete shape of SPEC gap #1's "transform work": a
**scene-transform stage** (UnityPy walk of the level binaries emitting
GameObject→Transform pairs) upgrades (b) to (a) without any schema change
(§6).

of `mb-dump/*` double-counts every POI family. Measured whole-corpus vs

`Class.txt`, later ones `Class_#<pathID>.txt`; subclass stems such as
`ObjectInteractiveItemTake`, `ObjectInteractiveReqIK`,
`Transform_PositionCamera` counted separately):

| `ObjectInteractive` | 353 | 312 |
| `Trigger_Event` | 359 | 334 |
| `Transform_Position` | 105 | 71 |
| `Interface_KeyHint_Key` | 657 | 382 |

### 3.2 `scene-links.jsonl` — the additive lattice + chapter grouping

Rows `{from_level, edge_kind: loads|unloads|continues, to_sub_scene,
via_component, path_id, mechanism:"hard"}` from §2.3, plus the derived
level↔chapter rows `{level, chapter_name_loc:{category:"Menu",

### 3.3 `poi.jsonl` — every placement-bearing instance

```jsonc
{
  "poi_id": "level9:Trigger_Teleport_#10938",   // container + dump filename — stable per buildId
  "class": "Trigger_Teleport",                  // verbatim component class
  "kind": "travel_gate",                        // curated enum: cartridge|interactable|travel_gate|
                                                // monster|spawn_event|minigame_access|move_point|safe|other
  "level": "level9", "location_id": "Location7",
  "position": {
    "source": "inline|pptr-unresolved|none",    // §2.6 truth classes — THE honesty axis
    "space": "world-assumed|parent-local|object-local-offset|unknown",
    "x": null, "y": null, "z": null,
    "target": {"kind": "Transform", "path_id": 6192}  // when source=pptr-unresolved
  },
  "joins": {"save_key": "mtacap"},              // per-kind payload (FlashTaker.save, prefab ids…)
  "build_id": 19029065
}
```

Class→kind mapping ships as curated data (`poi-kinds.json`), one ruling per
class, mirroring DS3's `speakers.json` pattern. `ObjectItem.positionFace`
rows emit with `source:"inline"` but `space:"object-local-offset"` and are
**excluded from marker projection** (§3.5) — the field names a hand pose,
not a place.

### 3.4 `spawn-tables.jsonl`

One row per `Event_CreateResource`: `{spawn_table_id, level, event_day,
destroy_after_create, entries:[{parent_target, prefab_refs:[{file_id,
path_id}], prefab_count}]}`. Prefab identity resolves when the global
cross-container pathID index exists (§9-R4); until then refs are stored
verbatim and flagged `unresolved-target`.

### 3.5 `markers.jsonl` — the map-marker projection (FRAMEWORK §2.6 contract)

```jsonc
{
  "marker_id": "level9:cartridge:mtacap",
  "layer": "location-scenes/Location7",        // SPEC maps.layers membership
  "kind": "cartridge",                          // marker-kind vocabulary = poi kinds
  "entity_kind": "cartridge_item", "entity_slug": "cartridge-cap-wearing-mita",
  "icon": {"source": "ART sprite path", "fallback_state": "named-explicit-missing"},
  "position": {"x": null, "y": null, "z": null, "status": "awaiting-transform-stage"},
  "links": {"page_url": "/db/cartridge_item/cartridge-cap-wearing-mita",
             "focus_url": "/map?focus=cartridge_item:cartridge-cap-wearing-mita&scene=level9"}
}
```

Rules: markers exist **only** for rows whose entity dataset confirms the
entity (no orphan markers); icon comes from the ART layer with the
design-standard named-explicit-missing state (never stock art); positions
carry their truth status — a marker without coordinates renders as a
visible-locked cell on the authored schematic (TOOLS §3.3 checkerboard-void
discipline), never at a faked spot. Imagery stays authored (SPEC
`maps.imagery-path`); bounds/zoom/CRS declarations per scene land in
`maps.json` when the transform stage calibrates them (SPEC
`coordinate-transform: rect-per-map`).

## 5. Scale estimate (measured floor, this build)

- **Registry:** 24 scene rows (20 story + 4 special) · 19 sub-scene nodes ·
  ~44 lattice edges (loads+unloads+continues) · 16 non-zero chapter pointers.
- **POI floor:** 21 cartridge takers + 312 interactables + 46 teleport/scene
  carriers (14 `Trigger_Teleport` + 13 `Player_Teleport` + 19 `Scene_Load`)
  + 31 AI move points + 24 spawn events + 32 proximity triggers + ~110
  monster-carrier instances (§2.7 sum) + 71 `Transform_Position` point sets
  ⇒ **≥650 poi rows** at the v1 class set; grows past ~1,000 once
  `Trigger_Event` (×334) and the remaining trigger/click families are fully
  enumerated. `[projected]` markers after entity joins: ~500–800.
- Behind it: 140,380 typed dumps already on disk — **no new extraction runs
  are needed for stages 1–3** (§8); the transform stage (§6) is the only new
  read of the raw client.

## 6. Coordinate honesty & the transform-stage unblock

Today's corpus answers "where things are" only partially: §2.6(a) rows carry
real numbers; §2.6(b) rows prove placement exists but hold a pointer, not a
point. The unblock is one bounded stage — **S9 `scene-transform`** (PIPE
registry grows one line; same-commit entrypoint discipline per
[DR-2026-08-18-pipeline]): UnityPy walk of `level0–23` binaries emitting
`{container, game_object_path_id, transform_path_id, local_position,
local_rotation, parent_path_id}` JSONL, from which every §2.6(b) PPtr
resolves and per-scene bounds/calibration fall out mechanically. Until it
lands: `position.source` labels every row truthfully, markers render
visible-locked, and nothing on the map is guessed. Space semantics
(`world-assumed` vs `parent-local`) get calibrated per class during that
stage by comparing resolved child chains against `World.positionSpawn`.

## 9. Completeness risks

1. **Transforms are not in the corpus** (§2.6 proof) — every coordinate
   promise beyond inline fields depends on stage S9; until then the map's
   coordinate columns are honestly sparse. Mitigation is the labelling
   contract, not optimism.
2. **Space ambiguity of inline positions** — `Transform_Position` points are
   parent-relative where `myParent ≠ 0`; treating them as world coordinates
   would misplace markers silently. Mitigation: `space` field + S9
   calibration; `world-assumed` restricted to `World.positionSpawn`.
3. **Cartridge key curation:** `mta` (level17) matches no DS1 gallery
   `save_key`; `mtad2`/`mtacore` have no `FlashTaker`. Needs one curation
   ruling (owner/research confirmation) before slug assignment; display names
   can ship regardless.
4. **Cross-container PPtrs** (`m_FileID > 0`, e.g. `Event_CreateResource`
   prefab arrays at `m_FileID = 3`) dangle until the global pathID index;
   stored verbatim, flagged, never dropped (same posture as DS3 §9 item 2).
5. **level23 identity unresolved** — Peaceful-Mode stub vs cut/test level
   (COMP J11 interest). It emits as `role:"unbound"` with its full carrier
   inventory; inventing a binding would be fabrication.
6. **Chapter-order divergence client↔wiki** (§2.4) — if the site displays
   wiki numbers anyway, the crosswalk must be marked `inferred` with method;
   the data layer itself never stores them as game fact.
7. **Post-0.93L drift** — silent rebuilds could move `fileSave` names or
   spawn floats (SPEC gap #7); buildId stamps make it detectable, per-record.
8. **Client-only locales** (ar, ar-EG, ru-x-prerev) get no store
   corroboration for the Location*/Menu pools — parity rides the standard
   shipping bar (SPEC §Locale strategy).

## 10. Acceptance criteria (verifier-checkable)

Each criterion runs against emitted files + repo artifacts only, no extraction
rerun.

- **S1 — registry reconciliation:** `scenes.jsonl` carries exactly 24 rows;
  the 20 story rows match §2.2's table tuple-for-tuple (`nameLocation`,
  spawn floats byte-equal to the MB dumps); each story level contributes
  exactly one `World`/one `WorldPlayer` (ASL recount); level23 is present
  with `role:"unbound"` and null `location_id`.
- **S2 — chapter-pointer resolution ×34:** every non-zero
  `stringFileNamePart` resolves to a non-empty string at `Menu` line_index
  100–118 in **all 34 locale dirs**; zero-value parts emit `null` chapter,
  never a guessed name; the resolved EN multiset equals the §2.4 readings.
- **S3 — lattice closure:** every `nameSceneLoad` referenced by any
  `continues`/`unloads` edge exists as some row's `nameSceneLoad` or lands
  in a ledger row with the dangling name; level18's missing `Scene_Load` is
  recorded, not synthesized.
- **S4 — save-vocabulary parity:** the set of emitted `fileSave` ∪
  `nameLevelSaves[]` values equals the 19-literal `SaveGame` set from
  `extracted/il2cpp/stringliteral.json`, both directions, zero residue.
- **S5 — cartridge joins reconcile:** all 21 `FlashTaker.save` values appear
  in `poi.jsonl` joined rows; 20 match DS1 registry keys exactly; `mta`,
  `mtad2`, `mtacore` each carry an explicit curation-status row (never
  omitted, never auto-merged); `TamagotchiGame_Cartridge` rows are classified
  as the distinct in-fiction kind.
- **S6 — position-truth labelling:** 100% of poi rows carry
  `position.source ∈ {inline, pptr-unresolved, none}`; every `inline` row has
  three finite floats; every `pptr-unresolved` row names its target kind +
  pathID; zero rows expose `ObjectItem` face offsets as map coordinates
  (spot-check: no `markers.jsonl` row cites an `object-local-offset` poi);
  `space:"world-assumed"` occurs only on `World.positionSpawn` rows.
- **S7 — two-way entity↔map link integrity (the map gate):** (a) every
  `markers.jsonl` row's `(entity_kind, entity_slug)` resolves to exactly one
  row in the owning dataset's emitted files; (b) conversely, every entity in
  those datasets that this corpus places (cartridges via §2.7, save points
  via §2.3, monsters via §2.7 carriers…) has ≥1 marker row — both directions
  computed mechanically, every violation a ledger row, zero silent drops.
  Focus URLs match the SPEC §Section-map URL contract
  (`?focus=kind:slug`).
- **S8 — determinism + provenance:** two emitter runs over unchanged inputs
  produce byte-identical files; every record carries `build_id` +
  source container/pathID; user-facing provenance prints buildId only
  (AGENTS.md rule 3).
- **S9 — stub ladder enforced negatively:** no wiki-derived room names,
  chapter numbers, or coordinates appear anywhere in `extracted/data/scenes/`;
  unresolved identities live in README/candidates ledgers with locators
  (level23 inventory, `mta` ruling, Fog-anomaly candidacy).
- **S10 — objective layer wired:** every story scene row's
  `objective_hints` pointers resolve in all locales that carry the category;
  the FR-only/LD16-style contentless cases reuse DS3 §4's classification
  (contentless ≠ missing) rather than alarming.
