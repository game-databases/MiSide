Dependency edges:

```

M2 ──► M5 ledger ──► {M3, M4}   (route admission + hreflang + sitemap gate)

M2 ──► feeds news.xml/patch.xml (item lists from registry)
M2 ──► EntityDetailRoute        ("featured in" reverse module)
M3 ◄─ ⛓ LANE-B                  (map island embed slot, optional)
M4 ◄─ ⛓ LANE-A                  (patch summaries; empty-honest meanwhile)
M1 ◄─ OQ-1 ruling               (translation authority shapes M1 file layout)
```

Hard rule (AGENTS rule 8 restated for this piece): **the page layer never
opens an `.mdx` source or re-derives TOC/counts/links at request time.**
Routes read `content/emit/articles.jsonl` through a server-only reader
beside `src/data/contracts.ts` (same `readJsonl<T>()` discipline, same
`_meta.row_count` pin-or-throw). M2 is build machinery, not derivation of
game data — it packages repo-authored prose only.

Stack pin amendment: `site/package.json` currently pins NO markdown/MDX
dependency (verified this pass). M2 adds exactly one pinned renderer
(`marked`, zero-dep, gives lexer AST for TOC + word counts) — recorded
here as the single allowed manifest addition under scaffold AC-S1
discipline (the scaffold §1.1 stack table gains its matching row in the
same commit). Article bodies stay JSX-free markdown inside `.mdx` files
(§5), so no React-runtime MDX toolchain is pulled in.

That renderer is bound by an ESCAPE-FIRST law, enforced in M2 — no
sanitizer dependency is added: before rendering anything, M2 validates on
the same lexer AST it already walks for TOC/word counts and fails the
build on ANY token of type `html` at ANY depth (block or inline), naming
file + offending snippet; the same walk restricts link destinations to
`http:` / `https:` / `mailto:` / relative paths / `#fragments`, closing
the `[x](javascript:…)` hole with the same validator and the same failure
mode. No raw HTML ever enters an article body, so `marked.parse()` output
contains only markup generated from markdown syntax itself (enforcing AC:
C14).

## 3. Data contract — what M2 emits, who consumes

### 3.1 Registry shape (`site/content/emit/articles.jsonl`)

Line 1 `_meta` header (class-A `_meta` wrapper, data-contracts §2.2
class A — `readJsonl()` handles both shapes):
`{schema: "miside.content.articles/1", generator, build_id,
version_label, row_count, streams: {guide, game, database, patch}}`.

One row per published article:

```json
{
  "article_id": "guide:all-cartridges-route",
  "type": "guide",
  "slug": "all-cartridges-route",
  "title_en": "...",
  "locales": {"en": {"path": "/guides/all-cartridges-route",
                     "title": "...", "description": "...",
                     "word_count": 1240,
                     "body_sha16": "<sha16 of admitted .mdx source>"}},
  "entities": [{"kind": "cartridges", "id": "mta-arcade"}],
  "entity_row_hashes": {"cartridges:mta-arcade": "<sha16 of JSON row>"},
  "toc": [{"id": "step-3", "text": "...", "level": 2}],
  "spoiler": "mild",
  "verified_build_id": "19029065",
  "published_at": "2026-09-01",
  "updated_at": "2026-09-01",
  "status": "published",
  "stale": false,
  "body_ref": "guides/all-cartridges-route.en.html"
}
```

Compiled HTML lands beside the registry
(`site/content/emit/bodies/<file>`); the reader loads it lazily per page.
Each locale cell mirrors `body_sha16` from the admission ledger (§8.1) —
the ledger copy is authoritative; the registry mirror exists so
registry-only consumers never open the ledger. `_meta.row_count` pins the
row count; the existing throw-on-mismatch in `readJsonl()` is the
enforcement, unchanged.

### 3.2 Consumer table (each consumes; none derives)

| Consumer | Reads | Contract |
|---|---|---|
| Sitemap — `src/lib/sitemapPartitions.ts` | registry locales + paths | `guides@<locale>` / `news@<locale>` partitions list index + article URLs; replaces the placeholder `"achievements"` ternary (lines 39–46); lastmod stays `BUILD_STAMP` (extraction stamp, never wall-clock, AC S14) |
| Search — `scripts/emit-artifacts.mjs` | registry | one `SearchRow` per article × translated locale into `public/search/<locale>.idx.json`; `id` = `guides:<slug>` / `news:<slug>` (kind-namespaced law unchanged); kind-balanced cap (`MAX_VISIBLE_ROWS=60`) applies untouched |
| Feeds — `feeds/news.xml/route.ts`, `feeds/patch.xml/route.ts` | registry | RSS items per stream; GET handlers read the emitted file server-side (no fetch, no client bundle) |
| Reverse links — `EntityDetailRoute.buildModules` | registry entities[] | "Featured in guides/news" `ModuleList` panel when ≥1 published article references the entity; crawlable `<a href>` |
| Route admission — availability extension | `article_locales.jsonl` | a non-pivot article URL exists iff the ledger cell exists (§8.1) |
| Static JSON API + `/llms.txt` | registry | `/api/v1/guides/{slug}.json` + `/api/v1/news/{slug}.json` derive from the registry, fact-identical to the served page (scaffold AC-S11 law extends to article pages); published articles listed in `/llms.txt` |

The registry is the ONLY hand-off surface: adding a consumer means
teaching it the §3.1 shape, never re-parsing article sources.

### 3.3 Staleness model (per-record)

At emit, M2 hashes each referenced entity's full contract row into
`entity_row_hashes`. Every rerun recomputes; any hash change flips
`stale: true` on dependent articles, prints
`STALE: <article_id> <- <kind:id> (<field-level diff omitted>)` to build
output, and adds the article to a machine-plane list the editor works
from. A stale article still renders (its facts were true at
`verified_build_id`, which the page stamps user-facing per D2) — silence
about drift is the defect this kills, mirroring the row_count-pin lesson.

Translation staleness rides the same recomputation. Every locale cell of
`article_locales.jsonl` carries `body_sha16` — hash of the admitted
`.mdx` source at admission time (ledger cell authoritative; mirrored into
the registry's per-locale map, §3.1). At every emit M2 recomputes; when a
pivot EN hash moves, every sibling locale still carrying its old hash
prints `TRANSLATION-STALE: <article_id>@<locale> <- pivot moved` and
flags the cell stale — machine-plane only, never user-facing, same
discipline as the entity-drift flags above. An accepted-staleness ack
ledger (explicit ack list) was considered and rejected: extra workflow
state for little gain at this scale; the editor already works from build
output. One column, one comparison — closes the blind spot that would
otherwise open exactly when OQ-1 multiplies files ×34.

## 4. Entity-link law (mechanical)

Frontmatter is validated mechanically by M2 before anything renders.
Failure = nonzero exit + the offending file/id in stderr. No warnings, no
auto-correction, no fuzzy fallback.

Required frontmatter (all articles):

```yaml
---
type: guide            # guide | game | database | patch
slug: all-cartridges-route
title: "Every cartridge location"
description: "..."    # ≤160 chars, used verbatim in metadata + search rows
status: published      # draft | published  (drafts never reach the registry)
published_at: 2026-09-01
verified_build_id: "19029065"
spoiler: mild          # none | mild | full   (OQ-6 default pending)
entities:              # ≥1 required for guides; optional for news
  - cartridges: mta-arcade
  - achievements: ACH_cartridges_all
steps: []              # guides only, when the body honestly is steps
embeds: []             # declared slots only (§5), never inline JSX
---
```

Validation rules:

- **V1 Resolution:** every `entities[]` entry must be `<routed-kind>: <id>`
  where kind ∈ `ENTITY_KINDS` and id ∈ `kindIds(kind)` (exact string match
  against the contract id column — the same totality AC S6 already
  enforces for params). Unresolved → build fails.
- **V2 Vocabulary:** the kind segment is the ROUTED kind
  (`profiles`, not `documents`; `mita`, not `characters`). M2 rejects
  non-routed synonyms outright.
- **V3 Deterministic linking:** body mentions are linked FROM the explicit
  list — each listed entity's known name forms link occurrences in body
  order, first occurrence only, resolved per locale. No autolinker,
  no fuzzy matching, no regex scavenging beyond the declared set;
  internal linking is reviewable in diff (site-sections
  aggressive-linking rule satisfied mechanically). Tie-break law:
  1. **Shared display names never auto-link.** If two listed entities
     resolve to byte-identical display strings in a locale, NONE of the
     colliding names links in that locale (measured precedent: mita-usual
     ↔ mita-true both carry `name_loc {Menu, 83}` + `name_is_shared`).
     A wrong-entity link is worse than no link — first-listed-wins is
     rejected. Reverse-link modules and `entity-cards` embeds are
     unaffected; the collision suppresses body-text linking only.
  2. **Nameless rows link zero occurrences** (CAR-5 posture: 23/23
     cartridge rows ship `name_loc: null`), unless frontmatter declares
     per-entity `link_terms: ["Exact String"]` — exact case-insensitive
     whole-token match, first occurrence per term, diff-reviewable like
     everything else V3 does. Community aliases are NEVER auto-scavenged;
     they may be declared explicitly via `link_terms`.
  3. **Per-locale resolution, omit on empty.** Names resolve through THAT
     locale's loc pointers; an absent/contentless name cell yields no
     link in that locale — never an EN-string fallback (omit-never-mix,
     §8.1). Link positions are identical wherever names resolve;
     locales with hole-y names simply omit those links.
- **V4 Rename decay fails loud:** if LANE-A renames a contract id, V1
  breaks the build at the next run — the article can never silently lose
  its link graph (scout risk 3).
- **V5 Draft isolation:** `status: draft` rows are excluded from the
  registry entirely (not rendered-with-banner); nothing half-authored is
  reachable, indexed, or counted.

Guides require ≥1 entity (they are entity-linked by definition); database
news SHOULD carry entities (they name datasets/kinds in prose); game/patch
news MAY omit.

## 5. Embed contract — OUR components only

Bodies contain **no JSX, no HTML, no iframes**. Interactive behavior is
declared in frontmatter `embeds[]` and rendered by `ArticleRoute` from a
closed module map:

```ts
interface ArticleEmbed {
  id: string;            // anchor target in the body, e.g. "route-map"
  after?: string;        // heading/step id to insert after
  module: "map-scene" | "entity-cards" | "checklist";
  props: Record<string, unknown>;  // validated per-module below
}
```

- `map-scene` → the LANE-B scene-map island
  (`components/map/SceneMap.tsx` family, the `LocationModule` embed
  pattern already shipped on entity pages). Props limited to
  `{scene_id, focus_poi_id?, height?}`; renders the designed locked state
  until LANE-B's marker emission fills rows. ⛓ optional: absent module ⇒
  slot renders `VoidWell` honest-empty, never a substitute.
- `entity-cards` → card grid over `entities[]` using the existing kit
  (`CartridgeCard` / index-card builder `buildIndexData`), so guide
  sidebars reuse the exact art-selection rules of `indexArtFor`
  (no-image rows get the well, never a guess).
- `checklist` → static ordered checklist cards with `KeycapKbd` keycap
  hints; pure server markup, no hydration.

Forbidden everywhere in this piece: third-party embeds of any kind
(extends the `check-no-third-party-maps.mjs` grep to
`site/content/**`), remote images, inline `<script>`, tool-internal
imports (tools talk to guides only through this §5 contract). The "no
HTML" rule is enforced, not assumed: escape-first validation at the
lexer level (§2) — M2 rejects every `html` token at any depth of the AST
before rendering (build fail, file + snippet named) and allowlists href
protocols to http/https/mailto/relative/#fragment — so emitted body HTML
contains only markup generated from markdown syntax itself. JSX needs no
separate rule: without an MDX runtime, tag-shaped text in `.mdx` is inert
text caught by the same html-token deny.

## 6. M3 — Guides section

### 6.1 Routes

`/guides` + `/guides/[guide_slug]`, in BOTH trees
(`(pivot)/guides/…` bare EN; `[locale]/guides/…` prefixed ×33), thin
wrappers delegating to the new factories exactly as every existing
section does. `generateStaticParams` = translated-and-admitted guides ×
admitted locales, sourced from the M2 registry + M5 ledger (never from
directory listing). Unknown slug ⇒ 404 (`notFound()`), matching AC S6.

### 6.2 Page anatomy

Answer-shaped lead block (what this achieves, key facts, entities
touched — doubles as the seo-standard answer block) → TOC (from registry,
anchor-linked) → steps/modules → related-entities row (cards) → comments
slot (reserved, renders nothing until the UGC piece lands). Question-form
H2s where the heading genuinely answers a player question (wikily ruling,
borrowed deliberately).

`HowTo` JSON-LD emitted ONLY when `steps[]` is populated and each step's
text is the honest instruction — ship markup for understanding, expect no
rich result (seo-standard posture). NewsArticle JSON-LD belongs to M4
only; guides do not wear news markup.

### 6.3 Tone & design law (tokens.css binding)

- Steps, keycaps, checklist cards: cozy candy-pill register
  (`GradientPill`, `KeycapKbd`); danger/negative conditions (an action
  that loses an ending, a missable) use `--ms-danger` (#fc0f43) as
  SEMANTIC state — red always means "this loses you something", never
  decoration.
- Corruption/CRT treatments (`--ms-glitch-split-a/b`) reserved for
  compromised-information callouts (ending reveals, glitched-entity
  notes), matching how entity pages mark corrupted entities. No
  jumpscare mimicry, no motion-for-atmosphere; a11y floor owned by
  LANE-D's audit.
- Any horizontally-ordered component (stepper rail) ships an RTL leg in
  its own tests; `dir="rtl"` arrives free from `[locale]/layout.tsx:37`
  but component geometry does not.

### 6.4 Seed demand map

Editorial backlog = competitor demand (scout §1.4): 100% achievement run
(26 achievements, missables flagged via joins), all-cartridges placement
route (23 cartridges over DS-4 authority), ending-route walkthroughs
(371 choice nodes / 1,555 branch edges rendered as step spines), outfit
unlocks (minigames `unlocks_outfits`), secrets compilation (world

## 7. M4 — News section

### 7.1 Taxonomy — one hub, three typed streams

`/news` hub lists all streams filtered by type chips; stream-filtered
views are chip states, NOT separate URL sections (facet combinations
create no URLs — search-in-place law analog). Types:

- **game** — official game news: Steam RSS ingest + collab/Kickstarter/
  award items. Ingest is an OFFLINE editorial step producing committed
  `.mdx` files; the site build never fetches. Patch-date reality: four
  patches Dec 2024–Feb 2025, silent since v0.93L — this stream alone
  starves; database + evergreen guides carry retention (scout risk 2).
- **database** — dataset/locale/coverage news, mandated by
  [DR-2026-08-19-ugc-accounts] item 2. Anti-slop guard: items state
  facts ("Cartridges dataset gained placement coordinates for 11
  pickups"), never site self-narration ("we added a page").
- **patch** — `/news/patch/{id}` per-build data-diff pages; the CORE
  differentiator. Schema-ready, empty-honest until LANE-A ⛓ (OQ-4
  recommends holding the whole stream rather than shipping thin pages
  twice).

### 7.2 Provenance two-class law (binding)

User-facing: dates, titles, body, and `verified_build_id` /
coverage-scope stamps where data-bearing (narrowest truthful granularity,
DR-2026-08-22-numbers-stand-alone). Repo-only, banned from every served
pixel: source identity (Steam RSS URL, Kickstarter), upstream URLs,
license tags, acquisition paths — those live in frontmatter machine-plane
fields and the JSON-LD/feed layer only, exactly the D2 split AC S9
greps for. Official-worded quotes ride cite-and-attribute care; whether
full official bodies are stored at all is OQ-3 (GW3 Steam precedent vs
link-out summary).

### 7.3 Metadata & discovery

`buildEntityMetadata`-law per article: unique localized title/description
from THAT locale's authored strings (never EN passthrough), canonical
carrying the serving prefix, hreflang cluster == ledger membership via
`buildAlternates`. `NewsArticle` JSON-LD with publication dates; news
sitemap entries flow through the §3.2 partition gate.

### 7.4 Honest empties

A stream with zero published items omits its chip and its feed stays a
valid empty `<channel>` (current skeleton shape) — no captions, no
placeholder cards, ever.

### 7.5 IndexNow

seo-standard §2 ping on publish: DEFERRED to the LANE-D SEO batch if it
complicates the static pipeline; recorded here as deferred either way
(revisit at SEO-completion TODO row).

## 8. M5 — Article i18n and the TRANSLATION AUTHORITY gate

### 8.1 Mechanics (decided)

- **Storage:** sibling files — `guides/<slug>.mdx` (pivot EN, always
  authored) + `guides/<slug>.<code>.mdx` per translation. Greppable,
  diffable, and the file set itself is the translation inventory.
- **Per-article ledger** (emit artifact
  `site/content/emit/article_locales.jsonl`, cells
  `<article_id>@<locale>`): the single gate for route admission, sitemap
  partitions, hreflang clusters, and the cross-locale row. Each cell
  carries `body_sha16` — hash of the admitted `.mdx` source at admission
  time, authoritative here and mirrored into the registry locales map
  (§3.1) — which pivot-move staleness reads at emit (§3.3). Kept SEPARATE
  from `locale_availability.jsonl` so game-content provenance stays
  clean (OQ-5 recommendation; corpus ledger keeps its three row kinds
  untouched).
- **Fallback chain is OMIT, never mix:** no translated file ⇒ no
  `/{locale}/guides/<slug>` URL, no sitemap row, no hreflang member, no
  cross-locale cell — localization-architecture option A applied to
  authored content. Rendering an EN body under `/de/` violates the
  no-mixing law even behind a banner. Zero exceptions (AC C2).
- **Chrome:** `nav.guides`/`nav.news` already ship ×34; NEW keys
  (step/spoiler/updated equivalents) land in ALL 34 files in the same
  commit — chrome ships only at complete coverage (enforced by the
  existing `check-chrome-parity.mjs` in prebuild).
- **RTL:** ar/ar-EG inherit `dir="rtl"` from the shell; guide-specific
  horizontal components need their own RTL leg tests (MV-1 precedent).
  Persian stays `ltr` per the pinned table comment (SB-1 finding,
  `locales.ts:50–53`) until the flagged amendment — see OQ-7.

### 8.2 Translation authority — OWNER-GATED (do not resolve silently)

The mandate's source of record is the board line itself, quoted verbatim
— [docs/TODO.mdx](../TODO.mdx) Phase 3:

> Localized content layer: blog posts/articles translated to all 34
> corpus locales [promptForDB Note#7]

The bracketed annotation points OFF-repo: it numbers a note in the
owner's recurring tasking prompt, whose text is not reproducible from
this repo (`promptForDB.md` itself carries no numbered notes — verified
2026-08-26). Until the owner supplies that text, this spec treats the
board line alone as the demand and leans on the note number for no
argument. What the demand does NOT do is authorize machine translation,
and localization-architecture §6 names machine translation a non-goal
(for missing GAME locales). The two must be reconciled by an explicit
decision-register entry before M1 scales past pivot EN — and that entry
MUST quote the tasking-prompt note verbatim (owner supplies it at ruling
time), making the authority chain self-contained from that moment
forward. Options, with honest costs:

| Option | What it means | Cost / consequence |
|---|---|---|
| **A. Human-authored EN-first** | EN seeds; human translators produce each locale; omit-fallback hides gaps | Slowest ×34; honesty perfect; zero new tooling; likely months for the full matrix — yet RU is FIRST-WAVE launch content under EVERY option (below), so the co-primary audience never waits |
| **B. Corpus-locale reuse** | Reuse only client-shipped locale TEXT for game terms (via `resolveLoc` pointers), human-authored connective prose per locale | Terminology stays game-native ×34 — highest fidelity where readers notice (game terms); pace slowest-to-moderate (connective prose still needs humans); MODERATE new tooling B has and A doesn't (emit-side term resolution in M2); highest editorial overhead per article |
| **C. MT-assisted + human review** | Draft translations generated, human-reviewed before ledger admission | Fastest to 34 on paper — but the true bottleneck is REVIEWER capacity, not generation (finding named human reviewers for all 34, incl. ar-EG/pl/tr…, is the schedule term; MT drafting is nearly free); needs an explicit register entry overriding the §6 non-goal — a legitimate ask, since that non-goal scopes to missing GAME locales, not articles; residual risk of subtle wrongness in walkthrough-critical steps |
| **D. Staged rollout (wave-shaping hybrid)** | chrome+UI stay fully localized ×34 immediately — already shipped and parity-enforced, this plane is unconditional and NOT gated by OQ-1; long-form articles launch pivot EN + RU (RU human-authored: co-primary audience per scout §3.3, small volume, community-translatable); remaining locales follow behind whichever authority wins | Near-term cheapest honest path; zero MT pressure at launch; wave-shaping, not a fourth translation authority — composes with any of A/B/C; consequence: non-RU/non-EN guides arrive late (omit-fallback keeps honesty throughout) |

This spec builds identically under any of the four (D composes with
whichever authority rules; the ledger admits whatever locales exist;
nothing downstream assumes EN exists everywhere). What CANNOT proceed
without the ruling: mass-producing non-pivot files. Until the register
entry lands, M1 authors pivot EN only, and the sections launch with the
omit-fallback doing its honest work. **Flagged explicitly per the task
constraint: MT is NOT assumed in scope.**

RU co-primary (scout §3.3): first-wave launch content under every option
— option D states that as policy instead of leaving it implied.

Assessment carried to the owner with this table: D as the rollout frame,
plus B's terminology reuse wherever `resolveLoc` pointer plumbing exists;
escalate to C only via an explicit register entry quoting the
tasking-prompt note's text and NAMING the per-locale reviewers; A remains
available if zero new tooling wins. Whatever is chosen, the register
entry quotes the note (per the citation discipline at the top of this
section) and states the RU first-wave commitment.

## 12. Non-goals

- Comments/accounts runtime, moderation, uploads — UGC piece owns the
  reserved slot only.
- Changelog/diff computation — LANE-A; patch pages consume its output.
- Map viewer internals — LANE-B; guides hold the §5 slot contract only.
- Tool implementations — tools-plan.md scoring governs; no tool logic in
  article code.
- OG/share image templates — separate Phase-3 row.
- Game-data derivation of ANY kind — every factual claim traces to
  `extracted/` contracts via the §4 law; the pipeline packages prose,
  never computes game truth (AGENTS rule 8).
- Machine translation by default — OWNER-GATED (§8.2); no MT tooling may
  be added under this spec without a register entry.
