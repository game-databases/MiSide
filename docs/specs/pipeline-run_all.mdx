**Contract:** one discoverable entrypoint at the pack root,
`./run_all <path-to-game-files>`, reproduces the P1 slice of `extracted/`
A→Z with no tribal knowledge; every stage idempotent and runnable in
isolation; tool + version + buildId pinned in
`extracted/EXTRACTION-LOG.md`, which the entrypoint reads its defaults
from. Later pieces (entity datasets, logic, relink, contracts) plug in as
additional stages behind the same driver.

**Argument semantics:** `<path-to-game-files>` is the **game root**
(e.g. `A:\SteamLibrary\steamapps\common\MiSide\`) — the directory holding
`MiSideFull.exe`, `MiSideFull_Data\`, **and** the loose `Data\` tree. E1
proved the loc store sits at game root, *not* inside `*_Data\`
([E1 §Step 5](../research/explorer-e1-hands-on.mdx#step-5--localization-sanity-partial-plan-corrections),
deviation 1) — the driver resolves all three anchors from the one root and
`detect` hard-fails if any anchor is missing.

## 1. Non-goals (boundaries of later pieces)

P1 ends at a complete, proof-backed **raw layer**: typed dumps, loc JSONL,
art/media catalogue, decompiled source trees, census/PROOF source
inventory. It does **not** spec the internals of:

- **Entity curation** — canonical JSONL datasets (characters/Mitas, items,
  cartridges/minigames, locations, documents, achievements, endings,
  dialogue). P1 only produces the typed MonoBehaviour dumps and asset-list
  crosswalks they derive from.
- **Relink layer** — pairwise join matrix, UI-link→schema map,
  `RELATIONS.md`, `locale_availability.jsonl`. P1 preserves every internal
  identifier (PPtr pathIDs, `lineTranslate`, `steamAchievement`,
  category names) so relinking is possible, and emits the proven join
  authorities as *data*, nothing more.
- **Logic layer derivations** — `extracted/logic/` unlock predicates,
  ending trees, minigame rules. P1 ships decompiled structure
  (hierarchies/reference graphs) as input to that work.
- **Contracts** (`contracts/` pinning) — Phase 2.
- **Protocol section content** — single-player game still owes a protocol
  section in PROOF.md ([doctrine](../../../_foundation/extraction-doctrine.md#protocol-layer-clientserver-reconstruction));
  P1's census only seeds the section placeholder (Steam achievements/cloud
  saves/telemetry surface inventory is a later piece).
- **Demo diff pass** — dropped until a demo install exists
  ([questions.md](../questions.md) Q2).

stderr, no downstream stage starts; **LEDGER** = record the anomaly in the
stage's report, `extracted/census/stage-reports/<stage>.json`, and continue
(never silently drop — the ledger row is the product).

### S1 `env`

- **Inputs:** none (repo-local `pipeline/requirements.txt`).
- **Outputs:** `D:\unpacked_game_data\MiSide\work\venv\` (workroot default;
  `--work-root` overrides). Nothing in the repo.
- **Invocation (E1-proven):** `python -m venv <workroot>\venv` then
  `<venv>\Scripts\pip.exe install --quiet -r pipeline\requirements.txt`.
  Pins = E1's `pip freeze`: `UnityPy==1.25.3 pillow==12.3.0 astc-encoder-py==0.1.12 brotli==1.2.0 etcpak==0.9.15 fmod_toolkit==0.1.3 fsspec==2026.7.0 lz4==4.4.5 pyfmodex==0.7.2 texture2ddecoder==1.0.6 tpk_ar==0.2.4 attrs==26.1.0 archspec==0.2.6`.
  Python 3.14.7 works — the 3.12/3.11 fallback contingency never fired
  ([E1 §Step 1](../research/explorer-e1-hands-on.mdx#step-1--python-env-works)).
- **Idempotency:** skip install when `pip freeze` already matches the pins.
- **Failure:** FAIL-FAST (pip resolution error).

### S2 `detect`

Re-runs the flavor-detection procedure ([toolchain.md §1](../../toolchain.md#1-flavor-detection--result-already-pinned))
and the container census ([E1 §Step 4](../research/explorer-e1-hands-on.mdx#step-4--container-census-proofmd-source-inventory-evidence-works))
as code. This is patch-day step 1 of the update watch
([data-acquisition.md §Update watch](../../data-acquisition.md#update-watch)).

- **Inputs:** game root. **Outputs:** `extracted/census/detect.json`
  (verdicts + per-file census rows), initial `extracted/EXTRACTION-LOG.md`
  pin block when absent.
- **Checks (expected values from E1):** `GameAssembly.dll` at root
  (22,411,776 B) ⇒ IL2CPP; u32 LE at offset 4 of
  `MiSideFull_Data\il2cpp_data\Metadata\global-metadata.dat` = **29**;
  leading string of `globalgamemanagers` = **2021.3.35f1**; loc store at
  `<root>\Data\Languages\` present with **34** locale dirs; Voice Editor
  Mono tree present at `<root>\Voice Editor\Miside Voice Editor_Data\Managed\`;
  census: **51** SerializedFile-class files (**583,027,900 B**) + **69**
  stream siblings `.resS/.resource` (**1,694,288,048 B**) =
  **2,277,315,948 B**; no `.unity3d` bundles, no Addressables catalog.
- **Free-space guard:** `Get-Volume`-equivalent check before any write;
  ~10 GB headroom required (E1's estimate); bulk staging prefers `D:`/`A:`
  ([extraction-host §Where to write](../../../_foundation/extraction-host.md#where-to-write)).
- **Failure:** FAIL-FAST on missing anchors, metadata > 31 (message points
  at the Cpp2IL escalation, [toolchain.md §8 P6](../../toolchain.md#8-open-risks--probes)),
  or census total deviating from a previous `detect.json` by >0 B without
  `--expect-drift` (patch-day honesty: a silent byte change is a buildId
  change).

### S3 `il2cpp-dump`

- **Tool:** Il2CppDumper **v6.7.46** (net6 win zip, repo
  `tools\Il2CppDumper\release\`) unzipped once into `<workroot>\tools\Il2CppDumper\`.
  Headless config delta: scratch copy's `config.json`
  `RequireAnyKey: true → false` — stock config waits for a keypress and
  hangs non-interactive shells ([E1 deviation 4](../research/explorer-e1-hands-on.mdx#deviations-from-toolchainmd-consolidated)).
  No `script.json` input needed (registrations found by scan).
- **Invocation (verbatim shape from E1, PowerShell, absolute backslash
  paths — the MSYS-mangling avoidance):**

  ```powershell
  Il2CppDumper.exe <GAME>\GameAssembly.dll `
                   <GAME>\MiSideFull_Data\il2cpp_data\Metadata\global-metadata.dat `
                   <EXTRACTED>\il2cpp
  ```

- **Child cwd:** the driver runs the exe with its working directory pinned
  to the tool dir (`<workroot>\tools\Il2CppDumper\`) — E1 invoked it bare
  from that dir ([E1 §Step 2](../research/explorer-e1-hands-on.mdx#step-2--il2cppdumper-works))
  and cwd-independence was never tested; a cwd gotcha is on record for this
  exact tool ([toolchain.md §2](../../toolchain.md#2-raw-harvest-path)).
  Matching the proven shape costs nothing.
- **Outputs:** `extracted/il2cpp/` — `dump.cs` (E1: 10,420,763 B /
  288,102 lines, 6,281 types), `il2cpp.h`, `script.json`,
  `stringliteral.json`, `DummyDll\` (**57** DLLs incl. `Assembly-CSharp.dll`
  1,873,920 B). E1 wall time 2.48 s, zero warnings.
- **Failure:** FAIL-FAST (metadata-version gate is deterministic,
  [toolchain.md §7 pitfall 1](../../toolchain.md#7-known-pitfalls-pre-loaded-from-the-knowledge-base)).

### S4 `mono-typed-dump`

Typed MonoBehaviour dumps over every container, feeding entity curation.

- **Tool:** AssetStudioModCLI **0.19.0.0** (net8 portable zip, repo
  `tools\AssetStudioMod\release\AssetStudioModCLI_net8_portable.zip`; zip
  name carries no version — pin by assembly `FileVersion` as E1 did).
- **Invocation (E1-proven shape; input path strictly FIRST — options-first
  fails with `Error: Input path was empty.`):**

  ```powershell
  AssetStudioModCLI.exe <container> -m dump -t monoBehaviour `
    --assembly-folder <EXTRACTED>\il2cpp\DummyDll `
    -o <EXTRACTED>\harvest\mb-dump\<container-stem>
  ```

  The same pass is planned to also emit `--export-asset-list xml` per
  container to
  `extracted/harvest/asset-list/<container-stem>.xml` — the name/pathID/
  source crosswalk later pieces resolve PPtrs from
  ([toolchain.md §2 step 2](../../toolchain.md#2-raw-harvest-path)).
  **[unverified]** — E1 never exercised `--export-asset-list`, so the flag
  combination with `-m dump` is confirmed during build (§8); if dump mode
  does not emit it, fall back to a dedicated second pass or a
  UnityPy-derived crosswalk (AC-8 accepts either mechanism).
- **Containers:** all 51 SerializedFile-class files from the census:
  `globalgamemanagers`, `globalgamemanagers.assets`, `resources.assets`,
  `sharedassets0–23.assets`, `level0–23`. Text-dump quirks (tab indent,
  continuation lines, NUL residue, array shape) are handled by the
  established parser pattern ([toolchain.md §2 step 2](../../toolchain.md#2-raw-harvest-path)).
- **Known behavior to design around:** dumping `resources.assets`
  auto-resolves dependencies (E1 saw 5 files loaded: + globalgamemanagers.assets,
  sharedassets0.assets, both builtin resources) — per-source attribution
  during reconciliation must account for it (E1 deviation 6).
- **Measure-first gate (R-E1-1):** before the full sweep, dump the smallest
  `levelN` alone and record object/type mix + wall time in
  `extracted/census/sweep-budget.json`; the full-sweep loop consumes that
  budget. Level dumps are expected orders larger than 993 objects. The S2
  free-space guard re-fires (same 10 GB bar, `common.py` helper)
  immediately before the full sweep starts — level/sharedassets writes are
  the largest unknown in the run.
- **Outputs:** `extracted/harvest/mb-dump/<container-stem>/*.txt` (E1:
  993 fully-typed dumps from `resources.assets` in ~2.0 s; `DataAchievements`
  carries the 26-entry array with `steamAchievement` ↔ icon PPtr ↔
  `lineTranslate` three-way join intact),
  `extracted/harvest/asset-list/*.xml`.
- **Failure:** per-container FAIL-FAST by default, `--keep-going` downgrades
  to LEDGER — each attempt (container, argv sha, exit, objects dumped)
  lands in `extracted/census/sweep-attempts.jsonl`, so a half-swept
  corpus never looks complete and census S8 reconciles attempted-vs-
  succeeded from that ledger. Ledger write mode: **deterministic full
  rewrite** — at stage end the driver rewrites the whole file from this
  run's attempts, one row per container in sweep order, never appending;
  a rerun over unchanged inputs therefore reproduces it byte-for-byte
  modulo the volatile fields. All ledger-style artifacts follow the same
  rule (`_ledger/locale-delta.jsonl`, `census/stage-reports/<stage>.json`)
  — rewritten per stage run, never appended — so idempotency holds by
  construction.

### S5 `loc-jsonl`

- **Input:** `<GAME>\Data\Languages\<locale>\<Category>.txt` (loose tree at
  game root — E1 deviation 1) + `Textures\` + `Font` per locale.
- **Emission:** `extracted/localization/<locale>/<category>.jsonl`, one
  record per line: `{category, line_index, text}` with `line_index`
  zero-based — the join key proven end-to-end:
  `GlobalLanguage.GetString(name, index)`
  ([E1 §Step 7](../research/explorer-e1-hands-on.mdx#step-7--dumpcs-recon-works);
  loader chain `CheckLocalization → LocalizatioLoad → LocalizationClearText`
  in `ConsoleInterface`). Text preserved verbatim UTF-8, odd chars
  recorded, never normalized ([toolchain.md §4](../../toolchain.md#4-localization)).
  **Line counting is split-based** — category files carry **no trailing
  newline**; `wc -l` undercounts (EN `Achievements.txt`: 25 reported, 26
  real, matching `lineTranslate` 0–25) (E1 deviation 3).
- **Ledger:** `extracted/localization/_ledger/locale-delta.jsonl` —
  per-locale present-vs-reference(EN) category set plus per-locale
  `Textures\`/font subset rows (both halves of R-E1-3). Category counts vary
  64–76/dir (French max; Arabic (Egyptian)/Belarusian min) and per-locale
  texture subsets differ (JA 20 png vs EN/RU/FR 26) — assert-equal is
  forbidden; the skew ledger is the deliverable (E1 deviation 2, risk
  R-E1-3).
- **Scope boundary:** per-locale `Textures\`/fonts are *catalogued* here
  (rows handed to S6's MEDIA-CATALOGUE), not copied inline — they are part
  of localization, not droppables ([toolchain.md §4 item 3](../../toolchain.md#4-localization)).
- **Failure:** LEDGER for missing categories/locales (skew is expected); a
  non-UTF-8-decodable category file is LEDGERed too — raw bytes hex-encoded
  into the stage report, parsing continues, and the stage exits non-zero at
  stage end if any file was ledgered (honesty without letting one odd file
  among 2,210 block the whole loc layer); FAIL-FAST only if the store
  itself is absent.

### S6 `art-export`

Implements the art policy table ([toolchain.md §5](../../toolchain.md#5-art-export-policy))
under [DR-2026-08-18-media-scope](../../../_foundation/decision-register.md#owner-ruling--videoaudio-offloaded-3d-and-heavy-assets-catalogue-first-dr-2026-08-18-media-scope):

- **Staged scope ([questions.md](../questions.md) §6, A→STAGED):** the
  walk/catalogue pass runs first; each family's export-vs-catalogue scope
  is derived from those first-pass row counts under the per-family rule in
  [toolchain.md §5](../../toolchain.md#5-art-export-policy) and recorded in
  EXTRACTION-LOG.md — decided at build time from measured rows, per family
  not globally, with no owner round-trip inside P1.
- **Export (2D):** sprites + Texture2D → PNG via AssetStudioModCLI
  `-m export -t sprite,tex2d` (same input-first CLI discipline), atlas
  sub-rects via UnityPy `Sprite.image`; WebP conversion with Pillow
  (already pinned in S1). Sprite-vs-Texture2D preference is baked **per
  asset family**, not globally ([toolchain.md §5](../../toolchain.md#5-art-export-policy)).
  Outputs `extracted/art/<family>/…`. Loose `Data\Custom\*.png` character
  templates copy through verbatim as raw-layer artifacts. The free-space
  guard re-fires (same 10 GB bar, `common.py` helper) before export begins
  — `.resS`-decode write volume is unmeasured.
- **Catalogue (everything else):** emit `extracted/MEDIA-CATALOGUE.md` +
  `extracted/media-catalogue.jsonl` rows with counts + bytes, measured by
  filesystem walk (numbers below are E1's, re-measured at runtime):
  audio `.ogg` **28,725 files / 1,441,141,744 B** (media carve-out: never
  emitted into `extracted/`), GI Enlighten tree **62 files / ~5.9 MB**
  (level3 only — R-E1-4: catalogue, don't chase), `.psd` **3 / 26,384,140 B**,
  per-locale localized art (**777 png + 3 psd** globally), 3D models and
  animations catalogue-first; textures start catalogue-first and flip to
  export only where the derived staged scope above says so.
- **Offload boundary ([questions.md](../questions.md) §5 ruling):** the
  live Steam install is never mutated — this stage writes catalogue rows
  and a *proposed* reverse-move manifest, performs **no destructive move**,
  and creates no pack-held media copies unless the owner later opts in;
  audio+video stay IN PLACE on `A:`, catalogued with paths+bytes.
- **Failure:** LEDGER per unconvertible asset (named black-square policy is
  frontend's problem; the catalogue must stay complete); FAIL-FAST if
  catalogue byte sums disagree with the walk.

### S8 `census`

Writes `extracted/PROOF.md` per Principle two
([doctrine](../../../_foundation/extraction-doctrine.md#principle-two-completeness-is-proven-not-claimed)):

1. **Source inventory** — every container/source with sizes/totals **and
   how each was measured** (tool + count method): the 51+69 container
   census from S2, the loc tree (34 dirs / 2,210 txt / 777 png + 3 psd),
   the `.ogg` family, GI tree, `Data\Custom`, Voice Editor `*_Data` as a
   second source row ([toolchain.md §8 P7](../../toolchain.md#8-open-risks--probes)).
2. **Coverage reconciliation** — per source: attempted vs succeeded, read
   from `census/sweep-attempts.jsonl` + the per-stage reports (containers
   swept vs dumped; loc files parsed), diff explained. Numbers
   must reconcile to source totals byte-for-byte.
3. **Residue ledger** — seeded from E1's known gaps: levelN dump depth
   pending measurement (R-E1-1), per-locale category/texture skew ledgered
   in S5, GI level3-only (R-E1-4), unlock-state bools needing
   defaults-vs-live separation downstream (R-E1-2).
4. **Remaining theoretical surface + protocol placeholder** — seeded;
   filled by later pieces (Non-goals).

- **Failure:** FAIL-FAST on any reconciliation mismatch — a wrong total is
  worse than a crashed run.

## 3. Entrypoint + output tree

Driver CLI (stdlib `argparse`, no third-party deps outside the venv):

```
run_all <game-root>                     # all stages in registry order
run_all <game-root> --list              # print stages in order + one-liners
run_all --help                          # usage, args, per-stage flags
run_all <game-root> --stage loc-jsonl [--stage art-export]
run_all <game-root> --from mono-typed-dump --to census

```

Exit codes: `0` ok · `2` usage error · `3` stage failure (failed stage
named on stderr) · `4` missing dependency outputs (run the earlier stage

## 5. Acceptance criteria (TestWriter contract)

**Entrypoint surface**

- **AC-1** `run_all --list` prints exactly the 8 registry stages in
  execution order, each with a one-line description; exit 0; touches
  nothing.
- **AC-2** `run_all --help` prints usage including `<game-root>` semantics
  (root holds `*_Data\` AND `Data\`), all flags, all four exit codes
  (0/2/3/4); exits 0 on `--help`; a usage error exercises exit 2.
- **AC-3** A full run executes S1→S8 in registry order; a failing stage
  stops the run with exit 3 and names the failed stage on stderr; no
  downstream stage runs. Invoking a stage whose dependency outputs are
  absent exits 4 naming the missing stage; a stale `EXTRACTION-LOG.md`
  pin block (pins disagreeing with `pipeline/requirements.txt`) aborts
  the run before S1 (stale-log defense).

**Isolation & idempotency**

- **AC-4** `--stage <name>` produces outputs byte-identical to the same
  stage's outputs within a full run (same inputs, same workroot), modulo
  the volatile fields enumerated in
  `extracted/census/volatile-fields.json` (measurement timestamps,
  wall-time durations, host names).
- **AC-5** Running any stage twice consecutively changes no byte under
  `extracted/` beyond mtimes and those volatile fields — e.g.
  `sweep-budget.json` wall times, the `detect.json` measurement stamp,
  stage-report run facts — except `EXTRACTION-LOG.md`, which gains no
  new line when tool set, buildId, and inputs are unchanged (record dedupe).
  Ledger-style artifacts (`sweep-attempts.jsonl`,
  `_ledger/locale-delta.jsonl`, stage reports) obey the S4 write mode —
  deterministic full rewrite, never append — so a rerun reproduces them
  byte-identically modulo the volatile fields. Idempotency means same data, not same clock: a rerun
  that changes any non-enumerated byte fails.

**Per-stage correctness (values = E1 ground truth on the current install)**

- **AC-6** `detect` reports: Unity `2021.3.35f1`; metadata version 29;
  IL2CPP verdict; 51 SerializedFiles / 583,027,900 B; 69 streams /
  1,694,288,048 B; grand total 2,277,315,948 B; 34 locale dirs at game-root
  `Data\Languages\`; and writes those totals where S8 can consume them.
- **AC-7** `il2cpp-dump` yields `dump.cs` (≥250k lines; E1 pinned
  288,102 — deviation >5% from the EXTRACTION-LOG-pinned count warns and
  logs, never fails), `il2cpp.h`, `script.json`, `stringliteral.json`, and
  57 DummyDlls; runs in seconds-class, headless (no stdin wait —
  `RequireAnyKey:false` verified in the scratch config).
- **AC-8** `mono-typed-dump` accepts options-after-input only (options-first
  is never emitted); `resources.assets` produces ≥993 typed dumps with
  non-empty field trees, `DataAchievements.txt` among them with a 26-entry
  array; all 51 containers are attempted and each attempt is recorded in
  `census/sweep-attempts.jsonl` (container, argv sha, exit, objects
