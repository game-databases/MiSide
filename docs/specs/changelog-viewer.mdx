## 3. M1 — Data-side emitters (`extracted/data/changelog/`)

Writer is `contracts/emit_changelog.py` (beside `check_contracts.py`,
same generate-and-verify discipline); nothing under `changelog/` is ever
hand-edited after emit. All three artifacts are class-A `_meta` wrappers
(data-contracts §2.2): first line carries `schema`, `generator`, `build_id`,
`version_label`, `row_count`; readers dispatch on the wrapper, and
`readJsonl()`'s pin-or-throw is the enforcement.

### 3.1 `patches.jsonl` — the dated event registry (Arm A spine)

Schema `miside.changelog.patches/1`. One row per dated public event:

```json
{
  "patch_slug": "v0-921",
  "label": "v0.921",
  "date": "2024-12-29",
  "event_class": "patch",
  "title": "Load-point renames + six more languages",
  "summary_facts": [
    "Save-point labels renamed (Cap → Cappie, Open Dialogue → Be Candid)",
    "Six language additions (id, th, hu, ro, sv + es-ES voice)",
    "New Year decorations"
  ],
  "source_kind": "wiki-table",
  "source_ref": "en-fandom:MiSide/Versions#v0.921",
  "build_id": null
}
```

- `event_class ∈ {release, patch, demo}` — schema /1 pins exactly these
  three. **Correction to the Scout:** its draft vocabulary also listed
  `collab | kickstarter | award | note`; those dated items belong to the
  **game stream** by content-pipeline §7.1's own taxonomy ("Steam RSS
  ingest + collab/Kickstarter/award items"), and duplicating them here
  would mint a second URL per event. They are seeded once, in the game
  stream. The `build_id` column stays nullable: only rows whose label the
  corpus actually pins carry one (today exactly `v0-93l` =
  `19029065`, per EXTRACTION-LOG's versionLabel pin).
- `source_kind ∈ {wiki-table, steam-news-item, keyless-api, encyclopedia}`
  and `source_ref` are **machine-plane forever** (AGENTS rule 3): the
  served page renders date + label + facts, never the source identity.
- Seed = the eight build-axis rows of [D1 §7](../research/game-research.mdx):

| slug | date | label | class | source_kind |
|---|---|---|---|---|

### 3.2 `build_integrity.jsonl` — fingerprints as a public artifact

Schema `miside.changelog.build_integrity/1`. A normalized, order-stable
projection of `fingerprints.json` — one row per artifact:

```json
{
  "path": "extracted/data/achievements/achievements.jsonl",
  "family": "achievements",
  "plane": "data",
  "sha256": "f4220fcc734deeb8a2c45f08341892332d858c654cac8bee205dd28786ea89be",
  "row_count": 26,
  "build_id": "19029065",
  "build_id_source": "row-stamp"
}
```

`plane ∈ {data, relink}` from the path prefix (55/29 today); the
`pipeline_pin` rides the `_meta` header. This file is what makes the
integrity panel (§8.2) possible: the frontend renders it verbatim and
never recomputes anything. Emission fails closed: if
`check_contracts.py verify` reports any mismatch, M1 refuses to write a
stale projection (CL-2).

### 3.3 `save_point_renames.jsonl` — documented lineage, labeled

Schema `miside.changelog.save_point_renames/1`. Rows join the spec's
`save_point` entity attributes (`name-per-build`, `rename-lineage`) to
patch-note evidence:

```json
{
  "entity_kind": "save_point",
  "entity_id": "cap",
  "attribute": "display_name",
  "from_value": "Cap",
  "to_value": "Cappie",
  "patch_slug": "v0-921",
  "evidence_class": "documented-note"
}
```

The emitter **refuses** `evidence_class: "computed"` unless the row was
produced by an M2 changeset in the same run — enforced structurally (M2
writes those rows itself; M1 can only emit `documented-note`) and by test
(CL-1). Seed rows — three at v0.921 (COMP J9): `Cap → Cappie`
(`entity_id: "cap"`), `Open Dialogue → Be Candid`
(`entity_id: "open-dialogue"`), and `Out of the Core → Leave The Core`
(`entity_id: "out-of-the-core"`) — all `attribute: "display_name"`,
`evidence_class: "documented-note"`. Spelling caveat recorded: D1's
chapter table writes `"Leave the Core!"` while its rename line writes
`Leave The Core`; `to_value` pins VERBATIM to the rename line, which is
the patch-note-derived evidence CL-3 resolves against. Entity ids remain
provisional joins to the spec-declared `save_point` entity
([spec.md](../../spec.md)) until LEVELS checkpoint configs are
extracted. Minigame tuning notes at v0.93 stay `summary_facts` on the
patch row until a computed diff decomposes them.

### 3.4 Emission laws (fail loudly, never silently unlink)

1. **Traceability**: every `patches.jsonl` row must resolve `date` +
   `label` against its `source_ref`; unresolved ⇒ nonzero exit naming the
   slug (the row_count-pin lesson; Scout risk 3).
2. **Row-count pins**: `_meta.row_count` exact; `readJsonl()` throws on
   drift.
3. **Slug uniqueness + route-safety**: slugs are lowercase `[a-z0-9-]`,
   unique across the file, and never collide with an article slug in the
   other streams.
4. **Order stability**: artifacts sort by (`date`, `patch_slug`) /
   (`path`) so byte-stable regeneration holds (PIPE AC-5 mode).
5. **Plane hygiene at emit**: any seed row whose `title`/`summary_facts`
   contains a repo-plane token (upstream URL, extractor name, license
   tag) fails the build — the same both-directions grep family as AC S9.

## 4. M2 — Diff activation stage (dormant by design)

### 4.1 Dormancy contract

S10 registers in `run_all` LAST, after `logic-layer`, and **exits 0
emitting zero bytes whenever fewer than two distinct build trees exist**
— no stub changesets, no empty-shell files, no log noise beyond one
machine-plane line stating the dormancy condition. Honest omission is
the feature (CL-8). Today's tree: S10 runs M1 (always) + the diff arm
(never). The anchor sits after `logic-layer` BY NAME, not by number,
for two measured reasons: M1 projects all 84 fingerprints — including
the four `extracted/data/logic/**` entries logic-layer rewrites on a
patch-day rerun — so registering before logic-layer would snapshot
stale digests (CL-2 red) and let the diff arm compare mid-rerun pins;
and positional numbers drift when scene-transform (canonically reserved
S9) eventually inserts mid-list, while name-based ordering does not.

### 4.2 Trigger chain (ridden, not rebuilt)

The update watch is DAQ's design; S10 is its last consumer:

1. appmanifest `buildid` ≠ 19029065 (local read + keyless appdetails
   cross-check);
2. DepotDownloader pull to `D:\Games\MiSide_<buildid>\`
   **keeping tree N−1 until diffing completes**
   ([data-acquisition §update watch](../../data-acquisition.md));
3. `./run_all <path>` rerun → every fingerprint invalidated → re-pinned
   in the emit-stage commit (patch_day law) → site rebuild unblocked;
4. S10's diff arm writes the prior-pin witness from tree N−1 FIRST
   (§4.3), then compares N−1 vs N and emits.

### 4.3 Diff algorithm when armed

- **Level 1 — artifact sets**: symmetric difference of the per-artifact
  sha256 maps between the two re-pins ⇒ added / removed / changed
  artifacts.
- **Level 2 — records**: inside changed `.jsonl` artifacts, join on
  preserved internal identifiers (COMP net advantage 5 — ids survive
  verbatim) ⇒ added / removed / value-changed records, keyed
  `record_id + field`.
- **Renames**: a removal paired with an addition whose non-name fields
  match ⇒ `renames.jsonl` row with `evidence_class: "computed"`.
- **Outputs — prior-pin witness (first)**: at trigger time, BEFORE tree
  N−1 is released and before any changeset is written, M2 hashes tree
  N−1's fingerprinted artifact set under fingerprints conventions and
  writes `extracted/data/changelog/_pins/<from>-to-<to>.json`, schema
  `miside.changelog.prior_pin/1` — fields `from_build_id`,
  `from_version_label`, `to_build_id`, `to_version_label`,
  `artifacts[]{path, sha256}` (the from-side digest map), `row_count`;
  the ids must parse from the directory name. This record is the durable
  witness for CL-1: tree N−1 itself is deleted once diffing completes
  (keep-until-diffed law, §4.2 step 2), so without it the from-side of
  every changeset rests on nothing verifiable. Pre-trigger the stage
  emits zero bytes including zero `_pins/` files (dormancy law
  unchanged).
- **Outputs**: `changesets/<from>-to-<to>/{artifacts,records,renames}.jsonl`
  (schemas `miside.changelog.changeset_{artifacts,records,renames}/1`)
  plus `code_plane_digests.jsonl`.
- **Code-plane rider (OQ-3, recommended mandatory)**: every changeset
  carries digests for the layers data rows cannot see — `il2cpp/dump.cs`,
  `script.json`, `il2cpp.h`, `stringliteral.json`, and a sorted
  path+sha256 manifest rolled up over `decompiled/main/**`. Any
  "unchanged" claim the UI makes is thereby scoped to the layer actually
  hashed; LG2 projections (`flag--gates.jsonl`, `choice--consequence.jsonl`)
  already ride the fingerprint surface under KEEP-PINNED
  ([data-contracts §4.4](data-contracts.mdx#44-keep-pinned-lg2-relink-projections-are-fingerprinted-not-join-families-f-ct3-2026-08-26)),
  so the BPB failure mode — publishing "nothing changed" over invisible
  script churn — is structurally fenced.

### 4.4 Demo boundary

Demo 2527520 covers ch 0–3 and shares no time lineage with the full
game: it is a **scope slice, not an ancestor build**, and never produces
a `/news/patch/` page. Its only sanctioned use to date is as a
mechanics-shakeout second tree for S10 behind an owner SteamGuard session
(OQ-2); a user-facing demo-vs-full comparison, if ever ruled in, belongs
to a compare tool, not the changelog.

`_meta` stops being permanently empty; content-pipeline OQ-4's "hold the

## 8. M5 — Interactions, i18n, and corruption semantics

### 8.1 Version picker — single-entry honesty

Selected state is a URL, never component-local (design-standard law):
picker targets are the existing slugs, written as segments/params
(`?from=&to=` form reserved for the future compare state). **At one
build the picker does not render at all** — not disabled, not shown with
one item; the timeline itself is the version list. When build #2 arms
S10, the picker enumerates only existing build pages + changeset pages;
any filter answers as typed, no submit controls
([DR-2026-08-22-inputs-answer-as-you-type]). A control that implies
choice where none exists is the same defect as a fake diff.

### 8.2 Artifact integrity drill-down

`#integrity` renders all 84 rows: path · short sha (first 16 hex, full
digest in `title`/copy affordance) · `row_count` · `stamp class`. Group
by family headers (55 data / 29 relink), sorted by path; ≤200 rows/page
bound is met with room. Row expansion state lives in the URL fragment
per-row anchor. The panel shows **values, not health words** — no
"verified/fresh/stale" vocabulary (DR numbers-stand-alone); byte-truth is
proven in CI (CL-2), not narrated at users.

### 8.3 Rename-lineage grammar (corruption semantics, finally literal)

State treatment, never decoration — token mapping pinned to tier-1 rows:

| Change class | Treatment | Tokens |
|---|---|---|

`evidence_class` is never printed as a caption (anti-slop ban on

recommendation).

### 8.4 Entity-scoped change views

Reverse-index module "Changed in …" on entity pages, fed from
`changesets/*/records.jsonl` via the consumer table. Absent until the
first changeset exists — omitted entirely, never rendered as a captioned
empty well. (The checkerboard `VoidWell` remains the only empty-state
visual anywhere in the piece.)

### 8.5 i18n

Chrome keys land ×34 in one commit with identical key sets (parity
checker gate). Timeline rails get an RTL leg mirroring the MV-1
precedent; ar/ar-EG serve `dir="rtl"` (CL-12). Page admission follows
`_foundation/localization-architecture.md` §1 bullet 2 (localized
content is never mixed across languages on one page) + §5 item 5 (a page
lacking admitted content in a locale is either omitted or rendered with
a pack-declared filler — this pack rules OMIT): pivot EN publishes
immediately; a non-pivot `/de/news/patch/<slug>` exists iff a
translated cell is admitted under content-pipeline §8's translation-
authority gate. Summary facts are never machine-translated and never
EN-passthrough onto a localized URL.

## 9. Honest states, stub policy, and the starvation note

Before M1 lands, the current empty-honest skeletons stand EXACTLY as
shipped (`ArticleType` member present, empty `patch.xml`, no chip) — no
preview cards, no "coming soon". After M1: chip appears, pages publish,
feed fills; there is no transitional state between skeleton and truth.

**Starvation is handled as content strategy, not fabricated cadence.**
No release-notes post has appeared since v0.93L (2025-06-13 — ~14 months
of patch silence while game news continues). The patch stream therefore
ships a finite, dated, rot-free corpus and stops; retention belongs to
the database stream and evergreen guides (content-pipeline §7.1, scout
risk 1). This piece will never invent an event, extrapolate a date, or
render silence as activity — a quiet changelog that is byte-true beats a
busy one that is fiction, and unlike every competitor's hand-maintained
table it does not rot between patches.

## 12. Non-goals

- Computed diffs, hashes, or lineage at request time — M1/M2 own all
  derivation; pages consume (AGENTS rule 8).
- Authored patch prose / `.mdx` bodies — patch pages are typed-field
  renders; editorial game news lives in content-pipeline M4.
- Demo-vs-full comparison surfaces; historical tree reconstruction
  (OQ-5 default NO).
- Standalone `/changelog` section (OQ-4 recommendation: hub shell stays
  content-pipeline's; new top-level sections are a domain-doctrine owner
  call).
- The tools-lane interactive compare UI (tools-plan §3.7) — it arms off
  these changesets when they exist.
- OG/share image templates; IndexNow pings; comments/UGC runtime.
- Fabricating any row to soften starvation (§9) — the anti-fake gate
  makes it a build failure, not a policy preference.

## 14. Risks

1. **Starvation** (~14 mo game silence): structural mitigation in §9 —
   ship truth that does not rot; retention rides database news +
   evergreen guides. Not solved with data.
2. **Disk (OPS GATE C)**: Phase-5 EMERGENCY pauses builds (TODO); M1
   emission needs the ≥10 GB free window confirmed before it lands
   (artifacts are small; the gate protects the rerun that re-pins).
3. **Source-ref drift**: patch rows depend on LANE-C news-ingest ids for
   two rows' `steam-news-item` refs; CL-3 must fail the build loudly,
   never silently unlink (row_count-pin lesson).
4. **Second-build surprise**: when the trigger fires mid-other-work, S10's
   diff + re-pin must complete in ONE commit or the site stays red by
   design (patch_day law); the runbook step belongs to DAQ's update
   watch doc, cross-referenced here.
