## 1. Scope

This dataset owns the **rows** for exactly two SPEC entity kinds:

- `cartridge_item` — flash-drive collectibles depicting Mitas and containing
  converted players (SPEC §entities; D1 §3);
- `minigame` — playable mini-game surfaces with access medium, carriers,
  rule/threshold evidence, and unlock hooks (SPEC §entities; tools lane
  "Minigame Rule Revealer", [tools-plan.md §3.5](../../tools-plan.md)).

Everything else is **joined, not owned**: character identities (DS-1),
achievement definitions ([DS-2](dataset-achievements-endings.mdx)), scene
transforms/placements and chapter attribution (scenes dataset, P5-gated),
outfit rows (outfit side of DS-1's join plan), profile documents
(`profile_document` is its own SPEC kind — not a cartridge; no row here).
Scales in SPEC were estimates ("~23", "~17"); this spec replaces them with
measured registry sizes (§3): **23 cartridge keys (13 character-family + 10
player), 21 with measured pickup carriers**, and **17 client-evidenced
minigame surfaces** pending one emit-time sweep (§3.2).

**Shared-source ruling — pickup placement (with [DS-5](dataset-documents.mdx)).**
The 21 measured `(container, save)` pairs appear in two emit plans: here as
`pickup_ref` (§4.1) fed by the §3.1 C2 census, and in DS-5's
`profile_documents.jsonl` `placement` column (its §3 table, §4.2 schema).
This dataset is the **single placement authority** for cartridge pickups —
the FlashTaker carrier census is a primary source of this spec (C2, §3.1,
AC-2) and the cartridge row is the entity the pickup places — so DS-5
consumes the pairs by reference to this dataset's emission instead of
re-measuring them, and its §1.2 boundary row gains a citation to this spec
before either emit stage lands. The two `(save_key, container)` multisets
reconcile byte-for-byte at emit time; divergence is a verifier failure
settled toward this census, never a silent second derivation. Scene-level
geometry is unchanged: transforms/chapter attribution stay with the scenes
dataset (P5-gated), as above.

Findings this table pins:

1. **21 of 23 registry keys have measured pickups.** Missing from C2:
   `mtad2` (community: kitchen side table) and `mtacore` (community: Core
   computer "Get FlashDrive") — both present in C1, neither carried by any
   FlashTaker dump (R3).
2. **The pickup namespace ≠ the gallery namespace for base Mita.** C1 and C2
   carry `mta`, but DS-1's registry (`level2/MenuPersonage.txt`) has *empty*
   `nameSave` for `MitaUsual`/`MitaTrue` (DS1-CONTRACT nullability note).
   Joins therefore go through the C1 literal + C13 anchors, never through an
   assumed `nameSave` equality.
3. **Container ≠ chapter.** Carriers span levels 8–21; per DS-3 §3.6 the
   story binding is `levelN ↔ Location(N−2)` `[inferred]`. Community chapter
   attributions (D1 §3) never enter rows (§8-R5).
4. **The gallery IS the cartridge album.** Menu labels live at `Menu.jsonl`
   lines 61–62 ("Characters - Cartridges", "Cartridges"), and menu buttons
   call `MenuPersonage.OpenPersonage("<save_key>")` with cartridge keys —
   measured: `level2/ButtonMouseClick_#2179.txt` passes `"mtad2"`. The
   display-name join rides DS-1 rows; cartridges add no name column of their
   own.

### 3.2 Minigames: four registries, one kind

Measured client evidence groups into four registry shapes — all owned here as
one `minigame` kind keyed by their distinct client identifiers:

1. **Resources-loaded prefabs via `MinigamesAutomate`** (C7): `Minigame
   CarSpace`, `Minigame MakeManeken`, plus scene-load `MinigameShooter`
   (whose `Shooter_Main` script lives in `level23.xml` — a dedicated scene).
2. **TV console games** (C5): entries `Fight` and `Pinguin`, named by
   `indexStringNameGame` into the `TelevisionGames` category (§5 pin).
3. **Scene-carrier classes** (C10): `Location4TableCardGame(_Card/_CardHold/
   _CardMemory)` @level6 · `Location7_GameDance(_Music/_Music_Note/_Sphere)`
   + `Location7_HammerButton(_Animations)` @level9 · `Location14_PCSnaker`
   @level16 · `Location17_PumpkinClicker` @level19 · `GamesCore_Main(
   _Folder/_Sphere)/GamesCore_InputField*` @level15+level17 · `MenuMitaDance`
   @level2 · `TetrisGame/TetrisFrog/TetrisSpriteAnimation` @levels 3–22
   (broad import — carrier breadth recorded, not over-read).
4. **Tamagotchi-phone activities** (C10, level3 only):
   `TamagotchiGame_Cooking(_Food)`, `_FindFurniture(_Object)`, `_HelpTrash`,
   `_Sorting(_Item/_ItemAnimation)`, `_Chip(_Case/_Plita)` — the in-fiction
   phone-sim loop (86 `*tamagotchi*` dumps in level3), Peaceful-Mode-adjacent
   present-but-unreachable content captured under SPEC COMP-J11 posture.

That is **17 measured surfaces** (3 prefab/scene + 2 TV + 8 carrier-class +
4 tamagotchi activity families: Cooking, FindFurniture, HelpTrash, Sorting).
The emit pass re-sweeps all 51 containers before the count freezes; D1 §4's
community table (~17,
names like "Hetoor"/"Spaceracer"/"DDR") is an alias source only — no such
string exists anywhere in the client (grep over C1 + C9 returned nothing),
so community names never become keys (AC-8).

### 3.3 Achievement & outfit hooks (already-built datasets this dataset fills)

- `achievements.jsonl` (C11) leaves `joins.minigame_id` null on all 8
  `type_tag:"minigame"` rows: `ACHI_PinguinTusim`, `ACHI_tetro`,
  `ACHI_racingfirst`, `ACHI_applesnake`, `ACHI_logA`, `ACHI_logB`,
  `ACHI_hellwin`, `ACHI_hellmegawin` — plus `ACHI_greatdance` tagged `story`
  but granted inside the dance location (C12: `level9/Dialogue_3DText_
  #13057.txt`). This dataset emits the edges; it does not mutate DS-2 files.
- Outfit unlocks ride `Achievement_cloth.ClothCompleted(string _nameCloth)`
  (C14) — already materialized for School/Christmas in
  `relink-outfit-cloth-site.jsonl`; Pumpkin/Vampire and Penguin-Piles/
  Christmas links land here as minigame→outfit edges.
- Collectible set: `ACHI_cartridgeplayers` → `collectible_set:
  "player-cartridges"` (C11) joins the 10 player-cartridge rows.

### 3.5 Non-entity infrastructure (never rows)

`MinigamesController` (per-scene render/fog/camera chrome), `MinigamesFast
Menu(_Case/_CaseMouse)` (pause menu), `MinigamesSettings` (post-processing),
`MinigamesTelevisionGame` runtime shell (C8) are presentation plumbing.
Caveat for the sweep: hashing all 48 `MinigamesController.txt` dumps yields
exactly **4 content groups (19/16/12/1)** — boilerplate dominates, and
`level2`'s hash is shared by 12 members, so it is not a lone real-value
outlier; identical hashes collapse to one logical instance per group (R4,
asserted mechanically by AC-7).

## 5. Locale plan

Pointer columns, not copies — DS-1 §4.1's ruling applies unchanged, and the
measured parity supports it: `MiniGame CarSpace` 8 lines ×34 locales,
`MiniGame Shooter` 10 ×34, `TelevisionGames` 2 ×34, `MiniGame MakeManeken`
35 lines in 33 locales and **34 in Arabic** (the sole skew; counted this
pass over `extracted/localization/*/`). Per-locale availability derives from
category presence + line coverage, fed by
`localization/_ledger/locale-delta.jsonl` — never hardcoded; the Arabic
MakeManeken cell renders the declared explicit-filler state for its missing
row (SPEC §Locale strategy filler policy).

**TelevisionGames offset pin (binding, mirrors DS-1 R2's discipline).** C5's
`indexStringNameGame` values are 1 and 2 while the category spans lines 0–1.
Names resolve under `GetString("TelevisionGames", indexStringNameGame − 1)`:
`Fight → line 0 "Dairy Scandal"`, `Pinguin → line 1 "Penguin Piles"`. The
identity hypothesis is rejected on semantics (it would name the fight-styled
entry "Penguin Piles") exactly like DS-1's clothes off-by-one; the pin lives
in the file `_meta` and README, and AC-4 makes a verifier recompute both.

## 7. Stub-first plan (evidence-tier ladder)

1. `registered-pickup` — in C1 **and** has a C2 carrier (21 cartridge rows):
   full record.
2. `registered-unresolved-pickup` — in C1, no carrier yet (`mtad2`,
   `mtacore`): full identity row, `pickup_ref: null`,
   `missing_fields: ["pickup_ref"]`, unblock named (R3 sweep).
3. Candidate minigame surfaces — class evidence without a loader/name row
   (e.g. `Metroidvania_Interactive.cs` if the sweep finds no scene use):
   candidates ledger only, `evidence: [{path, locator}]`.
4. Wiki-only minigame claims (D1 §4 rows whose client surface the sweep
   cannot find — e.g. the patch-note-only Tetris variant framing): **no row,
   no candidate**; noted in README against the research citation, per the
   no-fan-lore non-goal (SPEC §Non-goals).

Every non-full row carries `missing_fields: [...]` so missingdata.md
generates mechanically.
