## 0. Sequencing law — why a data-side module gates everything

A viewer built on today's artifacts renders nothing: `markers.jsonl` ships
**zero** marker rows (one `_meta` line, `row_count: 0`, four families
deferred under the no-orphan rule) and **zero** of the 986 `poi.jsonl` rows
project a coordinate — the census is inline 298 · pptr-unresolved 76 ·
none 612, and every inline cell fails the projection conjunction except
world-assumed, which exists only on the 20 story-scene `spawn` fields
(`extracted/data/scenes/scenes.jsonl`). "Markers v0 exists" means the
*schema and projection rule* exist; the data does not.

Therefore this piece opens with **M0 — marker/position emission**, a
data-side module with its own acceptance criteria ([§3](#3-m0--markerposition-emission-data-side-gating-module)).
No viewer module ships behind it; dependency edges are explicit in
[§2](#2-module-breakdown--dependency-edges). Frontend consumes emitted
artifacts and never derives data ([AGENTS rule 8](
../../../AGENTS.md)).

### 0.3 Correction: POI rows are ALREADY per-instance

The Scout's §1.2 premise — "row identity is per class per level … 41
ObjectInteractive instances in level13 share `level13:ObjectInteractive`" —
is **wrong**, and so is the brief's framing of M0(b) as an aggregate→instance
*expansion*. Measured:

- All 986 `poi_id` values are unique; **790 of 986 carry a `_#<pathID>`
  instance suffix** (`level9:Trigger_Teleport_#10938` — exactly the shape
  dataset-scenes §3.3 planned). 196 `(level,class)` pairs exist; 116 pairs
  have >1 row (level13 ObjectInteractive: **36 distinct rows**,
  `level13:ObjectInteractive`, `level13:ObjectInteractive_#13009`, …).
- A class-in-level's *first* instance keeps the bare `level:class` id —
  which is what made every pair look aggregated on a uniqueness-only check.
- Single-instance classes (`Scene_Load` ×19, `FlashTaker` per level,
  `Basement_Safe` ×2) genuinely have one row because there is one dump.

Consequence: **per-instance pins need no emitter expansion.** What M0(b)
must do instead is pin down the instance-identity contract for markers
([§3.2](#32-work-items)) and add the one genuinely missing schema piece:
profile-document markers, whose placements live in DS-5 columns rather than
in any `poi.jsonl` row, need a marker shape keyed by `placement`
provenance instead of `poi_id`.

In scope:

1. **Data side (M0):** marker-projection rerun over the landed DS-4/DS-5
   owners; S9 disposition accounting for the 76 pptr rows; per-instance +

enumeration (SCN-6), UGC pins/notes/trackers, embed bundle, distance tools,
tile layers, live tracking (Scout §3.2 avoid rulings all stand).

## 3. M0 — marker/position emission (data-side gating module)

Owner: data-side builder (B-6 lineage), same-commit entrypoint discipline
per [DR-2026-08-18-pipeline]. Regeneration stays byte-stable (AC S8
pattern). PIPE stage registration of emitters is XC-6 — out of scope here
but the rerun must be runnable through `run_all` once registered.

### 3.1 Emission law (unchanged, restated as the fence)

Markers exist ONLY for entities confirmed by their owning dataset's emitted
file, and every *placed* confirmed entity carries ≥1 marker
([site-scaffold §7](site-scaffold.mdx#7-map-module-contract)). A marker
without coordinates renders as a visible-locked cell on the authored
schematic — never at a faked spot (dataset-scenes §3.5, TOOLS §3.3
checkerboard-void discipline).

### 3.2 Work items

**(a) Resolve-or-defer-with-reasons the 76 pptr-unresolved positions —
PIPE S9 named.** Each of the 76 rows (MitaAIMovePoint 25, FlashTaker 19,
Trigger_DistanceCircle 18, Trigger_Teleport 14) ends the rerun in exactly
one of two states, recorded in `_meta.position_dispositions`:

- `resolved-by-s9`: the S9 `scene-transform` UnityPy walk
  (dataset-scenes §6; missingdata XC-3) resolved the row's `position.target`
  PPtr → row re-emits `source:"inline"` with a calibrated `space`
  (`world-assumed` or a newly ruled space), floats filled, `space`
  provenance noted per class against `World.positionSpawn`;
- `deferred:s9-not-run` / `deferred:<reason>`: unchanged row + reason code.

No third state may exist. If S9 has not run when M0 lands, all 76 defer
under `deferred:s9-not-run` and the viewer still ships — M0's coordinate
yield is *not* its shipping gate; its honesty ledger *is*.

**(b) Per-instance pin contract (verification, not expansion).**

- Every marker row keys a distinct `poi_id` (opaque to the frontend;
  corpus-verbatim, bare-first-instance form preserved — no normalization
  without an owner ruling, [OQ-1](#14-open-questions-for-the-arbiter)).
- Where identical-hash template dumps collapsed to one logical instance
  (DS-4 §3.5/§8-R4 boilerplate rule, e.g. `MinigamesController` groups),
  the marker row carries `instance_census` so a count shown to a user is
  never silently one-of-N.
- New schema piece — **profile-placement markers**: rows keyed by
  `placement_source: "DS-5"` + `document_id`, carrying `placement`
  verbatim (`carrier_class`, `component_path_id`, `container`) instead of
  `poi_id`. They render at scene granularity (list-chip + scene-level
  presence) until S9 resolves their carrier transforms into pins.
- `PoiRow.position.points[]` stays in the site contract
  (`site/src/data/contracts.ts`) for Transform_Position point sets; the
  frontend never iterates it for plotting (parent-local/unknown spaces are
  non-projecting).

**(c) Marker-projection rerun over landed owners.**

- `cartridge_item` family: join `poi.jsonl FlashTaker rows (21,
  via joins.save_key)` ⇄ `cartridges.jsonl (23 rows)`. Yield: **21 marker
  rows**. `mtad2`/`mtacore` (registered-unresolved-pickup, no proven
  container) get **no** marker; they are accounted in `_meta.unplaced`
  with reason codes ([OQ-9](#14-open-questions-for-the-arbiter)). The 4
  pet-cartridge POI rows stay deferred (no owning row — [OQ-8](#14-open-questions-for-the-arbiter)).
- `profile_document` family: emit from DS-5 `placement` — **≤11 rows**
  (11 of 14 documents carry placement). Join audit: every emitted slug
  resolves to exactly one `document_id`.
- `monster_anomaly` (96 rows) and `save_point` (19 `Scene_Load` rows):
  stay deferred — owning entity datasets still don't exist
  (missingdata XC-5, SCN-1).
- Optional in the same rerun if the Arbiter approves
  ([OQ-7](#14-open-questions-for-the-arbiter)): `minigame_access` family —
  both sides exist (`minigames.jsonl` 17 rows + `minigame--scene-carrier`
  76 edges), so no-orphan is satisfiable today.
- **Make the `_meta` family ledger total:** v0 lists 4 families but 709
  eligible rows span kinds (`interactable`, `move_point`, `spawn_event`,
  `safe`, `minigame_access`) that no family names. The rerun's
  `pending_families` must enumerate every `marker_eligible:true` kind with
  its deferral reason and unblock owner — counts pinned, never dropped
  (SCN-6 pattern).

**(d) Registry v2** (`emit-artifacts.mjs` §"map registry + markers" →
`public/map/registry.json`): per scene keep `bounds: null` until S9/P5
calibration writes real ones (null is the honest value; never a bounding

### 4.1 Marker row v2 (emitted shape)

```jsonc
{
  "marker_id": "level9:cartridge:mtacap",
  "poi_id": "level9:Trigger_Teleport_#10938",   // instance anchor; null for profile-placement rows
  "layer": "location-scenes/Location7",
  "kind": "cartridge",                           // poi-kind vocabulary (chip/filter axis)
  "entity_kind": "cartridges",                   // ROUTED segment == ENTITY_KINDS key

  "icon": { "source": null, "fallback_state": "named-explicit-missing" },
  "position": {
    "x": null, "y": null, "z": null,
    "status": "awaiting-transform-stage",        // "projected" | "awaiting-transform-stage" | "scene-granular"
    "target": { "kind": "GameObject", "path_id": 1208 }
  },

    "mechanism": "hard",                         // hard | logic | inferred (relink vocabulary)

    "scene_binding": "level9"
  },
  "links": {

```

The namespace split resolves Scout OQ-4: `kind` stays the marker/poi
vocabulary; `entity_kind`/`entity_slug` switch to the routed registry
(`ENTITY_KINDS` key + id column: `cartridges`/`cartridge_id`,
`profiles`/`document_id`, …). The **emitter** writes final
`page_url`/`focus_url` segments so the frontend formats, never maps,
vocabularies. `markers.jsonl._meta.focus_url_contract` updates to match
(`cartridge_item` → `cartridges`).

### 4.2 Projection law (unchanged)

`projectedCoordinates()` remains the only path from a placement row to
plotted pixels; `position.status === "projected"` in a marker row must
agree with it, and a disagreement fails the render test (AC MV-2). Plotted
pins therefore appear the moment S9 lands coordinates even while
`bounds` are still null: CRS.Simple plots raw world coords; fit-to-bounds
activates only when the registry carries bounds, and until then the default
view centers deterministically on the mean of the scene's plotted points
(presentation math over consumed rows — allowed; it derives no data).

| Entity confirmed but unplaced (`mtad2`, `mtacore`, 3 script-granted profiles) | entity page renders an unplaced well of equal height to a placed module — no absence sentence; `_meta.unplaced` carries the reason codes |
| Unnamed instances (CH-6) | class-preserving label via `desluggedLabel` of class/id; no invented proper nouns |
| Scene display names null (SCN-8: `display_name_loc` null ×24; chapters missing on 5 story levels) | filler chain per localization-architecture §5: localized chapter name → re-spaced `scene_id`; locale page never leaks another locale's text |
| Compromised/reachability-flagged entities (CAR-8 tamagotchi `present_but_unreachable`) | `CorruptionHover` + VHS-drift STATE treatment on the chip — horror register as state, matching `EntityShell compromised` semantics |
| Deferred families (monsters 96, save_point 19, pets 4) | stay invisible as pins; enumerated in `_meta` with owners; scene POI listing still shows them as counted rows |

## 9. Design language requirements

The viewer must feel like holding the game's spaces, not like atlas chrome
(Scout §3.2 "adopt" ruling; design-standard §5):

- Surfaces ride tier-1 tokens only (`site/src/styles/design/tokens.css`):
  `--ms-bg-0/1/2` plum stack, pill/panel/cell radius family, border via
  `color-mix` on `--ms-accent-soft`. **No uncited hex anywhere under
  `src/components` (AC-S8 defect class)** — kind-chip color axes derive
  from tier-1 rows via `color-mix` (accent / signal green / warm / danger)
  and are otherwise monochrome; a rainbow category palette like MapGenie's
  is off-soul anyway.
- Hot pink `--ms-accent` stays reserved for identity + actions (focused
  pin, active filter, primary popover link) — never a per-kind hue.
- Machine-voice data (counts, `awaiting-transform-stage`, buildId stamp)
  uses the LCD register (`--ms-font-lcd`, VT323 rung) on
  `[data-slot="lcd-terminal"]` surfaces with `ms-scan-breathe`;
  body labels use `--ms-font-sans` at ≥12 px (owner floor).
- Motion is state, not decoration: focused pin gets `ms-glow-pulse`;
  compromised-entity chips get `ms-vhs-drift` (CorruptionHover pairing);
  everything honors `prefers-reduced-motion` (all three loops are already
  gated in tokens.css).
- Hover does work everywhere (design-standard §5.3): filter chip hover
  highlights its pins; pin hover highlights its chip; popover fields carry
  provenance hovers. Tint-only hover fails review.
- Controls use the pill grammar (`GradientPill`/`PillButton` lineage);
  empty wells are `VoidWell` checkerboard, never captions.

## 12. Acceptance criteria

Proof methods are named per criterion; "scripted trace" = the
check-cwv-style scripted browser runner; "static grep" = CI HTML assertion
in the pattern of the negative-map gate.

### 12.1 M0 acceptance criteria

- **AC MV-0.1 — Rerun yields entity-backed markers.** `markers.jsonl`
  ships >0 data rows; every row joins to exactly one owning-dataset row
  (21 cartridge via `save_key`; ≤11 profile via DS-5 placement); a
  fabricated slug injected into the join audit fails loudly. *Proof:*
  emitter unit test + join-audit script diffing emitted rows against
  `cartridges.jsonl` / `profile_documents.jsonl` id sets.
- **AC MV-0.2 — Disposition axis total for the 76.** Each of the 76
  pptr-unresolved rows ends `resolved-by-s9` or `deferred:<reason>`;
  `_meta.position_dispositions` reconciles exactly with a row recount;
  no third state. *Proof: recount script over `poi.jsonl` vs `_meta`.*
- **AC MV-0.3 — Instance identity preserved.** Marker `poi_id`s are
  unique and corpus-verbatim; template-collapsed carriers carry
  `instance_census`; profile rows carry `placement` verbatim. *Proof:*
  schema test asserting uniqueness + required-field matrix over the full
  file (not sampled).
- **AC MV-0.4 — Family ledger total.** `_meta.pending_families` names
  every `marker_eligible:true` kind with deferral reason + unblock owner;
  eligible-row arithmetic (709) reconciles against families + emitted
  rows. *Proof: ledger-arithmetic unit test.*
- **AC MV-0.5 — Byte-stable rerun.** Two consecutive emissions are
  byte-identical (fixed ordering, single build stamp). *Proof:* double-run
  hash compare (AC S8 pattern).

### 12.2 Viewer acceptance criteria

- **AC MV-1 — Rendered equals projected.** For every scene, plotted-pin +
  locked-cell + list-chip counts equal the marker rows' disposition
  counts; a PENDING-disposition row never plots. Extends the AC S7
  projection tests over the full source×space axis. *Proof: component
  test.*
- **AC MV-2 — Status/projection agreement.** A marker row with
  `status:"projected"` whose floats fail `projectedCoordinates()` (or the
  inverse) fails the build-time fixture test. *Proof: fixture test.*
- **AC MV-3 — Deep-link round trip.** Cold load of
  `/map?focus=cartridges:mtal&scene=level10&kinds=cartridge` restores
  scene, filter, and focus (v0 restored focus only); discrete clicks
  update the URL without navigation; back/forward behaves per
  [OQ-5](#14-open-questions-for-the-arbiter) ruling. *Proof: scripted
  trace asserting DOM + history entries.*
- **AC MV-4 — SSR link graph.** Every cartridge/profile/minigame/mita
  page with placement data serves SSR HTML containing its
  `/map?focus=…` anchor; every marker popover target is a crawlable
  `<a href>` present in served HTML. *Proof: static grep in CI.*
- **AC MV-5 — Switcher totality + i18n.** All 24 scenes listed with
  non-null labels under the filler chain in every shipped locale; chrome
  parity green. *Proof: chrome-parity run + registry-driven snapshot
  test.*
- **AC MV-6 — Zero external requests.** No network request leaves the
  origin from any map interaction. *Proof: request-log assertion in the
  scripted trace.*
- **AC MV-7 — Mobile.** At 375 px: all controls reachable with ≥44 px
  targets, pinch zooms, popover renders as side sheet, no horizontal
  overflow. *Proof: scripted mobile trace + screenshot.*
- **AC MV-8 — Budget/bundle gates.** CWV `map-shell` budgets green;
  Leaflet absent from non-map route bundles; CLS < 0.1 across
  awaiting-artwork → ready transition. *Proof: check-cwv.mjs + bundle
  assert.*
- **AC MV-9 — Negative gate intact.** `check-no-third-party-maps.mjs`
  passes and its blocklist still trips on a canary string. *Proof: gate
  self-test.*

## 14. Open questions for the Arbiter

Carried from the Scout with recommendations; new ones marked.

- **OQ-1 (reframed by measurement) — instance identity.** The Scout's
  expansion question is moot: `poi.jsonl` is already per-instance
  (790/986 suffixed ids). Remaining call: may markers reference the
  bare-id *first* instance form (`level13:ObjectInteractive`) or must the
  emitter normalize all ids to suffixed form? **Recommend: keep
  corpus-verbatim ids; treat `poi_id` as opaque at the frontend.**
- **OQ-2 — scene artwork.** Author, format (recommend SVG schematics for
  zoom weight + text-free labelling), file contract
  `public/map/<scene_id>/base.svg` (+ optional `meta.json` overlay
  anchors), and progressive ship vs block. **Recommend: progressive —
  grid fallback is already honest; nothing blocks.**
- **OQ-3 — monster/save_point families.** Wait for owning entity
  datasets (strict no-orphan) or ship scene-presence chips labeled
  unslugged? **Recommend: wait** — the scene POI listing on
  `/locations/[scene_id]` gives counted coverage without minting orphan
  slugs (CH-6 forbids attributing unnamed instances anyway).
- **OQ-4 — focus-kind namespace.** Resolved in-spec ([§4.1](#41-marker-row-v2-emitted-shape)):
  routed `ENTITY_KINDS` key + id column, written by the emitter into
  `links.*`; `_meta.focus_url_contract` updated. **Confirm the contract
  edit is acceptable within the scenes spec's freeze discipline.**
- **OQ-5 — history API.** **Recommend: `replaceState` for filter toggles
  and focus changes (typing-law), `pushState` on scene change so Back
  walks the scene trail.** Needs one ruling since v0 used replaceState
  for focus.
- **OQ-6 — bounds timing.** Confirm spawn-only mode (raw-coords plotting,
  mean-center fallback, fit-to-bounds when known) is acceptable for v1 if
  S9/P5 calibration slips. **Recommend: yes; viewer accepts null bounds
  indefinitely.**
- **OQ-7 (new) — include `minigame_access` in the same rerun?** Both
  owning sides exist (17 minigames; 76 carrier edges). **Recommend:
  include** — cheapest coverage win, no-orphan satisfied; else it becomes
  the first post-M0 delta.
- **OQ-8 (new) — pet cartridges.** 4 POI rows (`TamagotchiGame_Cartridge`
  family) have kind `cartridge` but no DS-4 row. Owner ruling needed:
  extend DS-4 with tamagotchi rows, re-rule their kind, or ledger them
  deferred. **Recommend: defer with reason until a ruling lands.**
- **OQ-9 (new) — unplaced confirmed entities.** `mtad2`/`mtacore` +
  3 script-granted profiles are confirmed-but-unplaced. Spec excludes
  them from markers with `_meta.unplaced` accounting + honest wells.
  **Confirm exclusion** (alternative: infer container from
  `container_location_binding` — rejected here: `[inferred]` mechanism on
  a spatial claim is a faked spot).
- **OQ-10 (new) — kind-chip color axis.** Token law bans uncited hex;
  chips derive hues via `color-mix` from tier-1 rows only. **Confirm the
  derived-axis palette** (or commission a T2-sampled extension row set
  before implementation).
