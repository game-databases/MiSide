**Decompile-depth caveat that shapes everything below.** The
`decompiled/main/**` trees are ilspycmd 11.0.0.9335 output over Il2CppDumper
DummyDlls: **signatures, field offsets, and tokens are real; method bodies
are empty** (`AchievementsController.cs:68-71` — `MoveNext()` returns
`default`). Every claim below is therefore classed by what it actually
proves:

- **[proven-hard]** — serialized in a dump we hold (UnityEvent persistent
  calls, flag tables, field values). Reproducible byte-level evidence.
- **[proven-structure]** — class/field/method exists with pinned
  `dump.cs` line, token, or offset.
- **[unverified-behavior]** — requires IL2CPP *native* method bodies
  (numeric constants, condition order). Not provable from metadata; needs a
  future native-decompile pass or gameplay capture.
- **[community]** — wiki/guide attribution carried as labeled context,
  never as evidence.

## Part A — Achievements

### A.1 Corpus reality (measured 2026-08-25)

1. **The registry is one MonoBehaviour**: `DataAchievements` in
   `resources.assets` holds `DataAchievementsValues[26]`
   ([DataAchievements.txt](../../extracted/harvest/mb-dump/resources.assets/DataAchievements.txt),
   `int size = 26`). Each entry has exactly the three join keys plus one
   state bool — field truth at
   [DataAchievementsValues.cs](../../extracted/decompiled/main/Assembly-CSharp/DataAchievementsValues.cs):
   `steamAchievement:string` (0x10), `icon:PPtr<Sprite>` (0x18),
   `lineTranslate:int` (0x20), `[HideInInspector] get:bool` (0x24).
2. **Count reconcile: dump 26 = store 26 = wiki 26** — the research §5
   triple-verified total survives contact with ground truth *unchanged*
   (`achievements.total=26`, Steam stats page, D1 §5). No drift to report;
   AC-A1 pins it anyway because patches add achievements.
3. **Names live in loc, not code**: `lineTranslate` is the 0-based index
   into `Data/Languages/<locale>/Achievements.txt` via the proven loader
   authority `GlobalLanguage.GetString(name, index)`
   ([E1 step 7](../research/explorer-e1-hands-on.mdx#step-7--dumpcs-recon-works)).
   Measured parity: **all 34 locales carry exactly 26 lines** in
   `extracted/localization/<locale>/Achievements.jsonl` (loop-checked this
   pass) — zero locale skew on this category, so every achievement page can
   ship fully localized names from day one. The client carries **names
   only** — no description strings exist in any loc category → descriptions
   are an external-surface join (A.5).
4. **Unlock triggers are partially serialized.** Scanning every dump for
   persistent calls into the trigger classes found **13 sites**: 11 ×
   `Achievement_function.AchievementGet(string)` with the `ACHI_*` id as
   the string argument, 2 × `Achievement_cloth.ClothCompleted(string)`
   with outfit ids. Full site list with args in the table at A.2. Trigger
   classes:
   [Achievement_function.cs](../../extracted/decompiled/main/Assembly-CSharp/Achievement_function.cs)
   (`AchievementComplete(int x)` 0x60000F2 / `AchievementGet(string)`
   0x60000F3),
   [Achievement_cloth.cs](../../extracted/decompiled/main/Assembly-CSharp/Achievement_cloth.cs)
   (`ClothCompleted`/`ClothQuietCompleted`),
   [AchievementsController.cs](../../extracted/decompiled/main/Assembly-CSharp/AchievementsController.cs)
   (`dataAchievements` array @0x18, `AchievementCompleted(string)`,
   `ClearAllAchievements()`, `ProgressAchievementString()`,
   coroutine `CheckAchievementsSteam()` — the Steam sync pump).
5. **`get` bools are polluted state** (residue R-E1-2,
   [PROOF.md §3](../../extracted/PROOF.md)): entries `[0]` and `[3]`
   serialize `get = True` in the shipped asset — someone's editor-session
   unlock baked into the prefab defaults. They must never render as
   unlock state or rarity signal.
6. **Icons are NOT yet exported.** All 26 icon PPtrs point into
   `resources.assets` (m_FileID 0), pathIDs **862–910**; the art-export
   stage's `container-2d/resources.assets/` set contains no object with
   any of those pathIDs (checked `_#862…_#910` patterns this pass — zero
   hits). The sprite objects exist in the container but were not in the
   exported slice → a targeted re-export pass is required (AC-A5).
7. **Steam side is keyless-reachable**: global unlock % per achievement
   from the community stats page (rarest "Pro Gamer" 10.5%, most common
   "Creak in the Dark" 86.4%, D1 §5); localized *descriptions* would need
   the keyed schema endpoint — out of scope until per-site graduation
   (spec non-goal).

### A.4 Joins (characters/scenes and beyond)

- **Endings** — `ACHI_final`/`ACHI_safelife`/`ACHI_none` are the three
  ending anchors (Part B owns the edge).
- **Minigames** — award sites sit inside minigame scenes (`Penguin

- **Outfits** — the two `ClothCompleted` sites give outfit unlocks the same

- **Characters/scenes** — award sites carry their scene homes:
  prayer-room keyboard (`Location11_PrayerRoom`, level13 → "O, Great
  Mita!" matches the wiki's Discord-keyboard trivia), missing-assets door
  (`ObjectInteractive`, level14 → "Some Achievement?"), fight/dance rooms

- **Collectible sets** — "Caught Them All"/"Hi, Mita" join the cartridge
  and profile datasets as set-completion targets; the completion predicate
  itself is code-body [unverified-behavior].

### A.5 Completeness risks

1. **15/26 predicates need native bodies** — biggest honest gap. Options:
   native decompile pass (Il2CppDumper `script.json` addresses + Ghidra)
   or accept `unverified-behavior` with community gloss. Decision deferred
   to owner (cost/benefit); the schema already carries the split.
2. **Icon bytes missing from exports** (pathIDs 862–910) — fixable now
   with one filtered AssetStudioMod pass; without it, no achievement page
   has its art and OG cards fall back to non-entity art.
3. **Descriptions are EN-only forever (keyless)**; localized descriptions
   would require keyed endpoints — record as a deliberate hole, not an
   oversight.
4. **`get` bool pollution** — quarantined by `get_bool_trusted:false`.
5. **Steam % drift** — ephemeral plane; history policy per spec live block
   if we ever chart it.
6. **Patch sensitivity** — new achievements change array size and shift
   nothing else (indices are stable append-only so far, [inferred]); AC-A1
   makes any movement loud.

### A.6 Curated output format proposal

- Site plane: one page per achievement (26 pages, all-locale titles from
  game strings), card-grid index filtered by `type_tag`; global-% shown as
  a rarity band, never a leaderboard; award-site evidence rendered as a
  "where the game grants this" module linking the scene/entity page.
- Machine plane: static JSON per seo-standard §9 —
  `/api/achievements.json` mirroring the dataset verbatim.
- Tracker surface (site-section #8): checklists keyed by `achievement_id`;
  collectible-set trackers consume `collectible_set→members` index.

### A.8 Acceptance criteria (Achievements)

- **AC-A1 Count reconciliation**: emitted rows == `DataAchievements`
  array size == per-locale `Achievements.jsonl` line count (each of 34
  locales) == 26; any disagreement FAIL-FASTs the emit.
- **AC-A2 Three-way join completeness**: every row has non-null
  `steam_api_name`, `icon.path_id`, `line_translate`; name resolution via
  `GetString("Achievements", line_translate)` succeeds in all 34 locales
  with an availability-ledger row each.
- **AC-A3 Award-site sweep reproducibility**: scanning all 51 containers
  for persistent calls into `Achievement_function`/`Achievement_cloth`
  resolves exactly 13 sites whose string args match the A.2 table
  byte-for-byte on buildId 19029065; unresolved or extra sites FAIL.
- **AC-A4 Evidence discipline**: no row claims `proven-hard` without a
  resolvable cite (mb-dump path + pathID, or dump.cs line); automated
  lint verifies every `evidence[]` entry exists on disk;
  `ACHI_safelife.predicate_status == "unverified-behavior"` asserted
  explicitly.
- **AC-A5 Icon export closure**: after the art pass, all 26 pathIDs
  resolve to exported png bytes, or carry an explicit MISSING row in the
  media catalogue — zero silent gaps.
- **AC-A6 Steam cross-ref shape**: one canonical row per achievement;
  name mismatch between Steam and in-game loc renders as a flagged
  discrepancy (both strings kept, in-game wins display); % values never
  appear in user-facing HTML without their coverage label.
- **AC-A7 `get` quarantine**: `serialized_get_bool` recorded for all 26
  (expected True exactly at indices 0 and 3 on this build) and
  `get_bool_trusted` false everywhere; no renderer reads it.
- **AC-A8 Stub validity**: the stub validates against the schema draft
  and round-trips (read→emit is byte-stable).

### B.3 Grounding rules

- Every `evidence[]` value is a cite in one of three grammars:
  repo path (+ optional `:line` — a FILE line number), mb-dump
  container/file (+ pathID), loc category + explicit `#line_index=<n>`
  (0-based pointer into the jsonl record sequence). A loc row is **never**
  cited with a bare `path:N` colon form: that parses as a file line and
  binds record `line_index = N−1` (e.g. `Menu.jsonl:130` resolves to
  line_index 129 — an empty string — while "Peaceful Mode" sits at
  `Menu.jsonl#line_index=130`). Lore prose is structurally impossible in evidence fields;
  wiki content may appear only in `*_community`/`attribution` fields.
- Edge truth = the serialized PersistentCall (target pathID + assembly-
  qualified type + method name + ArgumentCache). We do not guess what a
  method "means"; effect_class labels are curated annotations, kept apart
  from the cite.
- Numeric constants (17%/98% windows, password compare, condition
  ordering) are unreachable from metadata — always
  `unverified-behavior` unless a future native-body pass proves them.
- Level↔chapter mapping stays open (spec gap 1 / P5 successor); until it
  lands, chapter numbers are `[community]` labels on nodes, never stored
  in `chapter_attribution` as data.

### B.4 Joins

- **achievements** — `ending_id ↔ achievement_id` both directions
  (`ACHI_*` rows in Part A carry `joins.ending_id`).
- **characters/mita_variant** — award chains and DialogueChanger prompts
  resolve their GameObject graphs to scene residents (`MitaPerson`,
  `Character_Look` targets appear inside edge chains already — e.g.
  level5 case calls `MitaPerson.FaceEmotion("smile")`); feeds Mita pages'
  "choices that change her" modules.
- **location_scene / chapter** — node `container` is the scene key; joins
  deepen automatically when the levelN↔chapter map closes.
- **game_mode** — Peaceful Mode stub row keyed `mode_id:"peaceful"`
  (COMP J11), fed by Menu loc + `showHintPeacemode`.
- **minigames/outfits** — choice nodes that gate outfits (cloth award
  sites sit inside option chains) join Part A's outfit ids.

### B.5 Completeness risks

1. **Body-dependent semantics** — negative-condition evaluation, window
   percentages, `MitaClickSafe` internals: unverified-behavior until a
   native pass. The explorer must render these as "condition tracked by
   the game here" with the cite, never as guaranteed mechanics.
2. **Edge completeness is bounded by serialization** — choices routed
   purely through code (no UnityEvent) are invisible to us today; the 13
   DialogueChanger + ObjectInteractive census is a floor, not a ceiling.
   Cross-check against the 6 community-documented choices and expand.
3. **Cyclic-typetree residue (I-S4)** — truncated nested tails exist in
   dev-console components only (bounded loss, PROOF.md §3); none observed
   in ending/choice components, but the emit should assert call-list
   integrity (non-zero m_Calls where m_Target pathID ≠ 0).
4. **TimelineAsset name collision** — a filename-based census of
   "MenuEnding" returns 46 same-name dumps: 45 TimelineAsset collisions
   plus the one real level2 component; type-aware filtering is mandatory.
5. **Peaceful Mode flux** — the locked stub will become a real mode in a
   patch; every stub row carries buildId so the diff is mechanical.
6. **Demo boundary** — demo 2527520 ends exactly at the wardrobe choice;
   a future diff pass would isolate the choice subtree cleanly (deferred,
   DAQ).

- **Ending explorer tool** (spec tools lane; COMP J1 moat): consumes

## Shared conventions (both datasets)

- **Staleness**: every row carries `build_id` (per-record model, spec
  automation block); appmanifest watch re-runs the sweep and diffs.
- **Locale**: names ride the proven category+lineIndex authority; the
  Achievements category is currently skew-free across 34 locales — AC-A1
  keeps that a checked invariant instead of an assumption.
- **Provenance**: two-class rule — user-facing surfaces show buildId +
  coverage only; source identities stay repo-side.
- **Indexes**: reverse indexes emitted per pair per doctrine Principle
  one; `achievement→award_site` and `ending←branch_edge` are launch
  members of the relink matrix.
- **Commit plan**: schema drafts + stubs land together as one commit per
  dataset (AGENTS rule 5), after verifier review of this spec.
