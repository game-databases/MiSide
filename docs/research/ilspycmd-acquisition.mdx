**Channel (evidence).** The correct distribution channel is the **nuget
dotnet-tool package id `ilspycmd`** (not `ICSharpCode.ILSpyCmd` — that id
does not exist; flatcontainer returns BlobNotFound). The exact pinned
version **exists there**:
`api.nuget.org/v3-flatcontainer/ilspycmd/index.json` lists `11.0.0.9335-rc`
between `11.0.0.9223-preview1` and `11.0.0.9375`. Upstream GitHub release
[`v11.0-rc`](https://api.github.com/repos/icsharpcode/ILSpy/releases) ships
GUI-only assets (the spec-pinned `ILSpy_windows_selfcontained_11.0.0.9335-rc-x64.zip`
among them) — **no CLI asset exists upstream**, re-confirming I-4's root
cause: the pin text named a channel that never contained a CLI.

**Package facts.** nupkg `ilspycmd.11.0.0.9335-rc.nupkg`, 4,741,133 B,
sha256 `9e336464fb5554cf1ed1ac50bb41db2ce369ad875670b6024bc49123d063c816`.
Single TFM: `tools/net10.0/any/` — **net10.0 only**, no net8/net9 variant,
no apphost exe inside. Host reality: SDK 8.0.424 + NETCore 6–9 runtimes;

**Pipeline-resolution verdict.** Two findings for the fixer:

1. **Path resolution is now satisfied by files alone** — the mirror at
   step 4 hits `_ilspycmd()`'s first branch. But **runtime resolution is
   NOT satisfied**: S7 children inherit the driver env, which carries no
   `DOTNET_ROOT`, so every `ilspycmd.exe` spawn dies rc=150 ("You must
   install .NET"). Minimal fixer options: (a) export
   `DOTNET_ROOT=<workroot>\it1-dotnet10` when invoking `run_all` (works
   today, zero code change, must be documented as an entrypoint
   precondition), or (b) small code fix injecting that env var in the S7
   subprocess wrapper (preferred for AC-16 reproducibility).
2. **Staging-fallback hygiene:** `_ilspycmd()`'s unzip fallback globs
   `ILSpy_windows_selfcontained_*-x64.zip` and takes `zips[0]` — today that
   resolves to exactly one file (the correct GUI zip, which contains no CLI,
   so the fallback can never succeed by design). Not a live bug since the
   exe probe above short-circuits it, but at fix time tighten the glob to
   the exact filename or retire the branch entirely — the CLI no longer
   comes from any zip in that directory.
