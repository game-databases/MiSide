### M-1 · Disk-audit table misstates the scene count (rows-vs-lines slip)

Spec §0.1: "| Scenes | **25 rows** | `data/scenes/scenes.jsonl` |".

Disk evidence: `extracted/data/scenes/scenes.jsonl` first line carries
`"_meta":{…"schema":"miside.scenes.registry/1","row_count":24…}` —
**24 data rows**, 25 lines including the header; `docs/specs/data-contracts.mdx`
§3.9 independently pins "`scene` (24)". This is exactly the
rows-vs-lines class of error the spec itself polices two rows earlier when
correcting the scout's POI count (986 not 987). The table presents itself as
first-hand measured authority; a builder quoting it could mis-pin. Fix: "24
rows (+1 `_meta` header = 25 lines)". All neighboring rows verified exact
(see GOOD).

### M-3 · Pinned renderer property is false: stock `marked` does NOT escape HTML, and the no-JSX/no-HTML body law has no enforcing AC

Spec §2: "Article bodies stay JSX-free markdown inside `.mdx` files … no
React-runtime MDX toolchain". Spec §5: "Escape-by-default markdown
rendering keeps first-party authored HTML inert." and "Bodies contain **no
JSX, no HTML, no iframes**."

Disk evidence: `site/package.json` dependency table pins no markdown lib
today (verified), so `marked` will be added exactly as pinned — and
`marked` renders raw inline/block HTML passthrough by default; its
`sanitize` option was removed in v5+. The §5 escape claim is therefore a
property the pinned dep does not have, and the §5 law ("no JSX, no HTML")
has no enforcing criterion: C9 greps only third-party hosts, remote images,
and `<script>` — arbitrary injected HTML (e.g. `<img onerror=…>`) would
pass C9 while violating §5. Bodies are first-party repo prose, so exploit
surface is small, but the spec states an invariant the toolchain won't hold
by itself. Fix before CodeWriter: require M2 to reject/escape HTML + JSX
tokens during its lexer walk (the AST is already in-hand for TOC/word
counts), and fold "zero raw HTML/JSX tokens in bodies" into C9 (or a new
AC) with a seeded-violation proof.

### M-4 · V3 deterministic linking is unsound at three named edges (shared names, nameless rows, locale holes)

Spec §4 V3: "each listed entity's known name forms link occurrences in body
order, first occurrence only, in every locale version … identical across
locales by construction".

Disk evidence: (a) `mita-usual` ↔ `mita-true` deliberately share one display
string (`data-contracts.mdx` §3.1 `name_is_shared` anti-merge note: both
read Menu 83) — first-occurrence linking cannot decide which listed entity
owns the mention; (b) cartridge rows ship no client display name at all
(missingdata.md CAR-5: `name_loc:null`, pages compose `client_key` + cited
`community_alias`) — "known name" is undefined for 13+10 collection-guide
anchors; (c) names resolve per locale via loc pointers, and the corpus has
precedent for a name being absent/contentless in specific locales (MA-2
French 0-byte shell; CAR-9 Arabic tail skew) — the cross-locale-identical
guarantee needs a declared skip rule. None of these three is ruled on; the
law is mechanical only after they are. Fix: pin tie-break semantics
(first-listed wins / ambiguous name never links / nameless rows link zero
occurrences) and the per-locale empty-name behavior.

### M-5 · Seed guide "secrets compilation (world documents)" cannot satisfy the §4 link law — the 160 notes are unreachable by any routed kind

Spec §6.4: "secrets compilation (world documents)" listed as a seed guide;
§0.2: "all ten routed kinds already resolve through `ENTITY_KINDS`".

Disk evidence: `site/src/data/contracts.ts:358` — the routed kind for world
documents is `lore` with `filter: ["paper_part","novella_surface"]`, so
`kindIds("lore")` (which honors the filter, `contracts.ts:415–426`) yields
only the 6 non-note rows; no `ENTITY_KINDS` key resolves any of the 160
`family:"note"` rows. A secrets guide is precisely a notes guide; under
V1/V2 it cannot carry note-level entity links, and the spec never
acknowledges this. Fix: either scope the seed guide's link set to
profiles/lore/books rows explicitly, or record "routed kind for notes" as a
dataminer work item per AGENTS rule 8 instead of leaving the seed map
silently inexpressible.

### M-6 · Staleness model detects entity-row drift only — translated-file rot is invisible exactly when OQ-1 mass-produces translations

Spec §3.3 hashes referenced entity rows; nothing hashes article sources
per locale.

Disk evidence: registry row shape (§3.1) stores per-locale
path/title/description/word_count but no source hash;
`article_locales.jsonl` cells (§8.1) likewise. When a pivot EN body is
edited, every sibling translation becomes silently outdated with no flag —
and option C (or B) will multiply these files ×34. Cheap fix before
CodeWriter: store a `body_sha16` per admitted locale cell (hash of the
`.mdx` at admission time); emit prints `TRANSLATION-STALE:` when pivot hash
moves. Same machine-plane discipline as §3.3, one column.
