## Findings

### F1 — MEDIUM — the spec's own "corrected" slug example is false on disk

§3, Scout corrections: *"its slug example pair `mtad2 → mta-cap` should read
`mtacap → mta-cap`"*. Measured pairs this pass: save_key `mtacap` emits
`cartridge_id == "mtacap"` — the hyphen rule fires only at letter↔digit
boundaries and `mtacap` contains none; the actual boundary splits are
`mtad2 → mtad-2` and the whole plr family (`plr1a → plr-1-a` …
`plr1099 → plr-1099`). The spec repeats the scout's false example one sentence
after restating the rule that disproves it, in a section claiming "nothing
copied on faith". Slugs are the tracker's key vocabulary (O2 store keys,
`focus=cartridges:<slug>` URLs, entity hrefs), so a CodeWriter trusting the
prose example breaks lookups for that row. One-line fix: `mtacap → mtacap`.
Sibling defect (report onward, out of scope here): data-contracts §3.3 pins the
same false example (`mtacap`→`mta-cap`).

### F2 — MEDIUM — TR-A5 promises personalized checked-state in raw HTML, impossible under the static-export posture

§15 TR-A5: *"served HTML carries EVERY checklist row with correct checked-state
representation, no script required"*. State lives in localStorage (T1); the site
is statically exported (scout §2: "the browser sees only emitted public/
artifacts"), so the server cannot know a returning user's checks — raw HTML can
only carry the default unchecked affordance. As written the AC is
unsatisfiable-as-stated and its curl proof passes vacuously (curl has empty
storage). The anti-Fandom intent (rows exist and degrade completely without JS)
is sound; reword to "every row present with its state affordance structure
(server-rendered default), personal state hydrating client-side without layout
shift".

### F3 — MEDIUM — exclusion-ledger numbers have no frozen source in T0's byte-freeze set

§5.1 law 2 freezes *"the eight dataset JSONLs of §3 + `markers.jsonl` +
`minigame--achievement.jsonl`"* while §5.2 emits
`"exclusion_ledger": {"notes": 160, "wiki_only_minigames": 4,
"cut_family_dumps": 48}`. notes=160 derives from frozen world_documents.jsonl,
but the wiki-only minigames (CAR-6, tier-4, `evidence:[]`) and the
Metroidvania 48-dump cut family (CAR-7) live in the candidates ledgers
(`cartridges-minigames.candidates.jsonl` et al.) which are NOT frozen. As
written T0 must either invent the two constants (violating its own projection-
only law 1) or read unfrozen inputs its tripwire cannot cover. Fix: add the
candidates JSONLs to the frozen set, or derive the counts from already-frozen
files. This is the riskiest item — it lands inside the gating module itself.

### F4 — MEDIUM — View D's "played/won is tracked" does not fit the stored schema

§8 View D: *"played/won is tracked"*; §6.1 stores one bit per item:
`interface ItemRecord { done: boolean; ts: number; … }`. Played and won are two
independent facts; one boolean cannot hold both, and the 8-set universe has no
second minigames set. Adding a value axis after v1 ships is exactly the
envelope-bump migration O3 exists to avoid. Fix now: either reword View D to a
single register ("played") or extend the record while no installed base exists.

### F5 — MEDIUM — L4's equal-ts tiebreak is executor-relative, and the "SAME conformance suite" claim conflicts with L1

§6.2 L4: *"equal-ts ties break deterministically on `(contract-id asc, then
local wins)`"*; L6/TR-A6: *"FakeSyncAdapter passes the SAME conformance suite as
LocalAdapter"*. Two problems: (a) "local wins" resolves the same tie oppositely
on device A vs device B — nondeterministic across replicas, undercutting the
determinism claim that makes the schema sync-ready; (b) L1's synchronous-write-
per-toggle spy (TR-A4) cannot bind a network-backed SyncAdapter, so an
unqualified "same suite" is unimplementable — the suite silently weakens or the
AC fails. Fix: pin an executor-independent total order (e.g. lexicographic on
`(ts, contract-id, done)`, or declare server-resolves-ties) and split the suite
into universal laws (both adapters) + adapter-specific laws (sync-write spy =
LocalAdapter only).

### F6 — LOW — `characters` store set has no defined 301 target

§13: *"`characters`, `profiles`, `books`, `papers` are STORE sets whose user
surfaces are the Documents view panels and entity tabs (their set routes 301 to
the owning view segment…)"*. Under §8's ruling `characters` owns no routed view,
so its redirect target is undefined. Name the hub as the target.

### F7 — LOW — TR-A12 conflates markers with rows; personage entity-href kind split unpinned

TR-A12: *"focus href == `/map?focus=<plural kind>:<slug>&scene=<scene_id>` for
all 70 marker-backed rows"* — markers number 70 but the rows backing them are
fewer (several rows carry ≥2 level markers); assert per-marker, not per-row.
Relatedly, cross-linking the 24 character rows needs the `mita`/`players`
segment split (`routes.ts KIND_SEGMENT` has no `characters` kind) — pin it.

### F8 — LOW — share token carries no ts, yet §10 speaks of "the codec's ts ordering"

§10 interaction 4: *"imported items keep the codec's ts ordering"*; L8's MST1
payload is `{sets:{<set_id>:[checked contract ids, sorted]}}` — ids only, there
is no ordering information to keep. Say what happens: imports stamp import-time
ts (and note the skew implication).
