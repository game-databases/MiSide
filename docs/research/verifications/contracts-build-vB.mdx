## Findings

**F1 — MAJOR: `relink_edge` registry block misstates corpus-wide measurements (last-artifact-wins
merge).** In `build_entities` (check_contracts.py ~lines 989–1007) `fields.update(measure_fields(rows))`
and `enums.update(measure_enums(rows, …))` execute inside the per-artifact loop, so for multi-artifact
entity types each field/enum entry reflects only the LAST artifact that contains it, not the union.
Only two decls are multi-artifact: dialogue_graph (fields empty by design — unaffected) and
relink_edge (25 files — fully affected). Measured against pooled disk truth over all 1,159 rows:

- `enums.direction` = `{forward:3, inverse:3}` (= character--dialogue-speaker's split, the last
  direction-bearing file processed); pooled truth is `{forward:196, inverse:154}`.
- `enums.kind` = `{forward:6, inverse:6}` (= document--minigame's kind-encoded direction); pooled
  truth is `{forward:396, inverse:396}`.
- **107 field-attribute misstatements**, e.g. `from.nullable=false` (truth: nullable, 31
  absent/null rows — 17 anchor-less + 14 nulls), `to.nullable=false` (28), `direction.nullable=false`
  (809), `kind.nullable=false` (367), `status.nullable=false` (17), `mechanism.nullable=false` (1),
  plus dozens of wrong `absent_or_null_rows` (`award_site` registry 14 vs pooled 1153).

This contradicts the registry's own `_meta.notation` ("enums are MEASURED value→count sets over all
data rows") and spec C2's "every enum lists only measured values" as a *distribution* claim. The 83
green gates cannot see it because regeneration repeats the same merge deterministically — C1 compares
identical wrongness. Note the notes-prose counts ({hard ×1024, logic ×104, inferred ×20 …},
status modeled ×1043 / partial ×73) ARE correct; only the machine-readable enums/fields blocks lie.
Fix shape: accumulate Counters/inventories across artifacts inside the loop, serialize once after it;
regenerate entities.json. Blast radius otherwise zero (single-artifact types unaffected — verified).

**F2 — MODERATE: `gate_never_null` cannot fail.** Its body (lines ~1576–1591) computes `bad` and
emits `rep.ok(...)` embedding the count — there is no `rep.fail` and no raise anywhere in the
function (verified by inspection + execution: 63 oks, fails impossible to produce). It contributes
~63 of the "83 gates green" headline while verifying nothing. Nullability drift does get caught
transitively by C1 byte-compare, so the *property* is covered, but the gate is a tautology wearing a
verification label. Fix: either compare against declared never-null expectations or delete the gate.

**F3 — MODERATE: `gate_anchor_lint` (C4) is self-referential and cannot fail on corpus drift.**
mode_verify passes it the freshly-built joins dict whose `anchor_grammar` was derived FROM THE SAME
ROWS in the same run — any novel anchor form auto-admits itself to the grammar before linting.
Demonstrated in memory: injecting `from:"cartridge:mta"` into minigame--scene-carrier leaves lint
green ("all 2259 string endpoints parse") while the grammar silently grows `cartridge:`. AC-C4's
mutation claim ("inject a `cartridge:` anchor → exit ≠ 0") does hold end-to-end, but through C1's
byte-diff of joins.json (`$.anchor_census.forms.cartridge:: added`), not through C4 — the lint adds
zero independent protection. Fix: derive the grammar from the COMMITTED joins.json (real lint), and
keep the fresh build only for the C1 comparison.
