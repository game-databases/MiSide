**Mutant liveness, reasoned from the gate code** (mutant not executed —
read-only pass): any reintroduction of suffix-first resolution at either bind
site changes artifact bytes in a way the provenance gate detects. Suffix-only
forgery (subject added, or writers/readers entry created, where
`inventory_object_path_id` is null but a suffix id exists) trips
`suffix_space_binds` → hard FAIL. Precedence-picking when both spaces match
different rows emits the suffix-named flag where the gate derives the true-row
flag → `subj_bad` FAIL. Suffix-routed writer/reader sets diverge from the
gate's true-space expectation → `wr_bad` FAIL. In all three shapes the run
exits non-zero, so F-LL4's "mutant killed" claim is consistent with the gate
mechanics. One honest boundary noted: the gate takes both id spaces from the
emitted `flag_instances` columns rather than re-deriving PathIDs from the
asset-list XMLs, so a hypothetical mutant that *fabricated inventory ids*
(rather than forging suffix binds) would not be caught by the selfcheck
alone — that gap is closed for this build by this pass's independent XML
pairing derivation (§2), and is a candidate hardening for the next selfcheck
round, not a defect in what shipped.
