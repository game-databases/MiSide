## 2. Emphasis 1 — `wiring_steps[]` as a CodeWriter receives it

Feasibility first, then the defects.

**The four-key set is projectable from shipped rows alone (D1-clean).**
`branch_edges` carries `from_node` and `call_index` as literal columns;
`container` is the node-id host segment; `edge_id` is unique ×1,555 so "keyed
by `edge_ref`" (§6) is collision-safe; zero pool edges have a `from_node`
outside `choice_nodes`, so "bridges two rendered nodes" is well-founded. A
mutant that adds/drops/rename a key dies at E10's EXACTLY assertion — that
part pins.

**V-B1 (MEDIUM, implementability): `edge_ref`'s FORM is unpinned, and only
one of the two candidate forms is legal under the spec's own laws.** On disk a
pool edge offers two identities: the raw `branch_edges.edge_id`
(e.g. `level15:DC4875:opt2:call1`) and the `effect-call:` canonical leg of its
`choice--consequence` projection. No §5.2 family covers the raw edge_id form,
and §5.2 declares the table exhaustive ("adding an id form not listed here is
an AC-E7 failure") — so the raw reading violates D6/E7 by construction, while
the arbiter's M-2 sentence ("`edge_ref` normalizes through §5.2") is true only
under the effect-call reading. The effect-call reading is also the only one
that can render §6's promised "neutral list of call targets": the bundle ships
no effect_calls rows and E6 bans frontend joins, so locator text exists only if
`edge_ref` embeds container/file/host/field/n. An implementer CAN infer all
this, but the spec makes them infer it; E10 cannot catch the wrong guess (key
set is identical). One clause fixes it — e.g. "`edge_ref` is the pool edge's
`to` leg in `effect-call:` canonical form (§5.2)". Related note, folded here:
`call_index` semantics resolve naturally once the disk schema is known
(verbatim copy of the shipped `branch_edges.call_index` column), but saying so
costs five words.

**V-B2 (MEDIUM-low): the population bound has no proof hook.** M-2's whole
point was a BOUNDED carrier ("ONLY pool edges bridging two rendered nodes on ≥1
precomputed path"), and §5.1 rule 4a states that law — but no AC tests it: E2's
reconciliation list covers nodes/edges/flags/pairs only, E10 checks keys plus
exclusion-ledger sums, E13 absorbs the size without asserting boundedness. A
mutant emitter that dumps all 824 pool edges into `wiring_steps[]` passes E1–E12
and E14 outright and only stresses E13 probabilistically. One E2 clause
("wiring_steps count reconciles against pool edges lying on ≥1 shipped
`paths[]` entry") closes it.
