## 4. Sync-readiness simulation (v1 → v2, two devices, skewed clocks)

Scenario walked through L1–L9 as amended: device A (wall clock +10 min fast)
and device B (accurate), both offline on the same T0 manifest; checks made on
both; a SyncAdapter arrives later and merges via `merge.ts`.

- **No v1-reachable loss path.** Single-writer localStorage; L1 writes
  synchronously inside the handler (no debounce window to lose); L3 quarantines
  malformed envelopes instead of wiping; drift-deleted ids are preserved across
  read/write cycles and exports; L9 reset clears exactly one key after
  confirmation. A remove-and-re-add patch round-trip restores the user's check.
- **Tie determinism holds.** Equal `ts` with opposite `done` resolves to
  `done=true` on either replica — executor-independent as F5 required; full
  ties are declared interchangeable/idempotent, so replaying a merge cannot
  flip state. Completion-preserving: no tie can silently un-check.
- **Per-axis independence behaves** (`done`↔`ts`, `won`↔`wonTs`): merging can
  produce axis combinations neither replica held — that is the definition of
  independent axes, not a defect; non-minigame sets never write the second
  axis.
- **Import leg** stamps uniform import-time ts (FIX-9) with an explicit skew
  note — an import reads as a local edit at the import instant; correct.

Holes found — all strictly BEHIND the declared seam (no caller today), none
reachable in v1, all non-gating:

- **HOLE-1 (clock skew is unordered, not just tie-prone).** With A fast by
  10 min: B checks item X at real 12:00 (ts_B); A un-checks X at real 12:05 but
  its stamp reads 11:55-equivalent < ts_B ⇒ merge resurrects `done=true`. The
  last REAL action silently loses. L4 orders on raw epoch ms; its guarantee is
  scoped to EQUAL-ts ties (and imports); cross-replica skew has no law. The
  spec's own words survive this ("a tie can therefore never silently un-check")
  because it claims tie-safety, not causal correctness — but "the semantics are
  already fixed" freezes wall-clock LWW in place, so a future HLC/monotonic
  fix would need the additive-migration path rather than a reword. One
  acknowledging sentence in L4 would close the gap between what a reader
  assumes ("sync-ready") and what is guaranteed.
- **HOLE-2 (`won`-axis tiebreak unstated).** The ruled tiebreak names only
  `done` ("equal ts ⇒ done=true wins"); the symmetric clause for equal `wonTs`
  with opposite `won` appears nowhere in L4 or TR-A6. Symmetry is implied, not
  ruled — the same executor-relative ambiguity F5 killed could legally
  re-enter through the second axis in a literal reading. No v1 writer emits
  `won`, so nothing breaks today; one clause fixes it.
- **HOLE-3 (tombstone-vs-live merge order undefined).** L5 reserves `tomb` and
  requires codec/suite round-trip, but L4 defines merge keys only for the two
  value axes. Nothing states `{tomb:t2}` beats a live record with `ts<t2`
  (nor whether a tomb can be cleared), i.e. resurrection-on-pull prevention is
  asserted at the schema level but not defined at the merge level where it
  would actually live.
- **HOLE-4 (reset × future sync = whole-set resurrection).** L9's reset clears
  the set key while L5 forbids writing tombstones in v1 — so once a SyncAdapter
  exists, reset-then-pull (or push-from-the-other-replica) reinstates every
  row: mass resurrection of precisely the class the tomb field exists to
  prevent. Unreachable in v1; the future adapter brief must define reset
  semantics (per-row tombs or a set-generation counter).

Net: the amended laws do prevent data loss AND silent resurrection for every
path reachable without a server (the simulation found none), and the equal-tie
determinism claim is sound; the four holes are future-seam residuals that must
ride into any SyncAdapter brief, not defects in the frozen v1 contract.
