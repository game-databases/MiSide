Probe-nuance, ruled no-defect: `javascript&colonalert(1)` (named ref
WITHOUT semicolon) passes — correctly. Browsers do not decode
semicolon-less non-legacy named refs inside attribute values, and the
decoder mirrors that (whole-key match against `NAMED_CHARREFS`;
`colonalert` is not a key), so the served attribute stays a relative
path — inert on both sides of the emitter/browser pair. The decoder's
aggressive side (`&Tab`/`&NewLine` decoded without semicolon where a
browser would leave them literal) can only over-block, never under-block:
fail-closed direction. Numeric refs decode with AND without the
semicolon, matching browser numeric-ref semantics; NUL/surrogate → U+FFFD
matches. Suite bite: lexer mutations ×4 + re-parse leg + pin block incl.
`&#106;avascript&colon;` full-decode (contentPipeline.test.mjs:178–248).
