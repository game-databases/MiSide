### Binding design — LG2 becomes a two-tier sweep (replace §4 LG2's sweep paragraph)

**Tier A — semantic whitelist (full extraction).** Corpus-wide persistent-call sweep over all 51
containers extracting every call whose target method is one of the nine whitelisted families
(`Achievement_function.AchievementGet/AchievementComplete(int)` · `Achievement_cloth.ClothCompleted`
· `Events_IntMemory.{Set,Add,Remove,CheckEvent,CheckEventIndex}` + `*Ignory` variants ·
`Events_Data.EV` · `Scene_Load.StartLoad/SilentSave` · `World.SaveStoryMita/SaveStoryCartridge`).
Tier-A rows carry `subject_ids` (achievement id from `args.string`, cloth id, flag id via LG1),
feed every floor (≥11 award sites, ≥2 cloth sites, ≥18 flag edges inside ending contexts), and feed
LG3/projections. Floors are minimums: the corpus-wide sweep must find at least them or explain every
miss in the emit ledger (existing sentence stays).

**Tier B — disposition sweep (census accounting, no silent drops).** Every remaining persistent
call found by the same sweep is also emitted to `effect_calls.jsonl`, classified with DS-2's
type/method semantics (`scene-flow | cosmetic | audiovisual | dead-reference`) so §7 item 2's ~824
presentation calls exist as graph fuel. Tier-B rows are stamped `"internal_only":true`,
`subject_ids:[]`, and never surface through LG3. Tier B is necessarily unfiltered — the
dead-reference class can only be discovered by sweeping without a whitelist (`m_Target=0` residue,
[END-4]). Tier assignment (A/B) is **orthogonal** to `effect_class`: measured proof —
`level14:ObjectInteractive:3695:call4` is whitelist-admitted (`Scene_Load.StartLoad`) yet DS-2
classified it `cosmetic`. The emitter must therefore record BOTH axes per row.

**Census accounting (what makes AC-L1 honest).** `effect_calls._meta` carries per-`effect_class`
totals over ALL persistent calls found corpus-wide plus `tier_a_count`/`tier_b_count`; any
persistent call the sweep declines to emit is impossible by construction — a call exists in the
output or in the ledgered counts, never in neither. No numeric promise beyond the floors and the
reconciled 1,555 is made (tier-B magnitude is discovered, not asserted).

### Binding design — AC-L1 restated (replace the §8 L1 row)

The reviewer's proposed join — edge_id-derived container + `(target.type, target.method,
object_path_id, args)` + `call_index` tiebreaker — was **collision-tested this pass and fails**:
47 colliding groups, max multiplicity 13 (container prefix alone: 59 groups, ×15). The container is
not the discriminator; the host component is. The working key resolves each edge's host through the
*node* table first:

```
K(edge) = ( node.container, node.event_field, node.object_path_id,
            edge.from_option, edge.call_index,
            target.type, target.method, target.object_path_id, args-tuple )
where node = choice_nodes[row with node_id == edge.from_node]   # 371/371 unique ids, 0 unresolved edges
```

Measured this pass over all 1,555 rows: **1,555 groups, 0 collisions** — dropping any one of
`event_field`, `from_option`, `call_index` reintroduces collisions (7–59 groups). Therefore:

- **L1a (byte-freeze, unchanged):** sha256 of the four `endings/*.jsonl` identical before/after
  emission.
- **L1b (row resolution):** every `branch_edges.jsonl` row resolves to **exactly one**
  `effect_calls` row under `K` — 1,555/1,555. To make `K` computable from the LG2 side,
  `effect_calls` gains three fields (fix-order item 2): `event_field` (the serialized UnityEvent
  field path the call lives in, e.g. `eventClick` or `buttons[2].eventClick`),
  `option_index:int|null` (null when the carrier has no option structure; edge-side `from_option`
  maps onto it), and `call_index:int` = position within that field's PersistentCallGroup. LG2
  computes these walking the same dumps DS-2 walked; the checker verifies the mapping empirically
  rather than trusting it.
- **L1c (census accounting):** `_meta` class/tier totals present and additive; zero unclassified
  persistent calls.

This keeps AC-L1 satisfiable honestly: no widening beyond spec, no force-fitting, and the gate gets
*stronger* than the original wording because it pins the discriminator the original tuple lacked.

## F-2 (M-1) — polarity `value` derivation — MODIFY

The hole is real and load-bearing: §3's pairing law + LG3's evidence_class rule prove *existence* of
a site, never *sense*; as written, `{value:"positive", evidence_class:"static-proven"}` passes AC-L3
on an unproven gate, exactly the harmful row Law 2 exists to prevent. The reviewer's verb→direction
allowlist is the right mechanism but needs two corrections: (a) **save-literals are not positives**
— a `Scene_Load.fileSave`/`nameLevelSaves` literal is a pure access point ("you can save here"), no
direction; it takes `value:null` under the spec's own no-direction clause, not `positive`; (b)
**`"negative"` must be reserved outright** — zero rows in this build may carry it, because no static
or cited evidence of a *hurts* direction exists anywhere in the corpus; leaving it assignable
invites the first wrong render.

**Binding rule (one paragraph into §3):** `polarity.value != null` is legal only per this table,
checked mechanically at emit AND re-checked by AC-L3:

| condition shape | value | evidence_class |
|---|---|---|
| call method ∈ {`Achievement_function.AchievementGet`, `Achievement_function.AchievementComplete`, `Achievement_cloth.ClothCompleted`} with site evidence | `"positive"` | `static-proven` |
| pickup-gate rows (`expression_class:"access-chain"` via `cartridges.pickup_ref`, serialized `FlashTaker.save` carrier) | `"positive"` | `static-proven` |
| safe-window attribution family (§6 row 3), while the OQ-3 posture stands | attributed parameter, flagged `sense_source:"community"` — directional `value` permitted only here | `inferred` + mandatory `citation[]` |
| pure access points (save-literals, minigame access chains) | `null` (no direction exists) | any |
| everything else — flag gates, toggles, windows-as-advice, spawn semantics | `null` | `fail-closed-unknown` until [XC-1] |

**`"negative"` is reserved: zero occurrences this build.** AC-L3's proof column gains "recomputes
`value` against the §3 table" alongside the existing `evidence_class` recomputation — a wrong
positive now fails the gate instead of passing it. Schema unchanged; OQ-3 tightening still costs one
renderer line.
