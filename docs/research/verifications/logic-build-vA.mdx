## 4. Dual-space binding discovery

Two id spaces exist in this corpus: **dump-filename suffix ids** (the pack-wide
instance handle used by DS-2 node ids, poi ids, `flag_instances.object_path_id`)
and **serialized PPtr path ids** (what UnityEvent `m_Target.m_PathID` carries,
mirrored by the harvest asset-list inventory). The emitter probed the relation
(`identity_namespace_check`: 40 suffixed ids sampled across 5 containers vs
their container's inventory PathIDs → 6 hits, agreement false → verdict
"namespaces DISJOINT -> bare-name resolution fails closed") and ledgered both
the probe and all 49 ambiguous pairings. Binding then ran suffix-first with
true-id fallback.

Empirical outcome on the landed build (my recount over all Events_*-targeted
calls, n=81): **20 true-only binds, 0 suffix-only binds, 0 conflicts (suffix and
true match different rows), 0 class mismatches, 61 unresolved left with empty
subjects/writers/readers.** So the risky suffix-space branch never fired; every
binding that happened went through the inventory-resolved true-id bridge, and
the level4 case in the brief is exactly right: Add() calls target PPtr 4823/4918
while the container's IntMemory dumps are bare + `_#3327` — those calls are all
honestly unresolved (`subject_ids:[]`), never force-joined.

Assessment for the arbiter: **no silent misjoin exists in the landed artifacts**,
and the duality is labeled honestly in at least four places (`_meta
.identity_rule` + `.identity_namespace_check` on flag_instances, the
`two-id-space-pairing` and `identity-namespace-measurement` emit-ledger rows,
per-row `inventory_object_path_id`, and the identity-ledger reason strings).
Residual latent risk, worth one arbiter glance: (a) the suffix-first ordering
would silently misbind on a future corpus where a targeting PPtr numerically
equals another instance's suffix id — the probe itself measured ~15% collision
propensity among suffixed instances, so inverting precedence (true-id first) or
adding a both-match→unresolved+ledger guard is a cheap hardening; (b) the field
name `object_path_id` means suffix-space in flag_instances but PPtr-space inside
effect_calls `target.*` — a naive cross-file join on equal field names would
produce garbage; today only prose warns about it. Blast radius if it ever fires:
writers/readers columns + `flag--gates.jsonl` (flags are not LG3 subjects, so no
predicate row consumes a flag binding).

## 6. Findings + verdict

No MAJOR defects found. Law 1 holds (every consumed dataset's live sha equals
its pre-emission manifest pin; endings files doubly confirmed), Law 2 holds
mechanically and holistically. Minor items, none gate-blocking:

- **F1 (minor)** — `minigame_tunables` rows carry no `internal_only:true`
  although §7's preamble/§3 pairing rule name LG4 envelopes as internal-only
  (§5's own shape omits the field too). The envelope label rides
  `kind:"envelope"` + `rule_status:"not-a-threshold"` instead; the common
  `if row.internal_only: skip` filter idiom treats absent as public. One-line
  emit fix + registry note recommended.
- **F2 (minor)** — 5 LG4 evidence globs match zero files: e.g.
  `harvest/mb-dump/level3/Tamagotchi_Main_*.txt` — those carriers exist as
  *bare-named* dumps (`Tamagotchi_Main.txt`), which the `_*` glob misses. Data
  itself is real (fence exclusion counted showInterface from that very dump);
  locator precision only.
- **F3 (minor)** — `input-manifest.entities_json_sha256` (7801f04d…) ≠ live
  [contracts/registry/entities.json](../../../contracts/registry/entities.json)
  (e4c68aef…, mtime 10:15:45 vs outputs 10:08:53): concurrent contracts-chain
  edits after emission, compounded by the emitter hashing the registry *before*
  its own insert. Self-heals on the next pipeline pass (the run_all stage
  report re-pins); all four `miside.logic.*` schema ids are present and
  registered (AC-L6 satisfied).
- **F4 (nit)** — `flag--gates` row `method` string says targets resolve to
  "(container, object_path_id)" — stale wording vs the actual
  suffix-or-inventory dual rule documented correctly elsewhere.
- **F5 (nit)** — spec §6 obliges the emitter pass to append newly-discovered
  gaps to `missingdata.md`; nothing was appended (the two-id-space facts live in
  emit-ledger/identity-ledger instead). Defensible reading — they are mechanics,
  not chase-prevention gaps — but the safer move would have been one row there.
- **F6 (spec prose)** — §4-LG2's "133 distinct pairs exist corpus-wide" is the
  ending-context figure (corpus-wide = 882). No artifact repeats the number, so
  the shipped data is unaffected.
