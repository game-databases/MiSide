## 3. Adversarial findings

### F-B1 · MEDIUM — `body_sha16` as defined cannot detect pivot-move staleness; TRANSLATION-STALE can ship silently

§8.1 L455–456 defines the cell field: "`body_sha16` — hash of the admitted
`.mdx` source at admission time". Read literally, each locale cell hashes ITS
OWN file (the de cell hashes `guides/<slug>.de.mdx`). §3.3 L205–208 then says:
"when a pivot EN hash moves, every sibling locale **still carrying its old
hash** prints TRANSLATION-STALE". Walk the edit:

- t0: `en.mdx` admitted (hash H_E1); translator produces `de.mdx` against it;
  under the literal definition the de cell stores hash(de.mdx) = H_D1.
- t1: pivot edited → disk hash of `en.mdx` becomes H_E2; emit recomputes.
- The comparison the spec needs is `stored(sibling) ≠ current(pivot)`. But
  H_D1 is a hash of a DIFFERENT FILE than H_E2 — they are unequal by
  construction, forever, for every sibling, regardless of when the sibling
  was translated. The predicate "still carrying its old hash" has no referent:
  no sibling ever carries a pivot hash, so either the implementation flags ALL
  siblings on every pivot move (noise → ignored → silent) or NONE (vacuous).
- Silent-ship path concretely: emit refreshes stored hashes to own-file
  current values (the only self-consistent behavior under the literal
  definition); a translator who re-admits `de.mdx` AFTER the pivot move is
  then indistinguishable from one who worked pre-move — the stale translation
  ships with zero output.

The intended mechanism is recoverable in one sentence — non-pivot cells must
store **the pivot body hash the translation was admitted against**
(base-hash semantics), and emit compares `cell.base_sha16 ≠ sha(current
pivot .mdx)` — but the spec's two sentences describe two different data
models, and an implementer following the definition sentence ships the vacuous
one. Aggravating: §11 has NO AC covering translation staleness — C8's proof
(L567) mutates a contract ROW and asserts entity-drift `STALE:` only; nothing
mutates a pivot `.mdx` and asserts `TRANSLATION-STALE:` on a sibling. The new
law from M-6/F7 therefore lands unenforced. Fix: redefine the per-cell field
semantics (pivot base hash for non-pivot cells, own hash for the pivot cell),
state the comparison explicitly, and add the missing AC leg.

### F-B2 · MEDIUM — C14's emitted-HTML grep lists `<img`, which markdown generation DOES produce

C14 L573 final leg: "emitted body HTML greps clean of raw-HTML signatures
markdown generation cannot produce (`<script`, `<iframe`, `<img`,
`onerror=`)". The parenthetical claim is false for `<img`: standard markdown
image syntax `![alt](/cdn/v19029065/x.png)` compiles to
`<img src="…" alt="…">` — markup generated FROM markdown syntax itself,
which is precisely what §2's law (L131–132) promises the output contains.
Nothing in §5 bans body images (only REMOTE images are forbidden), so an
honest guide with one local screenshot makes C14's clean-tree grep red.
The implementer's two exits are both bad: keep the signature and the AC is
unsatisfiable-as-written, or quietly drop `<img` and the tripwire is narrowed
without a spec change (`onerror=` has the same edge contrivedly:
`![onerror=](x)` → `alt="onerror="`). Note this does NOT open an injection
path — the html-token deny remains enforcement of record and no raw HTML can
reach the emitter — but the AC as written fails the soundness bar every other
AC meets. Fix direction: assert the stronger, decidable invariant instead of
a substring blocklist — re-parse the emitted HTML and allow only the
markdown-generated element set (`p h1–h6 ul ol li a img code pre blockquote
table em strong del br hr span`), or replace bare `<img` with a handler-
attribute pattern markdown never emits (`<img[^>]+\son[a-z]+\s*=`).

### F-B3 · LOW-MEDIUM — V3 cites cartridges as `name_loc: null`; disk truth is key-absent

Spec L264 (and, upstream, the CAR-5 row in `extracted/data/missingdata.md:93`)
states 23/23 cartridge rows "ship `name_loc: null`". Measured: the key is
ABSENT on all 23 rows — and the landed typed contract agrees:
`CartridgeRow` (`contracts.ts:109–121`) declares NO `name_loc` member at all,
while `MinigameRow` (`contracts.ts:128`) declares `name_loc: LocPointer |
null` and the minigames file really does carry literal JSON nulls (15/17;
`fight`/`pinguin` have real `{TelevisionGames, 0|1}` pointers). The corpus
genuinely exhibits BOTH shapes, and tie-break 2 cites the wrong one for its
own precedent while tie-break 3 says "absent/contentless" without stating the
words are interchangeable. Implementer hazard is concrete: `row.name_loc ===
null` is false for an absent key in JS, so a validator written to the cited
representation classifies every cartridge as named and attempts to link
`undefined`. Fix: make namelessness state-agnostic in one clause — "absent
key, explicit null, or empty resolution ⇒ nameless" — and correct the CAR-5
citation (the ledger phrasing in missingdata.md is itself the drifted source;
worth a one-line note there too, owner's call).

### F-B4 · LOW — C14 seed set omits the autolink and reference-definition vectors

`[x](javascript:…)` is seeded, but CommonMark also turns `<javascript:…>`
angle autolinks into anchor elements and resolves `[x][ref]` +
`[ref]: javascript:…` definitions — neither passes through an `html` token,
so both survive the token deny and are caught ONLY if the href allowlist
walks EVERY link/image destination regardless of token origin (autolinks,
definitions, image tokens). The law's wording ("link destinations") permits
that implementation but doesn't demand it; add both fixtures as seeds and say
"every `link`/`image` token destination however produced".

### F-B5 · LOW — `link_terms` "whole-token match" is undefined for unsegmented scripts

Tie-break 2 pins "exact case-insensitive whole-token match". Word-boundary
matching has no portable definition across the ×34 matrix for zh-Hans/
zh-Hant/ja/ko/th (no whitespace segmentation) and degrades in ar. Since
sibling files carry their own frontmatter, terms will be authored per locale
— exactly where the matching rule is least defined. Fix: define the matcher
(Unicode word-boundary where the locale segments, plain substring otherwise)
or scope whole-token to space-delimited locales explicitly.

## 5. Staleness simulation (pivot edit)

Full walk in F-B1; summary: entity-row drift (C8) is well-defined and
implementable — hash the referenced contract row, compare at emit, flip
`stale`, print `STALE:`. Pivot-move drift (M-6) is NOT implementable as
written: the stored per-locale value that would make "still carrying its old
hash" meaningful is undefined by the field's own definition sentence, and no
AC exercises the printout. One silent-ship path exists (post-move re-admission
indistinguishable from pre-move under own-hash refresh). This is the pass's
substantive design defect.
