## Findings

### F-1 — HIGH: LG2's method whitelist makes AC-L1's 1,555/1,555 gate impossible, and the L1 join key names fields `branch_edges` does not have

Spec §4 LG2: *"Corpus-wide persistent-call sweep (51 containers) with a method whitelist derived
from dump.cs signatures: `Achievement_function.AchievementGet/AchievementComplete(int)` ·
`Achievement_cloth.ClothCompleted` · `Events_IntMemory.{Set,Add,Remove,CheckEvent,CheckEventIndex}`
(+ `*Ignory` variants) · `Events_Data.EV` · `Scene_Load.StartLoad/SilentSave` ·
`World.SaveStoryMita/SaveStoryCartridge`."* — and §8 L1: *"every `branch_edges.jsonl` row resolves
to exactly one `effect_calls` row — 1,555/1,555 … checker joins on
`(container,file,target_type,method,object_path_id,args)`"*.

Disk evidence: cross-tabulating all 1,555 `branch_edges` rows against that exact nine-family
whitelist gives **20 IN / 1,535 OUT**: scene-flow 709/709 OUT, audiovisual 356/356 OUT, cosmetic
467/468 OUT, dead-reference 3/3 OUT, flag-set 10 IN, flag-query 8 IN, award 1 IN. The edges target
133 distinct `(target.type,target.method)` pairs led by `UnityEngine.GameObject.SetActive` ×265,
`ObjectAnimationPlayer.AnimationPlay` ×160, `UnityEngine.AudioSource.Play` ×131,
`UnityEngine.Animator.SetTrigger` ×104, `UnityEngine.ParticleSystem.{Play,Stop}` ×167 — none of
which the whitelist admits, yet §7 item 2 expects *"Cosmetic (468) + audiovisual (356) effect calls
(~824)"* **inside** `effect_calls.jsonl` as graph fuel. Second defect: `branch_edges.jsonl` rows
carry keys `{args,branch_if_int,call_index,edge_id,effect_class,feeds_ending,from_node,from_option,
status,target}` — there is **no `file` field and no top-level `container`** (container survives
only as the `edge_id`/`from_node` prefix), so the specified join tuple cannot be built as written,
and uniqueness would lean on reproducing DS-2's `call_index` ordering, which nothing pins.

Consequences if built as-is: either the CodeWriter implements the literal whitelist and AC-L1 fails
at 20/1,555, or it silently widens the sweep beyond spec and the spec text lies about what ran.

Fix (one paragraph, no structural change): make LG2 a **two-tier sweep** — tier 1 = the enumerated
semantic whitelist (feeds `subject_ids`, floors, projections); tier 2 = **all remaining persistent
calls**, classified with DS-2's type/method semantics so cosmetic/audiovisual/scene-flow land in
`effect_calls` as internal-only rows (they already carry `effect_class` semantics to copy). Restate
AC-L1's join as `(edge_id-derived container) + (target.type,target.method,target.object_path_id,
args)` with `call_index` as the explicit tiebreaker, or pin that `effect_calls` must reproduce
DS-2's per-host call ordering. Note the dead-reference class additionally *requires* an unfiltered
sweep (a whitelisted filter can never discover `m_Target=0` residue).

### F-2 — MEDIUM: `polarity.value` has no derivation rule — `static-proven` evidence does not prove *direction*, and AC-L3 cannot catch a wrong positive

Spec §3 defines the pairing law (*"A row may not state a `value` without an evidence class; the
checker rejects any `value` paired with `fail-closed-unknown`"*) and §4 LG3 gives the mechanical
**evidence_class** rule (*"serialized site in evidence → `static-proven`; `[community]`/
wiki-attributed citation → `inferred`; otherwise `fail-closed-unknown`"*) — but **nothing in the
spec states who or what assigns `value`, or when a serialized site justifies `value:"positive"`**.
For award verbs the direction is inherent in the call (`AchievementGet`/`ClothCompleted` grant);
for a **gate** (flag query, window, toggle) a byte-verified site proves existence, not sense —
that is precisely F5's NOT-STATIC ruling and the scout's "single biggest feasibility risk". As
written, a row `{subject: ending conditions-met, condition: <IntMemory site>, polarity:{value:
"positive", evidence_class:"static-proven"}}` passes AC-L3 (value paired with static-proven-grade
evidence) while asserting exactly the harmful unproven advice Law 2 exists to prevent. Today only
§6's per-family dispositions stand in the way; the LAW itself has the hole.

Disk evidence: `branch_edges` contains 8 `flag-query` + 10 `flag-set` serialized edges whose
sense is unproven ([END-5] `feeds_ending:true ×0` measured again this pass) — i.e., the dangerous
row population is real and already enumerated in the corpus.

Fix: pin a **verb→direction allowlist** for `value≠null` under `static-proven`
(`AchievementGet`, `AchievementComplete`, `ClothCompleted`, `Scene_Load.fileSave`-family save
literals, `FlashTaker.save` pickups ⇒ positive; every other target/method ⇒ `value:null` +
`fail-closed-unknown` until [XC-1]), and extend AC-L3 to recompute `value` against that table, not
just `evidence_class`. One sentence in §3 + one column in the L3 proof row.

### F-3 — MEDIUM: cartridge census is stale-scout, not re-measured — 23 rows / 21 resolved pickups on disk vs the spec's "24 cartridges" / "22 resolved"

and its `mode_unlocked:{state:"locked-stub"}` rides those rows (measured; XC-12 posture) — drop
the "+" clause or reword to "incl. the Peaceful locked-stub".
