### F-1 (MEDIUM) — AC MV-0.4 arithmetic unsatisfiable at kind granularity — **ACCEPT**

Evidence: measured exactly as claimed — `travel_gate` 46 = 19
`Scene_Load` + 14 `Trigger_Teleport` + 13 `Player_Teleport`; `cartridge`
25 = 21 emittable + 4 pets; the 11 DS-5 profile markers have no `poi.jsonl`
row at all. Kind-keyed families cannot partition 709.

**Binding corrected gate (replaces §3.2(c) last bullet + AC MV-0.4's
identity):** the ledger becomes two lists, and families key finer than
kind.

1. `pending_families[]` entries key a `(kind, class_axis)` pair and name a
   closed class list: `{family_id, poi_kinds[], poi_classes[], poi_rows,
   disposition, emitted_markers?, reason_code?, unblock_owner?}` where
   `disposition ∈ {"emitted", "deferred"}`. No entry may key a bare kind.
2. Partition identity: **Σ `poi_rows` over `pending_families` = the
   eligible-row recount (=709 today)**, with class lists pairwise disjoint
   and jointly covering every `marker_eligible:true` class. Counts are
   recomputed at emit time from `poi-kinds.json` + `poi.jsonl`, never
   inherited from v0 `_meta`.
3. Placement-sourced markers (DS-5 profiles; minigame carriers per OQ-7)
   report under a sibling `placement_families[]` with the same fields minus
   `poi_rows`/`poi_classes` plus `source_dataset` — their source rows live
   outside the poi pool, which is why they must not be forced into the 709.
   Total marker rows = Σ `emitted_markers` over **both** lists.

### F-2 (MEDIUM) — OQ-7 has no legal marker shape — **ACCEPT**

Evidence: confirmed and worse than stated — all 70 `minigame_access` rows
are `MinigamesController` whose only joins are `{is_scene,
world_object_path_id}`; the carrier edges bind `(minigame, container)` via
**CarSpace_\*-class grep co-presence**, not controller instances; level9
hosts 4 minigames over 3 controller rows and 9 containers host >1
minigame, so a per-instance `poi_id` anchor is not merely inconvenient,
any assignment would be fabricated. Edges span level2–level23; level1's
3 rows sit outside every edge.

**Binding corrected shape:** generalize §3.2(b)'s DS-5 escape hatch into
one **placement-sourced marker** shape and use it for both sources:

- Rows keyed by `placement_source` (`"DS-5"` | `"minigame--scene-carrier"`)
  + owning id (`document_id` | `minigame_id`); `poi_id: null` mandatory;
  `position.status: "scene-granular"` always — never `"projected"`.
- `container` must be emitted as its own scalar field, split emitter-side
  out of `to:"scene-class-family@levelN"`; downstream string-splitting of
  the compound id is a forbidden derivation (§4 list).
- Edge provenance rides verbatim (`mechanism`, `status`, `method`) into
  `placement`.
- `instance_census` required whenever a container hosts >1 controller
  instance or >1 minigame (measured: 22 covered containers, 9 multi-
  minigame) so a count shown to a user is never silently one-of-N.
- Forbidden: mapping specific `MinigamesController` poi rows to specific
  minigames; rendering a scene-granular marker as a plotted pin.

Yield accounting for the ledger: ≤38 scene-granular rows covering 67 of
the 70 poi rows (level1's 3 defer under `no-carrier-edge`).
