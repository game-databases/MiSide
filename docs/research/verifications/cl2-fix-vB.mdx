## 2. Safety design 1 — prior-pin witness, BOTH branches walked

Patch day simulated step-by-step against §4.2 + §4.3 as landed:

**Correct sequence (must ACCEPT).** Tree N−1 on disk; appmanifest buildid
≠ 19029065; DepotDownloader pulls tree N keeping N−1 (keep-until-diffed);
`run_all` rerun reaches S10 last; M2 hashes N−1's fingerprinted artifact set
under fingerprints conventions and writes
`_pins/<19029065>-to-<new>.json` FIRST (before any changeset, before
N−1 release); emit-stage commit re-pins fingerprints.json to N-only
(one generation); diff arm compares N−1 vs N and emits changesets.
Walking CL-1's clauses over this end state: (a) every
`changesets/<from>-to-<to>/` directory has its name-matched
`_pins/<from>-to-<to>.json` — yes, M2 wrote it from the same pair;
(b) ids coherent with the directory — yes, parsed from the same buildids;
(c) from-side artifact map covers every path the changeset reports
changed/removed — yes, the changed/removed set is derived FROM the N−1 map,
so coverage holds by construction (superset check); (d) fingerprints.json
holds exactly one generation — yes, replacement law. **CL-1 ACCEPTS.** The
original defect (gate keyed on ≥2 distinct build_ids inside
fingerprints.json, which flagged the correct post-trigger state) is gone:
the only remaining "distinct … trees" keying is the dormancy condition
(§4.1), correctly keyed on trees on disk, not pin generations.

**Fabrication branches (must REJECT).**
1. Changeset injected, NO pin record → clause (a) fails outright; proof
   method asserts nonzero exit naming the changeset file AND the missing
   `_pins/` path. REJECTED.
2. Pin present, ids incoherent with directory (e.g. wrong `<to>` in the
   filename) → clause (b) fails. REJECTED.
3. Pin present, from-side map missing a path the changeset reports removed
   or changed → clause (c) fails (coverage is per-path, not count-based).
   REJECTED.
4. Corrupted digest INSIDE an otherwise coherent pin record → CL-1 alone
   catches it when the mutated path is one the changeset reports (pin
   digest ≠ changeset from-side value); for a mutated unchanged-path digest
   the red comes from CL-10, whose "fingerprint delta between two re-pins"
   can only be computed as pin-record ↔ current-fingerprints symmetric
   difference under the one-generation law — a corrupted entry manufactures
   a false delta that appears in no changeset → red. So the promised
   "corrupt one digest → red" holds through the CL-1+CL-10 combination.
   Minor: that delta-source identity is derivable but never stated (Obs-2).
5. Residual honesty envelope (not a defect): a fully self-consistent
   fabricated pair (changeset + coherent pin whose to-side digests match
   real fingerprints.json) is unfalsifiable from the committed corpus once
   tree N−1 is deleted — inherent to any post-delete witness scheme, and
   outside this spec's threat model (mechanical drift, not forgery); the
   structural arm (M1 cannot emit `evidence_class:"computed"`), the
   code-plane digest coverage (CL-10), and the traceability gates are the
   fences the design actually promises.

Dormancy interplay clean: pre-trigger there are zero changesets and zero
`_pins/` bytes, so CL-1 passes vacuously and the zero-bytes law (§4.1, §4.3
final sentence, dependency edge, CL-8) stays intact everywhere — no
contradiction between "witness written first" and "zero bytes pre-trigger"
because the witness is trigger-time-only.

  projection goes stale against a longer fingerprints.json → same CL-2 red.
  Nothing breaks silently; the fingerprint conventions ("recompute on every

  makes ordering violations detectable regardless of direction.

  guards): M1 snapshots pre-logic-layer digests for the four
  `extracted/data/logic/**` entries; logic-layer then rewrites them;
