### F-1 (BLOCKING) — `effect_calls.edge_id` is not unique: 37 ids across 209 rows

Measured: 37 duplicate `edge_id` values covering 209 rows (172 excess), all on
array-of-events carriers — `Events_Animator` ×207 rows (11 containers,
largest single id reused ×10 in `level5/Events_Animator_#7106.txt`),
`FunctionsGame_PlayerWhyWalk` ×2 (`level9`). Raw ground truth
(`level2/Events_Animator_#2830.txt`): **8 distinct `eventAnim` UnityEvent
groups / 12 genuine calls** in one file; the parser collapses every element to
the same `field_path` string (`events.data.eventAnim` — no array-element
discriminator survives), so each group's restarting `call_index` collides.

Why it matters despite everything else passing:

- `effect_calls._meta.edge_id_shape` claims "a field_path segment keeps
  multi-group hosts unique" — falsified by these carriers (multi-GROUP hosts
  are exactly what collided);
- the emitter's own `REGISTRY_ENTITY_DECLS` declares `key="edge_id"` for the
  effect_call contract, and the landed `contracts/registry/entities.json`
  entry — whose enum counts match this build exactly — is the one logic entity
  registered with `key:null`;
- extraction-doctrine Principle one makes identifiers the join glue; any
  id-keyed consumer silently merges distinct serialized calls.

Blast radius (measured, contained): all 209 rows are tier B /
`internal_only:true`; **zero** branch_edges joins land on them under K;
**zero** references from either projection; selfcheck green because it joins
by K, not edge_id. AC-L1..L6 unaffected. Fix is mechanical (carry the group
ordinal/index into `field_path` for `<Type> data` element-array groups) +
deterministic re-emission; hashes and registry counts refresh with it.
