## Findings

### MEDIUM

**M1. §7 item 3 attributes the wrong artifact to "the one proven award edge".**
> "the level6 award-site call (`ACHI_none` grant) renders as the one proven award edge, linked to its call popover"

Measured: the single award-class edge in tree scope is
`branch_edges.jsonl` `level14:ObjectInteractive:call4` →
`Achievement_function.AchievementGet("ACHI_achi")`. The level6 `ACHI_none`
grant lives in `endings.jsonl.conditions-met.award_chain[]` (`Events_Data_#6042.txt`,
`award_chain_status:"proven-hard"`) — which is **not a graph edge**
(`feeds_ending:true` ×0, MA-8, and §7 item 3 itself says trigger context rides
native bodies three sentences earlier; §3's own render-set arithmetic counts
award ×1 = the level14 row inside the 728). As written, a CodeWriter binds the
pane block to the wrong row id or invents a join to make the sentence true —
E2's hop-traceability sampling would then fail or mis-link player-facing copy.
Fix: name the two artifacts separately (pane renders the `award_chain` calls as
chain entries with call popovers; the graph's award ×1 edge stays the level14
row).

**M2. E10 exclusion law contradicts the promised `+N wiring steps` expansion.**
§5.1 item 4: internal_only/cosmetic/audiovisual/dead-reference rows "never enter
the graph payload; they enter ONLY the `_meta.exclusion_ledger` counts" (AC-E10:
payload scan, zero hits). But §5.3's edges comment says "728 rendered +
traversal-through markers for the 824-pool", and §6 promises the chip "expands
to a neutral list of call targets". A list of call targets is row data from
exactly the classes E10 bans from the payload. No carrier shape is defined for
the expanded content. Fix before CodeWriter: either declare a dedicated compact
`pool[]`/`wiring_steps[]` bundle section (canonical id + container/file only)
explicitly outside E10's row scan, or downgrade the expansion to counts +
machine-voice locator text carried in `_meta.exclusion_ledger`.

**M3. §5.3 label-sourcing law cites a field that does not exist on choice nodes.**
> "node labels are class-preserving (`desluggedLabel` pattern) because `parent_name` is null by measurement"

Measured: `choice_nodes.jsonl` has **no `parent_name` column at all** (0 hits in
all 371 rows; registry `choice_node` field list confirms — `parent_name` exists
on `flag_instances`, where it is absent/null ×384). The justification survives
on `prompt_loc` alone (null ×358/371, measured ✓), but this is precisely the
invented-field class this review hunts: a CodeWriter implementing label fallback
will reach for `node.parent_name`. Fix: cite `prompt_loc` only (and optionally
note the conflation).

**M4. `explorerState.ts` is owned by two modules with no landing order.**
§4 table: M2 "interactions & state … `explorerState.ts` URL law" and M6 "routes,
deep-links, i18n ×34 … `explorerState.ts`". The file carrying the D5 URL law
(integer-probe rule, history split, slug encoding) has no single owner and no
stated merge order between M2 and M6 — the exact drift surface E8 tests. Map-viewer's
precedent assigns `mapState.ts` to exactly one module (M2) with the routes module
consuming it. Fix: name the owning module and the other's consumption posture.

### LOW

**L1. §3 table marks `branch_edges.jsonl` "(+`_meta`)" — the file is flat.**
First-line check: `choice_nodes`, `branch_edges`, and `endings` have **no**
leading `_meta` line (header class C per registry); only the three logic files
and both relinks lead with `_meta`. Spec states this correctly for
`choice_nodes` ("no `_meta` header — flat") but wrongly for `branch_edges`.
No AC depends on it, but E2 says "counts additive against `_meta` censuses" —
state that tree-scope edge-class counts recompute from rows directly.

**L2. §8.2 adds an emitter operation that §5.1 item 1's closed list omits.**
"paths[] … computed at EMIT time" vs §5.1's "performs ONLY projection,
filtering, prefix normalization (§5.2), and label joins". Path enumeration over
shipped rows *is* projection (D1 intact), but the closed operation list should
name it so E7-style "no second ad-hoc mapping" greps have a complete allowlist.

**L3. Verdict set lacks stated disjointness between `proven-reachable` and
`gated-by-known-condition`.** Both mean "path exists"; the boundary (zero named
gates vs ≥1 named gate) is implied, not stated. A closed enum whose members can
both match one path lets the renderer pick silently. One sentence fixes it.

**L4. AC-E3's DOM scan `/\d{4,6}/` "adjacent to flag-label slots" will fight
legitimate digits.** Canonical call ids and locators legitimately render numeric
tails (`…ObjectInteractive:3695`) in LCD machine voice. Scope the scan to flag-card
label text nodes specifically, with an allowlist for `[data-slot="lcd-terminal"]`
id surfaces, or it false-positives into being disabled.

**L5. §13 cites `scripts/check-chrome-parity.mjs`; the script lives at
`site/scripts/check-chrome-parity.mjs`** (verified on disk).

**L6. §4 table hygiene:** the "Blocked by" column is "—" on every row while real
gates live in "Depends on" (M6 ← "M2–M5 string freeze"); harmless but makes the
hard gate look weaker than map-viewer's equivalent table.
