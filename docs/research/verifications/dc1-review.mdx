## 2. Findings requiring revision

### F-1 (HIGH) — §4.2 anchor grammar does not match the corpus; AC C4 is unpassable as written

Prefix census over every `from`/`to` endpoint in all 25 relation files (2,284 endpoints across
1,142 anchored edges): forms NOT in the spec's "measured vocabulary" cover ≥1,527 endpoints (~67%) —
`note:` ×686, `target:` ×370, `container:` ×354, `paper_part:` ×20, `save_point:` ×19,
`controller:` ×10, `novella_surface:` ×6, `dialogue-carriers:` ×6, `choice_flag:` ×2,
`prop_family:` ×2 — plus BARE ids with no kind prefix on the from side of
character--achievement / character--cartridge / character--scene-membership
(`mita-short-hairs`, `player-10`, `mila`, …; 52 endpoints). Conversely four LISTED forms never occur
as anchors: `cartridge:<save_key>`, `document:<document_id>`, `cloth-site:<key>`,
`encoding-residue:<…>` (those families key rows by id columns like `achievement_id`/`cloth_id`/
`node_id`, or ship meta-only). As specified, C4's lint ("unknown anchor form → exit ≠ 0") fails on
the majority of real edges. Fix: derive each family's anchor grammar into `joins.json` from disk and
reword C4 to lint against those per-family grammars.

### F-2 (MODERATE) — POI `space` enum invents `world-assumed`

0 of 986 poi.jsonl rows carry `space:"world-assumed"`; measured values are only
unknown ×668 / parent-local ×56 / object-local-offset ×262. The value IS emitted — but on
scenes.jsonl `spawn` (20 rows, `{source:"inline", space:"world-assumed"}`), i.e.
World.positionSpawn is a SCENE-level field, not a POI cell. §3.9 lists it in the POI enum and says
"the ONLY projection-proven cell today is `inline ∧ world-assumed`" in the POI paragraph — this
violates the spec's own C2 rule ("every enum lists only measured values"), misstates where the one
projection-proven cell lives, and risks map consumers treating POI inline cells as proven.

### F-3 (MODERATE) — §3.7 speaker-null claim contradicted by disk and by its own citation

Null speakers ×129 ✔, but they span FIVE kinds: choice_case 70 + quest_box 13 + pet_dialogue 24 +
branch_group 11 + grouped_scene_dialogue 11. The spec says nulls are "exactly the speaker-less kinds
choice_case/quest_box/pet_dialogue" (=107, which is what DLG-3 in missingdata.md actually ledgered).
Both the sentence and its cited ledger disagree with the emitted rows.

### F-4 (MODERATE) — invented field `ptr` in the dialogue_edge block

`"ptr"` occurs 0 times in edges.jsonl (it exists only in the emitter source and the dangling-edges
ledger). Real edge fields unlisted by §3.7: `call_index` (all 3776), `call` (1535),
`resolved_to` (1535), `anchor_entry` (142). Direct breach of the brief's "do NOT invent fields not
present in emitted data".

### F-5 (MODERATE) — §3.10 mechanism/status enums are not exhaustive

Measured: document--minigame carries `mechanism:"scrMain PPtr (hard)"` ×10 (+ inferred ×2) with
status mirroring the same free-text strings — outside {hard, logic, inferred} and {modeled, partial};
dialogue-speaker-theme--character status ∈ {provisional-pending-ds1 ×9, pending-curation ×5};
achievement--award-site / achievement--ending / cloth-site--outfit / encoding-residue carry no status
at all. A consumer parsing either column as the pinned enum breaks.

### F-6 (MODERATE) — §3's "COMPLETE field inventory" claim is falsified by omissions

Data-row fields present on disk but absent from the blocks: dialogue_node `level`, `voice_present`;
ending `notes_community`; world_document `scr_main` (5 rows), `audio_source_refs` (1);
achievement.steam `captured_at_machine_plane`; spawn_table `spawn_table_id`, `level`, `status`,
`destroy_objects_count`, `materials_count`, `meshes_count`, `textures_count`; poi `level`,
`location_id`. Blocks that ARE complete against disk: personage, candidates, cartridge, minigame,
choice_node, flag_table, profile_document, book, scene, scene_link. Fix the incomplete six or drop
the completeness claim so entities.json generation isn't held to it.
