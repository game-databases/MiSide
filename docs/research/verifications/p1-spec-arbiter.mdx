## New findings

### N-1 · MAJOR (blocker) — `sweep-attempts.jsonl` "append" contradicts AC-5

**Evidence:** S4's failure policy says each attempt "**appends** to
`extracted/census/sweep-attempts.jsonl`" (`pipeline-run_all.mdx:196-198`);
AC-5 says running any stage twice consecutively changes **no byte** under
`extracted/` beyond mtimes, volatile fields, and the deduped
EXTRACTION-LOG (`:446-452`). Rerunning S4 appends ~51 duplicate rows — a
byte change that is none of those. Volatile-field exemption cannot absorb
it: timestamps/durations/host-names are *values*, and these are *whole new
records*; a harness that dropped them would be doing exactly the silent
narrowing F-4 outlawed. A TestWriter handed `test_idempotency.py` writes a
test that can never pass. Secondary exposure: AC-12 reconciles
attempted-vs-succeeded **from this ledger**, which double-counts under
accumulation unless reconciliation is defined over latest-attempt-per-
container. This is precisely the F-4 class on the artifact F-7 introduced;
the two sections cannot both be implemented as written.

**Fix (one decision, two sentences):** define the ledger write mode in S4 —
either (a) upsert keyed by `(container, argv-sha)` keeping the latest
attempt plus cumulative counters, or (b) deterministic full rewrite per
stage invocation — and align AC-8/AC-12 wording to it. State in the same
breath that ledger-style artifacts (`_ledger/locale-delta.jsonl`,
stage reports) are likewise rewritten, never appended, so idempotency holds
by construction. No other section moves.
