## Findings

### HIGH

**H1 — Hard sequencing rule violated: viewer merged onto the v0 zero-row
emission; M0 has not landed.**
Spec §2: *"no M1+ module may merge before M0's ACs ([§12.1](../../specs/map-viewer.mdx#121-m0-acceptance-criteria))
pass. A viewer merged onto a zero-row `markers.jsonl` repeats the v0
mistake this spec exists to close."* Measured state of the tree:

- `extracted/data/scenes/markers.jsonl` is 1 line — `_meta` only,
  `"schema":"miside.markers.projection/1"`, `"row_count":0`, and the v0
  **bare-kind** `pending_families` shape (no two-list ledger).
- `site/public/map/registry.json` is v1 (`bounds/zoom/coordinate-transform/
  imagery/status/build_id`) — no `display_label_loc`, no role-per-row v2
  additions beyond `role`… no per-kind marker counts.
- `extracted/data/scenes/build/emit_scenes.py:1240` still documents
  *"markers.jsonl — projection v0: zero data rows by the no-orphan rule"*;
  grep finds **no** `placement_families`, `position_dispositions`,
  `display_label_loc`, or `instance_census` anywhere in the emitter.

So AC MV-0.1…MV-0.5 cannot have passed. The suite itself agrees this red
is the gate: `site/tests/mapLedger.test.mjs:10-11` — *"Red until the M0
emitter rerun lands; that redness IS the sequencing gate (spec §2 hard
rule)."* Five `[M0-PENDING]` tests are red by design (see test
reconciliation below); landing the build with them red is precisely the
state §2 forbids. The code is honest about it
(`site/src/components/routes/MapRoute.tsx:16-18`), but honesty about an
empty shell does not repeal the sequencing law. **Resolution:** either
land M0 first (the five gates flip green mechanically) or record a
deliberate re-sequencing decision in the decision register before this
commit is treated as shippable.

### MEDIUM

**M1 — Books module emits crawlable dead `/locations` links; the
documented "value rides as text" behavior was not implemented.**
`EntityDetailRoute.tsx:538-540` comments: *"consumer_scene is a
scene-family label ('Location House'), NOT a registry scene_id — so no
/locations link and no scene param on the focus anchor; the value rides as
text, verbatim."* But `LocationModule.tsx:73-78` renders the found-in
anchor **unconditionally**: `<a href={`${localePrefix}/locations/${encodeURIComponent(s.sceneId)}`}>`.
Measured: all 8 `book_id`s are absent from
`extracted/relinks/document--scene-membership.jsonl`, and
`consumer_scene` ∈ {"Location House", "Location19"} while registry scene
ids are `level0…level23` — so every book page serves `<a
href="/en/locations/Location%20House">` (and `Location19`), which
`generateStaticParams` never enumerates and `buildDetailData` 404s.
8 book pages × 34 locales of crawlable dead links. Fix: carry a flag (or
resolve against `scenes()`) so non-registry scenes render the label as
plain text and keep only the focus anchor.

**M2 — PinPopover implements half the provenance carry law.**
Spec §5: provenance cell *"surfaced whenever `mechanism !== "hard"` OR
`status !== "modeled"` — §7 carry law."* `PinPopover.tsx:44-45` implements
only `Boolean(target.mechanism) && target.mechanism !== "hard"`; there is
no relink-status field anywhere in the plumbing
(`viewTypes.ts:10-44`, `mapView.ts:60-98`,
`contracts.ts:261-265` — `placement` types drop §3.2(b)'s mandated
verbatim `status`/`method`). Zero observable miss today (every marker-family
edge is `hard`/`modeled`; the one biting entity, `mita-black`, flows
through the M4 module where the full OR **is** implemented,
`LocationModule.tsx:64-66`), but the spec keeps the law mandatory exactly
so *"a future relink edit cannot silently flip rendering."* Add `status`
to the VM/target chain and the OR condition before markers land.

### LOW

nothing.

**L4 — Popover dialog niceties.** `PinPopover` uses `role="dialog"` with a
44 px close button but no Escape-to-close/focus return; acceptable v1,
worth a follow-up.

**L5 — Dead fixture module in production source.**
`src/components/map/fixtures.ts` ("FIXTURES ONLY — never imported by a
production route") is imported by nothing — not the routes, not the tests
(the suite uses `tests/fixtures/map-viewer/*.fixture.json`). Move it under
`tests/` or wire it into a dev-only lane.

**L6 — mtad2/mtacore unplaced wells arrive only with M0.** The §8 stub
policy names mtad2/mtacore as unplaced-well pages, but
`EntityDetailRoute.tsx:155-158` gates the well to `kind === "profiles"`;
cartridge pages currently get neither module nor well (consistent with
deviation (a), noted so the wells aren't forgotten when the emitter lands).

## Deviation rulings

**(a) Cartridges wait for marker rows; profiles use the pinned DS-5
fallback — ACCEPT.** Spec §7's own table names different sources per kind:
cartridges *"marker rows / pickup_ref.container via markers.jsonl"* vs
profiles *"marker rows / DS-5 `placement.container`"*. A runtime DS-4
rejoin would breach §4's forbidden list; reading DS-5 through
`findRow("profiles", …)` is sanctioned by §4's owning-datasets row.
Verified live: DS-5 carries `placement_mechanism:"placed"` ×11 with scalar
`container` = registry ids (`level12`/`level17`) → working found-in +
focus anchors; the 3 placement-less profiles hit the honest well
(`EntityDetailRoute.tsx:587-599`). Consequence (all-cartridge modules +
mtad2/mtacore wells deferred to M0) is within the honest-state law — see L6.

**(b) Books' `consumer_scene` as focus anchor without `scene=`, value as
text — concept ACCEPT, implementation REJECT-as-is (→ fix M1 before
merge).** Sourcing is right and necessary: measured, the relink holds zero
book edges (`note:*` rows are world-document ids; all 8 `book_id`s absent),
while AC MV-4 explicitly includes books in the SSR grep set — some pinned
source had to produce anchors, and mapping "Location19"→"level19" would be
a fabricated join. Dropping `&scene=` is right (no scene binding may be
invented). But "rides as text" does not exist in the markup — that is M1.

**(c) Registry built server-side from contract readers instead of fetching
`public/map/registry.json` — ACCEPT with conditions.** §4's preamble
allows reads *"through `site/src/data/contracts.ts` readers or the emitted
`public/map/*` artifacts"*, and `scenes.jsonl` is the named upstream of
the registry row; switcher labels via the filler chain are §5-sanctioned;
and building props server-side beats a runtime fetch (island receives
plain JSON, zero requests — MV-6 posture). Conditions: when S9/P5 writes
real `bounds`/`display_label_loc`/per-kind counts, consumption must flip
to the artifact — the duplicated constants in L1 are the exact divergence
risk, and the `[M0-PENDING]` registry-v2 test already pins those fields.
