## 2. Persistence design space

Where does checklist STATE live? Three options, evaluated against this pack's
binding constraints: the UGC/accounts mandate
([DR-2026-08-19-ugc-accounts] — every database MUST have sign-in/profiles;
spec §Section map rows 8/18 tie trackers and saved checklists to accounts),
the UGC lane ordering in [../TODO.mdx](../TODO.mdx) (UGC waits behind
LANE-C), and the static-export posture (browser sees only emitted `public/`
artifacts; `site/src/data/*` readers are server-only build-time).

| Option | What it is | Wins | Costs | Verdict |
|---|---|---|---|---|
| A. localStorage only | Per-browser store, one namespaced key per set, written on every toggle | Zero infra; ships immediately; private by default; works offline and on static origins | Device-local (cleared by eviction/private mode); no cross-device, no public profile; silent-loss risk on schema drift | **Ships FIRST** — v1 |
| B. URL / share-code state | Set selection as real routes; progress as an explicit opt-in compressed token | Shareable completion snapshots (design-standard §3 selected-state-is-a-URL; NWG published-build precedent); no infra | Personal state in a copyable string (shoulder-surf leak); token schema needs versioning; robots discipline owed | Ships with v1 as an **export/import action**, not ambient state |
| C. Server accounts | Sign-in, server-side checklist rows, profile pages | The mandated end state ([DR-2026-08-19-ugc-accounts]); cross-device; feeds comments/corrections identity | Whole UGC stack (auth provider, moderation, privacy handling — per-database build-time call, [DR-2026-08-16] ruling 2); blocked behind LANE-C ordering | **Seam only** — designed here as an interface, built in the UGC piece |

**Ruling proposed to the Documentator:** v1 = A + B behind a storage adapter
interface shaped so C slots in without a data migration (T1 module, §4).
Concretely:

- One versioned key per set: `miside.tracker.v1.<set_id>` holding
  `{schema:1, items:{<contract-id>:{done,ts}}}`. Writes are synchronous
  per-toggle (the reactive-input law applied to persistence: no submit
  control, no debounce loss window).
- **Contract ids are the only keys ever stored** — `achievement_id`,
  `cartridge_id`, `document_id`, `minigame_id`, `ending_id`,
  `character_id`. Never `save_key` alone, never loc indices: patch reruns
  may reorder loc lines but contract ids are the pinned stable vocabulary.
- **Build-drift tolerance**: ids absent from the current emitted set render
  nowhere but are *preserved* in storage (a patch that removes and later
  re-adds a row must not lose the user's check); unknown ids never crash
  render. Reconciliation happens against the emitted set manifest, never by
  rewriting history.
- Share-code: pure encode/decode functions over the same shape (bitset per
  set, versioned prefix), imported read-only into the local store on
  acceptance. Ambient URLs carry **surface selection only**
  (`/tools/trackers/<set>` as real `<a href>` routes); item-checked state
  never enters an ambient URL (privacy + the facet law: filter combinations
  create no URLs, site-scaffold §6/§7).

**Competitor precedent, honestly sourced:**

- Fandom's `table-progress-tracking` extension (COMP S1 structural
  weaknesses: JS-dependent rendering, content degrades without JS, crawlers
  see partial tables) is the **anti-precedent**: our checklist rows must
  exist in served HTML with JS only enhancing (AC-A6).
- new-world.guide is the network's structural reference
  ([design-standard §2](../../../_foundation/design-standard.md#2-reference-targets))
  and its published-build share URLs are the closest precedent for option B —
  but nothing in this repo documents NWG's actual persistence mechanism, so
  this scout records it as **unverified** rather than asserting localStorage
  patterns it cannot cite.
- Steam's own global-% surface (S5 of COMP) supplies rarity context, not
  persistence.

**What NOT to decide here:** auth provider, moderation, privacy/data-handling
for accounts — owner-domain per-database calls ([DR-2026-08-16] ruling 2).
The seam is: `TrackerStore { read(set), write(set, patch), subscribe }` with
`LocalAdapter` (v1) and a later `SyncAdapter` (sign-in push/pull, merge =
last-write-wins per-item `ts` + deletion tombstones). Once signed in, the
server is authoritative and the local store demotes to cache — no schema
change, only a second adapter.

## 3. Existing site integration points

The tracker adds a surface to a living site; every seam below already exists
and none requires new derivation law.

- **Data readers are server-only, build-time**
  ([../../site/src/data/contracts.ts](../../site/src/data/contracts.ts):
  "SERVER-ONLY build-time readers over ../extracted … the browser sees only
  emitted public/ artifacts"). Consequence: the checklist shell SSRs from
  build-time readers (rows, resolved labels, group keys as props), and the
  client island touches ONLY localStorage — it never reads `extracted/`
  (AC-A3). Where an island needs more than props (share-code import), it
  consumes an emitted manifest, mirroring the explorer's M0′
  emitter-under-`public/` pattern ([explorer-tool.mdx §5](../specs/explorer-tool.mdx)).
- **EntityShell** composes every entity page from conditional `tabs[]`
  modules, present only when the entity has that data, inactive panels hidden
  but served ([../../site/src/components/entity/EntityShell.tsx](../../site/src/components/entity/EntityShell.tsx)).
  The tracker slots in as a "track" tab/module on the routed kinds it covers
  (achievements, cartridges, minigames, endings, profiles/books, mita/player
  pages) plus a dedicated `/tools/trackers` hub. Mita-keyed colour identity
  (`accentLocal`) and the `compromised` horror-as-state prop come free.
- **Relation cards** run off the join registry (25 families in
  [contracts/registry/joins.json](../../contracts/registry/joins.json)) with a
  dedicated-module exclusion law: families surfaced by a dedicated module
  stay off the cards so a page never shows the same edge twice
  ([../../site/src/lib/relations/relationCards.ts](../../site/src/lib/relations/relationCards.ts)
  header). The tracker module must register its families there — a cartridge
  page would otherwise render its achievement edge twice (card + track tab).
- **Map module**: markers v2 already projects the three placement-bearing
  tracker kinds (cartridges 21 · profiles 11 · minigames-access 38) with the
  focus contract `/map?focus=<kind>:<slug>&scene=<scene_id>`
  ([dataset-scenes §markers](../../contracts/dataset-scenes.mdx)); positions
  are `pptr-unresolved` until PIPE S9, and the map viewer already renders
  that state with named-explicit-missing pins. Tracker rows get a
  "show on map" link at scene granularity today; coordinates upgrade it
  automatically when S9 lands. Reverse leg (map popover → track checkbox)
  stays out of v1 scope (OQ-T5 adjacent).
- **Search** is one matching function on both sides
  ([../../site/src/lib/search/searchRows.ts](../../site/src/lib/search/searchRows.ts)),
  rows typed `id = "<kind>:<contract-id>"`, census-pinned. The tracker adds
  **no new searchable kinds**; the tools hub joins the existing `tools`
  index segment ([../../site/src/lib/routes.ts](../../site/src/lib/routes.ts)
  `INDEX_SEGMENTS`). Kind-balanced truncation and MIN_QUERY_LENGTH=2 are
  inherited, not reimplemented.
- **Chrome i18n ×34 incl. RTL**: site chrome is the keyed JSON namespace
  [../../site/src/i18n/chrome/](../../site/src/i18n/chrome/) (78 top-level
  keys in `en.json`, namespaces `nav.*`, `map.*`, `filters.*`, …) with strict
  parity enforced by
  [../../site/scripts/check-chrome-parity.mjs](../../site/scripts/check-chrome-parity.mjs)
  (exit 1 naming tag + key + referencing file — the keyed-namespace-over-
  next-intl posture kept network-wide in
  [DR-2026-08-26-corepunk-i18n-keep]). Every tracker UI string is a chrome
  key landing in all 34 tables; direction is pinned per locale in
  [../../site/src/i18n/locales.ts](../../site/src/i18n/locales.ts) — `rtl`
  for `ar`/`ar-EG` (with the logged SB-1 finding that `fa` is natively RTL
  but stays LTR until a spec amendment), and the two declared aliases only.
  Locale stays route-coded (`/ru/tools/trackers`), never a same-page toggle.
  Namespace discipline: tracker row LABELS are **game text** resolved through
  loc pointers at build; buttons/empty-states/progress words are **chrome** —
  the two namespaces never mix (localization-architecture §4).
- **Kit components ready to reuse**
  ([../../site/src/components/kit/](../../site/src/components/kit/)):
  `GradientPill` (progress gauges — the HUD pill grammar T-P1 §3.4 maps
  literally), `KeycapKbd`, `VoidWell` (checkerboard honest-empty wells),

- **Stub policy for untrackable items** (inherited, extended): rows exist
  only where an owning dataset emits them — candidates-ledger tiers 3–4
  never become checklist rows; honest-missing renders as the declared state
  (`name_loc: null` → id-form label; `icon.status: pending-export` → named
  explicit-missing cell, the markers-v2 fallback convention); locked
  content stays visible-locked (`peaceful` mode-stub, four
  `present_but_unreachable` minigames, unresolved pickups `mtad2`/`mtacore`)

- **Route plumbing**: `(pivot)` + `[locale]` mirror pairs delegate to

### 4.2 Interactions (v1)

1. Toggle any row → persists synchronously to the local store; optimistic
   render; full keyboard + screen-reader semantics.
2. Group/filter controls per view — client-local, create no URLs (facet law).
3. Surface navigation by real `<a href>` route segments; the address bar
   carries surface selection only, never item state; any state-bearing
   control follows `replaceState` (no keystroke fills Back).
4. Share-code: explicit generate (per set or all sets) + import with a
   before-apply diff preview; invalid tokens produce a typed error state.
5. Reset per set, confirmed; never resets across sets.
6. Placement-bearing rows link `focus=` URLs into the owned map (two-way
   law with the map module).
7. Every row cross-links its entity page and vice versa (aggressive internal
   linking mandate); the two collectible-set achievements deep-link their
   member rows; the idx-13 profile achievement renders the exact consumer
   rule 4 predicate.
8. Rarity band + confidence chip (`proven-hard` vs `unverified-behavior`)
   ride every achievement row; missable rows wear the alarm-red treatment.
