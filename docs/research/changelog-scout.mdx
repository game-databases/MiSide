## 2. What a viewer CAN ship today vs later

### 2.1 Shippable today, at exactly one build

1. **Patch-event timeline** — the D1 §7 skeleton as structured data:
   dated rows, version labels, content-class tags (languages / renames /
   tuning / console / modes). Dates here are the *article's own facts*,
   which [DR-2026-08-22-numbers-stand-alone] explicitly keeps ("a news
   article's publication date is the article's own fact") — while the
   refresh-time/health ban stays enforced.
2. **Per-version integrity view — the genuinely novel one-version
   product.** `fingerprints.json` renders as a machine-verifiable "what
   database v0.93L IS" panel: 84 artifacts × sha256 × row_count × stamp
   class, byte-reverified at build (`check_contracts.py verify`
   precedent: 22 gates green byte-stable). This is provenance as product
   — D2's user-facing class (buildId + coverage scope) made interactive;
   no competitor can even state what their data was built from.
3. **Schema/version_label surfacing** — `_meta` blocks already carry
   `schema miside.*./N`, generator, and registry-pin literals per family;
   the changelog section aggregates them into one honest provenance
   surface.
4. **Documented rename-lineage page** — `save_point` attributes already
   declare `name-per-build` + `rename-lineage` (spec §entities); rows
   seed from patch notes labeled evidence-class `documented-note` until a
   computed diff replaces them.
5. **Locale-addition timeline** cross-checked against the availability
   ledger's current cell set.
6. **Route/feed scaffolding filled honestly** — `ArticleType` already
   includes `"patch"` in `site/src/data/articles.ts`;
   `site/src/app/feeds/patch.xml/route.ts` exists empty-honest;
   `/news` type chips land with LANE-C's News section.

### 2.2 What waits for build #2 (the diff-ready activation contract)

The trigger chain is already designed; the viewer just rides it:

appmanifest buildid change (local read + keyless appdetails
cross-check) → DepotDownloader pull into `D:\Games\MiSide_<buildid>\`
keeping tree N−1 → `./run_all <path>` rerun → fingerprints invalidated →
re-pinned in the emit-stage commit (patch_day law) → **diff stage
compares per-artifact sha256 sets, then per-record stamps inside changed
artifacts → changesets emitted**. Zero waste: everything in §2.1 is row
15's shape regardless; the diff arm plugs into the same artifacts.

**Honesty rider inherited from Backpack Battles:** that pack dropped the
section because data-row diffs published "nothing changed" over real
script changes. MiSide has the same structural exposure — its logic
layer lives in IL2CPP decompiled trees, and LG2 projections
(`flag--gates.jsonl`, `choice--consequence.jsonl`) ride the fingerprint
surface under KEEP-PINNED ([docs/specs/data-contracts.mdx §4.4](../specs/data-contracts.mdx)).
Ruling needed (OQ-3): every changeset must carry code-plane hashes
(assembly/decompile-tree digests) alongside data deltas so any
"unchanged" claim is scoped to the layer actually hashed.

### 2.3 The demo boundary is NOT a time axis

Demo 2527520 covers ch 0–3 only (ends at the wardrobe choice, D1 §6).
Demo-vs-full is a **scope slice**, not an ancestor build: different
appid, no shared time lineage, no changelog semantics. Its acquisition
stays dropped and owner-gated (SteamGuard DepotDownloader). If revived,
it belongs in a compare tool — OQ-2 rules whether that product exists.
What a demo pull WOULD add regardless: a second harvested tree to shake
out the diff emitter's mechanics before a real patch day (same appid
family, same pipeline), which is why DAQ kept calling it "the low-risk
diff target".

## 3. Competitor rulings

Evidence base: [competitor-research.md](../../competitor-research.md)
S1–S3 + D1 §7 sources (fresh fetches unnecessary this pass; if a later
fetch returns blank, retry once with an AI-crawler UA per promptForDB
Note#6, then record it as a finding and move on).

### 3.1 S1 EN Fandom — one Versions table, two planes mixed

- A single hand-maintained table mixes REAL build history (v0.91→v0.93L
  with dates + summaries — literally the public source D1 §7 cites) with
  the FICTIONAL in-game version lattice.
- **BORROW**: the dated-table skeleton as the timeline reader model.
- **AVOID**: unsourced prose, zero per-entity change annotation, silent
  rot between patches.

### 3.2 S2 RU Fandom — finest granularity, wrong plane

- Standalone «Версия 0…1.9» + Цикличная версия pages: page-per-version
  granularity is the best in the niche — but they document the fictional
  metaspace, not builds.
- **ADAPT**: one URL per REAL build (`/news/patch/<slug>`).
- **AVOID**: plane confusion. Spec non-goal is explicit: "the fictional
  version lattice never masquerades as site freshness". Our
  `game_version` entity (~15 rows, IDX 805/809) may be LINKED from a
  patch page; it may never BE one.

### 3.3 S3 Steam guides + the official news hub

- Guides: staleness is their defining weakness (top cartridge guide
  dated 2024-12-26, pre-v0.93 fixes; "no diff discipline"). The AVOID
  that defines our differentiator; X5 stands — nothing in the niche
  versions anything (tools-plan §4).
- News hub: dated posts, unstructured, no entity links, no diff.
  **BORROW** dates as the canonical public pinning; **ADAPT** into
  structured rows carrying entity refs and repo-plane source ids.

Per-entity change annotations ("this cartridge moved in v0.93") are
modeled nowhere — our X5 claim — but honesty gates them behind ≥2 builds
before a single annotation renders (AC-1).

### 3.4 The Backpack Battles precedent — why it does not transfer

[DR-2026-08-22-bpb-drop-changelog] waived the section for BPB because
BPB's star fields derive from decompiled scripts that change between
patches invisibly to data rows — a data-only diff would be "a
false-statement engine". The ruling's scope is explicitly BPB-only; the
section KEEPS `[CORE differentiator]` status for other packs. Two things
transfer anyway: (a) treat the code plane as a first-class diff input
(§2.2 rider); (b) dropping is not on this pack's menu — D5's CORE-min
makes a "patch-diff/changelog route" launch-blocking except where waived,
and no waiver exists for MiSide.

## 4. Spec skeleton for the Documentator

Naming precedent: [docs/specs/map-viewer.mdx](../specs/map-viewer.mdx),
[docs/specs/content-pipeline.mdx](../specs/content-pipeline.mdx). Seam
with the frozen content pipeline (`ef022cc`): its M2 reserves the patch
stream and hooks it ⛓ to this piece, and its OQ-4 recommended holding
patch pages until changelog summaries exist — THIS spec is what unhooks
that chain. Frontend consumes emitted artifacts only (AGENTS.md rule 8);
it never derives diffs.

### M1 — Data-side emitters (`extracted/data/changelog/`)

- `patches.jsonl` — patch-event registry, one row per dated event:
  `{patch_slug, label, date, event_class: release|patch|demo|collab|kickstarter|award|note, title, summary_facts[], source_kind: steam-news-item|extraction-log|wiki-table, source_ref, build_id?}`.
  Seed = D1 §7 rows + EXTRACTION-LOG run events. `_meta`: schema
  `miside.changelog.patches/1`, row_count pin, build_id/version_label
  stamps. Repo-plane fields (source ids) stay machine-plane per D2 —
  never rendered as user-facing provenance words.
- `build_integrity.jsonl` — normalized projection of
  `contracts/registry/fingerprints.json` (path · sha256 · row_count ·
  build_id · build_id_source class) + census detect pins. Emitted by the
  contracts tooling path, never hand-written.
- `save_point_renames.jsonl` — documented lineage rows with
  `evidence_class: documented-note`; the emitter REFUSES to emit
  `evidence_class: computed` unless M2 produced the row (AC-1).

### M2 — Diff activation stage (dormant by design)

- Registered in `run_all` but exits 0 emitting ZERO bytes while fewer
  than two build trees exist (honest omission — no stub changesets).
- On trigger (update watch): diff tree N−1 vs N — per-artifact sha256
  sets first, then per-record stamps inside changed artifacts → emits
  `changesets/<from>-to-<to>/{artifacts,records,renames}.jsonl` plus a
  code-plane digest manifest (OQ-3); fingerprints invalidated + re-pinned
  in the same commit.

### M3 — Frontend readers

- Server-only reader beside `site/src/data/contracts.ts` under the same
  `readJsonl()` discipline (`_meta` shapes, row_count pins); buildId /
  version_label surfacing already exists via `_meta` handling.

### M4 — Routes & placement

- `/news/patch/[slug]` ×2 trees — thin wrappers delegating to a shared
  factory beside `src/components/routes/`; the `/news` hub + type chips
  (`game | database | patch`) belong to content-pipeline M4, the detail
  page's data modules to this spec.
- Page anatomy: build-stamp header in pixel font (machine voice about
  machine state, T2 §4) → summary facts → changed-entity refs as
  crawlable links → integrity panel (artifact table with short sha) →
  related `game_version` links visually separated from build labels.
- Feeds: `feeds/patch.xml` fills from M1/M2 rows; sitemap partition gate
  replaces placeholders; search rows kind-namespaced `patch:<slug>`
  (search-in-place law).

### M5 — i18n + interactions

- Chrome keys ×34 in one commit; RTL leg for timeline rails (MV-1
  precedent); per-locale ledger cells gate non-pivot rendering — omit,
  never mix (localization-architecture §5.5 option A).
- Version picker = URL state (`?from=&to=` or segment form), never
  component-local state (design-standard selected-state-is-a-URL); any
  filter answers as typed ([DR-2026-08-22-inputs-answer-as-you-type],
  gated: no submit controls).
- Entity-scoped change views: reverse-index module on entity pages
  ("changed in …") — armed only when changesets exist; absent otherwise,
  without a caption.
- Corruption semantics finally literal: deletions alarm red `#fc0f43`,
  additions CRT green `#08cb05`, renamed rows VHS-degraded with current
  value crisp (T2 §4.1/4.3/4.4; tools-plan §3.7 sketch) — state
  treatment, not decoration.

### Acceptance criteria (each with its proof method)

1. **Honesty gate**: build FAILS if any changeset/renames artifact exists
   while `fingerprints.json` holds <2 distinct build_ids. Proof: suite
   asserts emitter refusal + empty output glob in a sandbox tree.
2. **Byte-truth**: recomputed sha256 over all 84 artifacts equals
   `fingerprints.json`; `build_integrity.jsonl` matches 1:1. Proof:
   `check_contracts.py verify` extension runs in-suite.
3. **Traceability**: every `patches.jsonl` row resolves date+label to its
   `source_ref` (news item id or EXTRACTION-LOG heading); an unresolved
   row fails emit. Proof: join sweep test.
4. **Plane separation**: no `game_version` entity id renders where a
   buildId/version label is expected, and vice versa. Proof: negative
   grep over emitted HTML.
5. **Locale parity**: `/news/patch/[slug]` exists ×2 trees × locale iff
   the availability ledger says so; hreflang cluster == ledger cells;
   metadata law per page (unique localized title/description,
   self-canonical, x-default → bare path). Proof: mechanical
   route-vs-ledger equality + existing metadata checker.
6. **Feed validity**: `patch.xml` parses; item count == published patch
   pages; valid while zero. Proof: XML parse + count assert.
7. **Machine-plane hygiene**: no refresh-time/status vocabulary on any
   surface; dates appear only as article facts. Proof: banned-token
   sweep (Phase-4 CI lane).
8. **Dormant silence**: M2 pre-trigger produces no bytes, exits 0.
   Proof: suite runs the stage against a single-build sandbox tree.

### Risks for the Arbiter's attention

1. **Starvation**: no release-notes post since v0.93L 2025-06-13 (~14
   months); game news continues but patch rows do not. Mitigation is
   structural: the database-news stream and evergreen guides carry
   retention (content-scout risk 2); this piece ships truth that does
   not rot rather than cadence.
2. **Disk**: OPS GATE C: EMERGENCY paused builds (TODO Phase 5) — emit

3. **Source-ref drift**: patches rows depend on news-ingest ids landing
