### 1.2 The single most important property: method bodies are stubs

Every decompiled file is an Il2CppDummyDll signature tree re-emitted through
ilspycmd (11.0.0.9335). Method bodies contain **no logic**:

```csharp
// D:\unpacked_game_data\MiSide\decompiled\main\Assembly-CSharp\AchievementsController.cs
[Token(Token = "0x6000E82")]
[Address(RVA = "0x3EEAA0", Offset = "0x3ED4A0", VA = "0x1803EEAA0")]
public void AchievementCompleted(string _nameAchievement)
{
}
```

`_structure/README.md` says it in one line: *"Decompiler method bodies are
garbage-prone in call-heavy serializers (IL2CPP); take structure, get
semantics from data"* — and points at
`does-not-work/decompiler-method-bodies.md`, **a file that does not exist in
the tree** (broken pointer; only `_structure/README.md` matched `*.md` under
`decompiled/`). What the dump *does* carry, and it is a lot:

- **field inventories with offsets** (`[SerializeField] private string
  fileSave; // 0x50`) — the serialized predicate grammar;
- **RVA/VA addresses per method** (`Address(RVA = "0x3EEAA0"…)`, mirrored in
  `il2cpp/script.json`) — the hook table a future native pass would drive;
- **attribute-declared ranges/constants** (`[Range(0, 6)] public int
  enemyComplexity`) — declared tuning envelopes;
- **enum member tables and string literals** (`stringliteral.json`,
  619,523 B).

Consequence (ruling detail in [§3](#3-feasibility-ruling-the-core-deliverable)):
anything the game decides inside a method body is invisible here; anything it
*configures in the editor* and serializes into scenes is fully visible in
`harvest/mb-dump/`. MiSide's architecture makes that split unusually
favorable: the game is built on generic wiring components, so most gameplay
decisions are editor-configured UnityEvent graphs, not code.

### 1.4 Family-by-family locator

**(a) Achievement unlock conditions.** Grant mechanism is a serialized
UnityEvent persistent call to `Achievement_function.AchievementGet(string)`
with the achievement id as the string argument. Exactly **11 dumped grant
sites corpus-wide** (`extracted/data/achievements/relink-achievement-award-site.jsonl`),
e.g.:

```json
{"achievement_id":"ACHI_WinFIght","level":"level6","file":"Dialogue_3DText_#7081.txt",
 "target_type":"Achievement_function","target_path_id":9330,"method":"AchievementGet",
 "args_string":"ACHI_WinFIght","mechanism":"hard"}
```

The other 15 predicates ride native bodies (minigame win loops, set-completion
counters) — missingdata [ACH-2]. Registry side:
`DataAchievements` in `resources.assets` (26 rows, E1-proven three-way join).

**(b) Ending-determination logic (DS-2's emitted trees).** Source classes:
`Location4Condition` (chapter-4 toggle set), `Basement_Safe(_Console)`
(safe chain), `Events_IntMemory` (branch tables), `Events_Data_#6042`
(level6 award chain calling `CameraClickTelevision`/`DestroyGameobject`/
`SetActive` then `AchievementGet("ACHI_none")`), `MenuEnding` (presentation
only). Emitted artifacts: `endings.jsonl` (4 rows), `choice_nodes.jsonl`
(371), `branch_edges.jsonl` (1,555), `flag_tables.jsonl` (5) — details in
[§2](#2-what-datasets-already-carry).

**(c) Cartridge/character unlock gates.** Pickup = serialized `FlashTaker`
instance per level carrying a `save` string field; 22 of 24
`cartridges.jsonl` rows have `pickup_ref` `{container, field:"save", …}`
(two unresolved: `mtad2`, `mtacore` — [CAR-1]). Story-side mirrors:
`World.SaveStoryCartridge/_Mita(string)`. In-fiction pet cartridges:
`TamagotchiGame_Cartridge(_Details/_Cartridge)` family — four rows flagged
`present_but_unreachable:true` ([CAR-8]).

**(d) Save-flag vocabulary.** Two mechanisms:

1. *Named save literals*: `Scene_Load.fileSave` + `nameLevelSaves[]`
   (dump.cs:106788–106791). Already harvested:
   `extracted/relinks/scene--save-vocabulary.jsonl` — 19 literals,
   `stringliteral_parity: both-directions-equal` (`SaveGame 2ingame`,
   `SaveGame wetogether`, `SaveGame startsecret`, `SaveGame basesub`, …).
2. *Unnamed int memories*: `Events_IntMemory` instances keyed by
   `(container, object_path_id)` — identity is the component, never a
   string. This is why the flag universe has no name column today and why
   `flag_if_int` targets are mostly unresolved (see [§3](#3-feasibility-ruling-the-core-deliverable)).

**(e) Mini-game rule implementations (17 games per DS-4).**
`cartridges/minigames.jsonl` `_meta.surface_count`: `carrier_class: 8,
prefab_scene: 3, tamagotchi_activity: 4, tv: 2`. Access chain is fully
serialized: `MinigamesAutomate.resourceGame` names the Resources prefab
(`key_locator: harvest/mb-dump/level9/MinigamesAutomate.txt :: resourceGame`,
value `"Minigame CarSpace"`), `sceneGame` the additive-scene variant.
Rules/thresholds are **not** in any dump — every row carries
`scoring_derivable: false` under the section 8-R1 IL-stub fence; what IS
captured is `rule_evidence` (loc-string claims like `"Defeat the boss"`,
`"Nitro"`) and serialized tunables (e.g. `Location4Fight.enemyComplexity`
Range 0–6). TV cabinet name mapping is pinned in `_meta.tv_name_offset_pin`
(`GetString("TelevisionGames", indexStringNameGame - 1)` chosen on
semantic rejection of the identity offset).

### 2.2 The delta = the extraction target

Already carried (no new extraction needed): award-site bindings (11),
ending wiring trees (371 nodes / 1,555 edges / 5 flag tables), cartridge
pickups (22 of 24), save literals (19), minigame access chain + UI-string
rule evidence, outfit grant sites (2), serialized tunables where they exist.

Absent today, statically reachable from the existing harvest, **and**
load-bearing for the explorer:

1. **Flag-instance registry.** No dataset names `Events_IntMemory` /
   `Events_Data` components as first-class entities; they appear only as
   edge targets (`object_path_id`) and inside the 5 `flag_tables` rows.
   The explorer cannot answer "what does this flag gate / who sets it"
   without a `(container, path_id) → thrown-by / gates` index.
2. **Effect-call sweep beyond achievements/outfits.** The
   `AchievementGet`/`ClothCompleted` sweeps prove the method; the same
   sweep over `Events_IntMemory.{Set,Add,CheckEventIndex,CheckEvent}` and
   `Events_Data.EV` has only been done inside ending contexts (18 edges),
   not corpus-wide.
3. **Choice-node ↔ prompt ↔ consequence join for non-ending choices.** 353
   `object-interactive` nodes exist; only ending-relevant ones are joined
   to outcomes today.
4. **Serialized minigame tunables.** Declared ranges and non-default
   public fields are dump-visible (e.g. `CarSpace_Money.animationFly`
   keyframes dumped in full) but not extracted as records.

Absent and **not** statically reachable at all (must stay labeled, or move
to a runtime/native pass): predicate polarity and evaluation order,
safe-window percentages, all scoring thresholds/win conditions, aggregate
counting logic, Peaceful Mode behavior (the [XC-1] family).

## 3. Feasibility ruling (the core deliverable)

Verdict vocabulary:

- **STATIC** — recoverable from this dump by parsing serialized data /
  metadata tables; no code execution or native code needed.
- **PARTIAL** — structure recoverable statically; semantics require
  cross-referencing multiple sites and even then stay incomplete without
  native code or runtime observation.
- **NOT STATIC** — decision lives in an IL2CPP *native* method body that
  this corpus does not contain; extraction must stub it per
  [missingdata.md](../../../extracted/data/missingdata.md) rules or wait
  for a native/runtime pass ([XC-1]).

| # | Logic family | Verdict | Basis |
|---|---|---|---|
| F1 | Achievement grant wiring (which interaction awards which achievement) | **STATIC** | 11 dumped `AchievementGet` sites; already emitted (`relink-achievement-award-site.jsonl`, all `mechanism:"hard"`) |
| F2 | Achievement predicate expressions (code-body ×12, aggregate ×3) | **NOT STATIC** | bodies stripped ([ACH-2], [DOC-6]) |
| F3 | Choice/branch graph structure (nodes, options, wired consequences) | **STATIC** | DS-2 proved the pipeline: 371 nodes / 1,555 edges all `proven-hard`; branch tables serialize completely |
| F4 | Flag-memory identity & throw/gate topology | **STATIC** for identity, **PARTIAL** for value flow | components serialize (`_memory[]`, `int_memory_default`); writers/readers joinable via call targets; but `CheckEventIndex` calls persist `m_IntArgument = 0` — the live index is computed natively, so value-flow needs cross-referencing and stays incomplete |
| F5 | Ending condition semantics (polarity of the Location-4 toggles, negative conditions, evaluation order) | **NOT STATIC** (structure STATIC) | class method table enumerates the toggles; serialized instances carry nothing (`level6/Location4Condition.txt` = base fields only; bools are private non-serialized) |
| F6 | Safe-window percentages (17% / 98% / empty) | **NOT STATIC** | numeric gates ride native safe-chain bodies ([END-2]; DS-2 labels them `[community]`) |
| F7 | Cartridge unlock gates | **STATIC** ×22, **NOT STATIC** ×2 + reachability | pickups dumped hard; `mtad2`/`mtacore` grants undumped ([CAR-1]); tamagotchi lock state present-but-unreachable ([CAR-8]) |
| F8 | Save-point / save-slot vocabulary | **STATIC** (done) | `Scene_Load.fileSave/nameLevelSaves` → 19 literals, parity proven both directions |
| F9 | Minigame access chain | **STATIC** (done) | `MinigamesAutomate.resourceGame/sceneGame` verbatim per level |
| F10 | Minigame scoring rules & win thresholds | **NOT STATIC**; tuning envelopes PARTIAL | `scoring_derivable:false` ×17 fence; only UI strings + serialized presentation tunables exist |
| F11 | Outfit unlock chain | **STATIC** ×2 sites; ×1 wiki-only | `ClothCompleted` sweep complete corpus-wide; pumpkin-clicker→`HellVamp` has no dumped site ([CAR-4]) |
| F12 | Dialogue gating | **PARTIAL** | option modifiers structural; quest conditions survive only as loc comment hints (318 rows) |
| F13 | Spawn/event gates (day/holiday creation) | **PARTIAL** | table rows serialized (`spawn-tables.jsonl` ×24); calendar semantics native |

### 3.1 Evidence anchors

**Static strength — branch tables serialize whole**
(`harvest/mb-dump/level4/Events_IntMemory.txt`):

```yaml
SerializableIntMemory[] _memory
  Array Array
  int size = 4
    [0] SerializableIntMemory data
      SInt32 ifInt = 1
      UnityEvent _event
        PersistentCallGroup m_PersistentCalls
          [0] PersistentCall data
            m_TargetAssemblyTypeName = "UnityEngine.GameObject, UnityEngine"
            m_MethodName = "SetActive"
            m_Mode = 6 … m_BoolArgument = False
```

This is why F3/F4-identity are STATIC: the game's own condition objects are
data rows in our harvest. `flag_tables.jsonl` already distills them
(`level4:Events_IntMemory`: branches if_int 1→2 calls, 2→2, 3→2, 4→4).

**Native wall — the ending tracker carries no state on disk**: the level6
instance of the chapter-4 condition tracker dumps as base fields only
(`m_GameObject/m_Script/m_Name`, nothing else); its `lookStove/lookVentil`
bools are `private` non-serialized and every toggle method body is empty in
the decompile. DS-2's honest labeling (`"polarity and evaluation order are
native-body unverified-behavior"`) is exactly right — and the explorer's
six documented prerequisites currently rest on that `[community]`
attribution plus this structural skeleton, not on proven polarity.

**Native wall — scoring**: minigame controllers keep win logic in
`Update()` loops (bodies stripped); what survives on disk is presentation
tuning (`CarSpace_Money.animationFly` keyframes dumped in full) and loc
strings naming rule concepts (`"Defeat the boss"`, `"Coins collected"`).
A "minigame-rule-revealer" built only from this corpus can reveal access,
controls, and tuning envelope — never thresholds. Saying otherwise in a
row would poison the tool.

### 3.2 What flips the verdicts

1. **XC-1 native pass** (owner-costed): `il2cpp/script.json` carries every
   method RVA; a Ghidra/IDA-class decompile of `GameAssembly.dll` turns
   every NOT STATIC above into PARTIAL-or-better. DS-2 §A.5 already names
   this option. Highest-leverage single spend for this board item.
2. **Runtime capture** (own-session playthrough probes): could pin polarity
   and windows empirically; protocol-layer posture (single-player, no
   server surface) makes this legitimate observation of our own sessions —
   needs an orchestrator ruling on scope before anyone schedules it.
3. **Community cross-check continuation** (already the DS-2 posture):
   keeps `[community]` attribution honest where structure proves existence
   but not sense.

**Single biggest feasibility risk**: *polarity is unknowable statically.*
The graph will draw itself beautifully from serialized data, yet the one
bit that makes advice correct — "looking in the vent HELPS or HURTS" —
lives in stripped native bodies. A wrong render is actively harmful in a
game with Missable achievements (tools-plan §3.1 names this risk). Any spec
must make polarity an evidence-classed field (`proven-hard` /
`[community]` / `unknown-fail-closed`) and the frontend must render
unknown polarity as unknown — never inferred from narrative vibes.

## 4. Spec skeleton for the Documentator

What follows is skeleton, not frozen spec — the Documentator owns wording,
schemas, and AC final form. Design center: **never mutate DS-2/DS-4
emitted files** (the B-4 consumer-note pattern); the logic layer is a new
dataset family that *references* existing rows by id and adds the missing
index plane.

### 4.1 Extraction modules

| Module | Sweep | Emits |

### 4.2 Record shape (illustrative, not frozen)

```jsonc

  "predicate_id": "logic:achi_slaphead",
  "subject": {"kind": "achievement", "id": "ACHI_slaphead"},

  "condition": {

             "host_object_path_id": 12820},
    "call": {"target_type": "Achievement_function", "method": "AchievementGet",
             "args_string": "ACHI_slaphead"}
  },
  "polarity": {"value": "positive", "evidence_class": "proven-hard"},
  "status": "proven-hard",           // proven-hard | proven-structure | community | unknown-fail-closed
  "build_id": 19029065,
  "evidence": ["data/achievements/relink-achievement-award-site.jsonl#…"]
```

Hard rules baked into the shape:

- `polarity.evidence_class` is mandatory; a row may not state a polarity
  value without evidence ([§3 risk](#3-feasibility-ruling-the-core-deliverable)).
- Unverifiable semantics render `"unknown-fail-closed"` — never omitted,
  never guessed ([ACH-2] stub-ladder posture).
- Every row stamps `build_id` so patch-day diffs are mechanical (XC-10).
